# 設計書: 浮動バーチャルスティック(タッチ操作の作り替え)

状態: ユーザー承認済み(2026-11-03、「タップしたところからのスクロールで操作できるやつ」という要望に
対し、本書の方式を提示して「その方式で作って」)

## 背景

PR #13/#14 で画面ボタンを付け、実機で押せる大きさにはなったが、ユーザーの求める操作感は
ボタンではなく、スマホゲーム式の「触った場所から指を滑らせて操作する」方式だった。

## 方式

- 移動と梯子は **浮動スティック** に置き換える(← → ↑ ↓ の 4 ボタンは撤去)。
  - 画面のどこでも、触った点がスティックの原点になる。全画面の受けレイヤー(DOM)が
    pointerdown を拾い、原点に土台の円(112px)、指の位置にノブ(52px、原点から最大 42px)を出す。
  - 原点からの変位 (dx, dy) を方向キーへ変換する純粋関数 `stickKeys` が担う:
    横は |dx| が 14px を超えたら左右、縦は |dy| が 18px を超えたら上下(縦を少し鈍くし、
    歩行中の誤っての梯子入力を減らす)。斜めは両立する。離せば全て解放。
  - 入力先は既存の `Input.touchDown/touchUp`(キー集合)で、ゲーム本体には触らない。
  - 同時に受け付けるスティックは 1 本の指だけ(pointerId で固定)。2 本目の指は無視する。
- ジャンプ(跳)と重粒子砲(砲)は **ボタンのまま** 右下に残す(80px、PR #14 の寸法)。
  スティックとは別要素なので、スティックで動きながら跳ぶ/撃てる。
- 表示は従来どおり `pointer: coarse` の端末だけ。PC では何も出ない。

## 非ゴール

- スティックの感度・アナログ量の反映(入力はキーのオン/オフのまま)。
- 照準のタッチ操作、眺望・ミュート(従来どおり非ゴール)。

## 検証

- `stickKeys` は Vitest で固定する(閾値・斜め・デッドゾーン)。
- エミュレーションで、ドラッグ操作でプレイヤーが歩くこと、スティックの円が出ることを撮影確認。
- PC 開始地点は差分 0(スティックもボタンも出ない)。
