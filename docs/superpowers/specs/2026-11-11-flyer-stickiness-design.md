# 飛行ドローンの粘着保持（チカチカ・瞬間移動の修正）設計

## 症状と真因（実証済み）

本人の報告（2026-11-11）: コウモリみたいな敵（飛行ドローン）がチカチカして瞬間移動を繰り返す。

真因は出現選定の窓依存。`findAirPockets` は走査窓の中で 5×4 の空気矩形が収まる左上を全列挙し、`chooseFlyerSpawns` は列挙順に貪欲に密度規則（32×16）を適用する。開けた空間ではポケットがタイル単位で重なって大量に存在するため、窓の開始位置がずれると貪欲チェーンが別の代表を選ぶ。実証: 全面空気の場で窓を +2 タイルずらすと選定 ID 集合が入れ替わる（+3 では全体が 1 ずれる）。`refreshEnemies` は 30 フレームごとに走り、`main.ts` は選定から外れた実体を即座に捨て、新しい選定位置に新しい実体を湧かせる。結果として、目の前の個体が消え、少しずれた位置に別の個体が出る（追尾中ならアンカーへ戻るように見える）。

2.13 で武器庫・補給キャッシュに適用した粘着保持（`holdSpot`）が、飛行敵には未適用だったのが落ち度。

## 修正方針

- **粘着保持**: 生存中の飛行敵は、そのスポーンアンカーがプレイヤーから保持半径（チェビシェフ距離 64 タイル）以内にある限り、選定集合から外れても捨てない。捨てるのは保持半径の外に出たときだけ。
- **地区ゲートは新規出現だけを止める**: 地区倍率が 0 の地区に入っても、保持半径内の生存個体は保持規則が優先する（境界でのポップアウトを防ぐ）。
- **純粋関数化**: 保持の判定は `retainFlyers(current, desiredIds, playerX, playerY)` のような純粋関数として切り出し、単体テストで固定する。`main.ts` はそれを使うだけにする。
- 撃破済みの扱いは現行どおり（`defeatedEnemies` で再出現しない、死体は即除去）。
- 出現率・密度・行動（巡回/追尾/諦め）の数値は一切変えない。歩行敵・固定砲台は今回の対象外（床ランは最大ランで窓依存が小さい。計画書の保留に記録する）。

## 合格条件

- 窓をずらしても、保持半径内の既存個体が消えないことが単体テストで固定される。
- 全テスト・型・ビルド通過。性能への影響なし（保持は既存配列のフィルタのみ）。
