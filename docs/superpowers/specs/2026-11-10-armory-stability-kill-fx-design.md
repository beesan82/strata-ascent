# 設計: 武器庫・キャッシュの出現安定化と敵撃破エフェクト（2026-11-10）

本人の報告（2026-11-10）:

2. 敵を倒したときのエフェクトが乏しく、あっけない。

## 1. 出現の安定化（武器庫・補給キャッシュ）

原因: 武器庫と補給キャッシュは「プレイヤーの現在地にひもづく選定の先頭 1 個」だけが実体化する。プレイヤーが選定の境界をまたぐと先頭が入れ替わり、箱が別の場所へ跳んだり消えたりして見える。

- 選定を**粘着**にする: 純粋関数として「前回の選択・候補一覧・プレイヤー位置・保持半径」から次の選択を決める。
  - 前回の選択が未開封で、プレイヤーから保持半径（目安 48 タイル）以内にあるなら、それを維持する（今回の候補に入っていなくても維持する。候補のレコードごと保持する）。
  - 維持できない場合だけ、候補から最も近いものを選ぶ。
  - 開封されたら選択を手放し、次回の選定で残りの候補から選び直す（同じ場所には二度と出ない。開封済み集合の仕組みは従来どおり）。
- 武器庫と補給キャッシュの両方に適用する。密度・候補の決め方（chooseArmories / chooseSupplyCaches）自体は変えない。

## 2. 敵撃破エフェクト

撃破の瞬間に、既存の fx 相乗りの中で以下を出す（描画パスは増やさない、平坦な色、`lighter` の画素は最小限）:

- **破片バースト**: 敵のパレット色の破片（小さな矩形）が飛び散り、重力で落ちて縮みながら消える。歩行敵・ドローン・砲台で色と量を変える。ボスは大きめのバースト＋画面シェイク。
- **閃光とリング**: 中心に短い閃光、広がる輪（細い矩形の円環表現）で「壊れた」読みを強める。
- 速度や向きは実体の ID と時刻からの決定的なハッシュで決める（Math.random() は使わない）。パーティクルの更新は純粋関数に寄せ、単体テストで固定する。
- 既存の撃破音・ハプティクスはそのまま。数値・行動・ドロップは変えない。

## やらないこと

- 武器庫・キャッシュの密度や出現条件そのものの変更。
- ヒットストップ（ sim の時間に触らない）。
- ボスの行動や相の変更（バーストの大きさだけ差をつける）。
