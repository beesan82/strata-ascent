# 設計書: 段階1 — 弾の向き＋チャージ演出のリアル化（2026-11-09）

## 背景と方針（2026-11-09 本人確定）

- 世界の見た目はドット絵のまま。**エフェクトと音はリアル寄せ**にする。この対比が「味」になる、というのが本人の方針。音は音質第3ラウンド（PR #51）で実現済み。本書はエフェクト側の第一歩。
- 本人の実機所見（2.0 (22)）: ①パルスの弾が斜めに撃っても全部横向きで違和感。②重粒子砲のチャージ中グラフィックがダサい。
- 本段階は**描画のみ**の変更。ゲームルール・物理・入力には一切触らない（崖つかみは段階2、サバイバル刷新は段階3で別途）。

## 1. パルス弾・敵弾の向き

現状: `src/render/renderer.ts` の弾描画は `|dx| >= |dy|` で横/縦の2向きしか選ばず、斜め射撃でも弾が横向きの矩形になる。

方針:
- 速度ベクトルの角度に沿って、既存の2層形状（外帯＋芯）を回転させて描く。回転は `ctx.save/translate/rotate/fillRect/restore`。低解像度バッファ＋32色量子化で斜めは階段状になるが、それがドット調として正しい。
- 純粋関数 `shotShape(dx, dy, ppt)` を `src/render/` に置き、角度と外帯/芯の長さ・太さを返す。Vitest で固定する（beamShape と同じ流儀）。
- 対象はプレイヤーのパルスと固定砲台の敵弾の両方（同じ描き方を共有しているため）。
- 速度ゼロ時は横向きフォールバック。新規描画パスは足さない（既存 fx パスへの相乗りを維持）。

## 2. チャージ演出（重粒子砲）の作り替え

現状: `drawCharge`（`src/render/beam.ts`）は回転する矩形セグメント＋四角い芯のみで、平たい。

方針: 「リアル寄せ」の要素を、量子化に耐える形で重ねる。

1. **収束パーティクル**: チャージ進行に比例した数の火花が、外側から銃口へ吸い込まれる。配置・位相は決定論ハッシュ由来（描画での `Math.random()` 禁止を守る）。進行が上がるほど速く・多く・明るく。
2. **コア**: 四角を廃止し、放射グラデーションの球（白→金→透明）。大きさと明るさは ratio で成長。量子化で帯になるが体積感は出る。
3. **電弧**: ratio >= 0.6 でコア周囲に折れ線の放電を数本。時間量子化したハッシュで形が変わる。色は白〜鋼色。
4. **完了リング**: ratio が 1 に達してからの短時間、拡大するリングを描く。経過時間が必要なため、fx に `chargeFullT`（満タン経過秒）を追加して配線する。
5. **グロー（present 後オーバーレイ）**: 滑らかな光暈は量子化バッファでは出ないため、present 後に表示解像度で放射グラデーションのグローを `lighter` 合成で1枚だけ重ねる。これが「リアル」側の主役。renderer の最終段に限定し、定数フラグで無効化可能にする。frametime を前後各2回測り、render p50 の悪化が +0.5ms を超える場合はオーバーレイを外して in-buffer のみで出す（裁定を計画書末尾に記録する）。

音は変更しない（第3ラウンドで確定済み）。

## やらないこと

- ゲームルール・物理・入力の変更（段階2以降）
- ビーム発射後（beam 本体）の演出変更 — 今回はチャージ中のみ
- 描画パスの追加はグローオーバーレイ1枚のみ

## 受け入れ基準

- 斜め（45°付近）に撃った弾が、その向きの細長い形状で描かれる（スクリーンショットで確認）。
- チャージ 0.5 と 1.0 のスクリーンショットで、収束パーティクル・グラデーション球・電弧（1.0側）が判別できる。
- `npm test` / `npx tsc --noEmit` / `npm run build` 全通過。render p50 の悪化 +0.5ms 以内（グロー採否の裁定込み）。
- MARKETING_VERSION を 2.1 に上げる。
