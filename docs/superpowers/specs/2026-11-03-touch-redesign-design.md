# 設計書: タッチ操作の根本刷新(モード分離 + 直接ポインティング照準)

状態: ユーザー承認済み(2026-11-03)。Fable の設計検討(同日)に基づく案1を採用。
スティック方式(2026-11-03-virtual-stick-design / aim-stick-design)は本書で置き換える。

## 根本原因(Fable 分析 + コード裏取り)

- 重粒子砲は「0.6 秒溜め → 離した瞬間に発射」(entities/graviton.ts)。スティック照準は
  「倒す=狙い+溜め」「離す=発射」を 1 本の指に結合したため、狙いをやめる動作が誤射になる。
  掘削は地形に恒久反映されるため誤射のコストが高い。
- 本作は敵なし・時間圧なしで、同時精密操作が要る場面がほぼ無いのに、ツインスティックは
  親指 2 本 + 跳ボタン = 3 点同時を要求していた。
- 浮動原点 + 最大 42px のストロークでは 360° の角度分解能が足りず、指と土台円が
  狙う地形そのものを隠す。
- 旧ボタン方式の失敗も大きさではなく「ボタンを目で探して押し分ける」認知負荷が主因。

## 方式(モード分離)

| 入力 | 操作 |
|---|---|
| 左右移動 | 左下の ← → ホールドボタン(74px) |
| 梯子 上下 | 梯子のそばにいる間だけ ← → の上に表示(64px)。それ以外は隠す |
| ジャンプ | 右下の 跳 ボタン(84px) |
| 照準 + 発射 | 砲ボタン(76px)を押して溜め開始 → その指を画面上へドラッグすると指位置が照準点(マーカーは指の 30px 上) → 離した瞬間に発射 |
| キャンセル | 指を砲ボタン中心 38px 圏内に戻して離すと溜め破棄(ボタンが破棄色に変わって予告) |
| 眺望 | 右上の小ボタン(48px)長押し |

- 照準ドラッグの開始は、指が砲ボタン中心から 24px 以上動いてから。
- 溜め中(砲を押している間)は移動ボタンを無効化し、不透明度 0.25 に落とす
  (「止まって狙う」のモードを視覚的にも明示)。ジャンプは有効のまま。
- 照準の受け渡しは Input の「照準点(CSS px)」とし、main は PC のマウス照準と
  同じ経路で合成する(スティックの角度方式は廃止)。
- キャンセルは Graviton.cancelCharge() を新設して行う(溜めを破棄し、続く解放で
  発射しない)。タッチ側は Input のフラグ経由で main に要求する。
- 縦持ち前提。横持ちでも配置・役割は変えない。

## 非ゴール

- スティック類の存続、照準の角度入力、撃ちながらの移動。
- PC 操作の変更。

## 検証

- Graviton.cancelCharge、Input の照準点とキャンセルフラグ、砲ドラッグの位相遷移
  (純粋関数 cannonPhase)を Vitest で固定する。
- エミュレーション: 砲ドラッグで照準コーンが指の点を向き、離して発射(弾数減)、
  キャンセルで不発(弾数不変)、梯子のそばで ↑ ↓ が出ることを確認する。
- PC 開始地点は差分 0。
