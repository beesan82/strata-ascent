# 設計書: アニメーション作り込み（ジャンプ／梯子／着地／よじ登り）（2026-11-09）

## 背景

- 本人の実機所見（2.2）: 全体はいい感じだがアニメーションがチープ。例としてジャンプ時と梯子を登る時を挙げた。
- 現状の内訳: 歩行は gait（移動距離駆動）で作り込んである。一方で空中は静止に近いポーズ、梯子は通常ポーズのまま滑って昇降する、着地は無演出、よじ登りは即時移動のみ（段階2の保留）。

## 方針

ポーズ計算（`src/render/playerPose.ts` の純粋関数）を中心に拡張し、Player には位相とタイマだけを足す。描画パスは増やさない。歩行 gait には触らない。

## 対象

### 1. 梯子の昇降ポーズ

- Player に `climbPhase`（昇降した距離で進む位相。歩行の walkPhase と同じ流儀）を追加する。
- ポーズ: 梯子にしがみつく横向き。腕は位相で交互に前上方へ伸ばし、脚は交互に段を踏む（膝の曲げが交互）。昇降していない間はしがみつき静止ポーズ。
- renderer へ「梯子中かどうか＋climbPhase」を渡す経路を作る（既存の hanging の渡し方に揃える）。

### 2. 空中ポーズ（ジャンプ〜落下）

- vy を入力に、3 相を連続につなぐ: 上昇＝脚を後ろへ畳み体が少し伸びる／頂点付近＝中立／落下＝脚を下へ伸ばし腕が少し上がり体が少し前傾。
- 相の切り替えは vy の閾値でパキッと変えず、vy の連続関数として補間する（カクつき防止）。
- 照準の腕（銃を持つ腕）は既存の照準追従を維持する。

### 3. 着地の沈み込み

- 着地直後 0.1 秒、体が沈む（bodyOffset 負＋膝曲げ）。深さは着地時の落下速度で変わり、上限を設ける。
- Player に着地タイマと着地時落下速度を持たせ、pose に渡す。ゲームプレイ（移動・入力）には影響させない。

### 4. よじ登りの復帰ポーズ（段階2の保留の解消）

- よじ登り自体は即時移動のまま。登った直後 0.16 秒、「縁に手をついた屈み→立つ」の復帰ポーズを出す。Player に復帰タイマを持たせる。

## やらないこと

- ジャンプ前の予備動作（しゃがみ溜め）: 入力バッファとコヨーテの感触に触るため今回は見送り、保留に記録する。
- 歩行 gait の変更。
- 新規の描画パス、スプライト画像の導入（従来どおりプログラム描画のポーズで表現）。

## 受け入れ基準

- 各ポーズが純粋関数の単体テストで固定される（位相・vy・タイマに対する手足の位置の性質）。
- スクリーンショットで、梯子昇降の途中・上昇中・落下中の姿勢の違いが判別できる。
- `npm test` / `tsc` / `build` 全通過。frametime の render p50 悪化 +0.5ms 以内。
- MARKETING_VERSION を 2.3 に上げる。
