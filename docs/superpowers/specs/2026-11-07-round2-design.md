# 設計書: アクション化 第2弾(飛行敵 / ボス / ドロップ / 記録保持 / 砲と敵の相互作用)

状態: 設計案(ユーザー承認待ち)。第1弾(設計書 2026-11-04-action-phase1)の続編。
第1弾の実機判定とゾーン化 段階1〜3・武器切り替え・ズーム滑らか化を経て、
ユーザーの「いい感じ。つづけよう」で第2弾への進行が決まった(2026-11-07)。

## 方針

- 第2弾の範囲は当初予約どおりの 5 点に限る: ①飛行敵 ②ボス ③ドロップ
  ④倒した敵の記録保持 ⑤重粒子砲と敵の相互作用。
- ゾーン設計 §5 の予約(飛行敵の初出は大空洞水域、ボスの居場所は大広間、
  ドロップの質は地区で寄せる)をそのまま具体化し、地区 ID を参照するだけで済む形にする。
- ワールド生成・決定論・描画制約(内部バッファ、32 色量子化、焼き込み相乗り、
  新規描画パスなし)は壊さない。敵・ドロップは実行時エンティティとし、
  タイルや焼き込みには混ぜない(第1弾の方針を継承)。
- 既存の数値体系を前提にする: パルス威力 1・6 発/秒・射程 14、Walker HP3、
  プレイヤー HP5・被弾 1 ダメージ・無敵 1 秒、重粒子砲は弾数 3・回復 6 秒/発・
  溜め 0.6 秒・BORE_LENGTH 300・BORE_RADIUS 3。変える場合は理由を明記する。

## 前提: 現行の接続点(コード確認済み)

- 敵の出現は `world/spawn.ts` の決定論スキャン: カメラ近傍(±40×±24、
  30 フレームごと)に `findFloorRuns` で床ランを列挙し、`chooseSpawns` が
  hash2(seed + salt, run.x, run.floorY) で出現・位置・向きを決める。
  スポーン ID は `w:${run.x},${run.floorY}`。基礎率は `spawnRateForLayer`
  (第 0 層 0、上限 0.7)に地区の `spawnMul` を乗算済み。
  保護点はスポーン地点 r=10、休憩点 r=20。密度は近傍 24×12 に既選があると除外。
- 敵の実体は `main.ts` の `enemies: { spawnId, walker }[]`。有効範囲から外れた
  実体は捨てられ、倒した敵も戻れば再出現する(第1弾の割り切り)。
- 重粒子砲の発射は `main.ts` の `fire()` が `Destruction.bore` で地形だけを壊す。
  敵への作用は現行では存在しない。
- 死亡時は最後の休憩点へ復活し、破壊した地形と砲の弾数は保持される
  (`enemies = []` で敵はリセット)。セーブ機構は無く、記録はセッション内が前提。
- 大広間は `world/grandhall.ts` の `grandHallAt(seed, cell)` で引ける
  (率 1/7、幅 200・高さ 200、休憩点を 1 つ内包、床行 `floorY` を返す)。

## 1. 飛行敵「飛行ドローン」(entities/enemy.ts に追加、world/spawn.ts に出現決定を追加)

### 振る舞い

- 重力を受けない空中巡回機。体格 0.8×0.8、HP2(パルス 2 発。Walker より脆いが
  当てにくさで釣り合う)。攻撃手段は接触のみ(敵弾は第2弾でも持たない。
  第1弾の非ゴールを継承)。
- 状態は 2 つだけ:
  - **巡回**: アンカー点を中心に水平 ±6 タイルを速度 1.5 で往復し、
    縦は sin 波で ±0.8 タイルうねる(位相はスポーン ID の hash で決め、個体差にする)。
  - **追尾**: プレイヤー中心が半径 7 タイル以内に入ると、速度 3.2 で
    プレイヤーへ直進する(プレイヤー歩行 6 より遅く、逃げ切れる)。
    半径 10 を超えたら巡回へ戻る。視線判定はしない(壁越しでも気づく。
    壁は `moveBody` の衝突で自然に阻まれる)。
- 追尾中に 1 秒以上進めない(壁に阻まれる)場合は巡回へ戻る(固着防止)。
- 被弾・撃破・接触ダメージの扱いは Walker と同じ経路
  (`hit(damage)`、`player.damage(fromX)`)を通す。梯子・床への依存は無い。

### 出現条件

- 床ランではなく「空間のポケット」をスキャンする新関数で決める:
  5 幅×4 高の AIR 矩形が収まる場所をアンカー候補とし、Walker と同じ流儀で
  hash2(seed + salt, anchorX, anchorY) により出現・位相を決定する。
  スポーン ID は `f:${anchorX},${anchorY}` とし、Walker と名前空間を分ける。
  保護点(スポーン r=10、休憩点 r=20)と密度上限(近傍 32×16 に既選があれば除外、
  空は広いので Walker より緩める)は Walker の流儀を踏襲する。
- **地区ゲート**: ゾーン設計 §5 の予約どおり、初出は大空洞水域(`waterVoid`)
  のみとする。地区ごとに倍率を持つ表 `flyerMulFor(biomeId)` を新設し、
  第2弾の段階 1 では waterVoid = 1.0、他地区 = 0 とする。
  他地区への開放は表の数値を変えるだけにし、段階 3 で電力区・生体異物区への
  開放を判断する(未決事項 2)。基礎率は `spawnRateForLayer` を
  Walker と共有し、地区倍率は `spawnMul` とは独立に掛ける
  (歩行敵の出やすさと飛行敵の出やすさは別の個性として扱う)。
- 大広間(`grandHallAt` の矩形)の中には出さない。広間はボスの arena として
  空けておく(§2)。

### 倒し方

- パルス: 2 発。アナログ照準・保持照準で真上・斜め上を撃てる現行操作で届く。
- 重粒子砲: ビームに巻き込まれると即死(§5)。
- プレイヤーが梯子で縦移動する場面では、追尾速度が歩行より遅いため
  「登ってやり過ごす」が成立する。

## 2. ボス「広間番人」(新エンティティ、配置は world 側の純関数)

### 居場所と出現

- 大広間を第一候補とし、接続は具体的にこうする:
  `bossSpawnFor(seed, cell)` を純関数として新設し、`grandHallAt(seed, cell)`
  が非 null のセルについて、広間の床(`floorY`)の中央にボスの出現点を返す。
  スポーン ID は `b:${cell}`。
- 実体の生成は Walker と同じ有効化の仕組みに相乗りする: プレイヤーが
  広間のあるセルに入ったら番人を 1 体だけ有効化する。撃破済み
  (`b:${cell}` が記録保持の集合にある、§4)なら出さない。
- 番人は広間の矩形(`x0..x1`)の外へ出ない(移動をクランプする)。
  広間内に飛行敵は出ない(§1)ので、広間の戦闘は番人との一対一になる。

### 体格・HP・行動

- 体格 2.6×2.0 の大型歩行機。HP30(パルス 30 発 = 連射約 5 秒分。
  回避と位置取りを挟んで 1〜2 分の戦闘を想定)。接触ダメージは 1 のまま
  (プレイヤーの HP 経済は変えない)。
- 行動は 3 相の単純な状態機械:
  - **巡回**: 広間の床を速度 1.2 で巡回(プレイヤーが広間の外なら戦闘にならない)。
  - **接近**: プレイヤーが広間内に入ると速度 2.6 でプレイヤーへ歩く。
  - **突進**: 接近中、3 秒間隔で予備動作 0.7 秒(その場で停止し点滅) →
    向きへ速度 9 で 0.45 秒突進 → 壁に当たるか時間切れで **1.2 秒の硬直**。
    硬直中はパルスのダメージが 2 倍になる(「溜めて撃つ砲」と
    「硬直を撃つパルス」の読み合いを作るのがこの一手)。
- 突進の予備動作が読みの柱: テレグラフが 0.7 秒あれば、ツインスティックでも
  横移動とジャンプで避けられる。突進は直線のみで、梯子・縦移動には追随しない
  (広間内の休憩点と梯子列が安全弁になる)。

### 倒す意味・再戦

- 撃破時は確定ドロップ: 回復セル 1 個 + 砲弾セル 2 個を広間の床へ散らす(§3)。
  それ以外の進行ゲートは現行のゲームに存在しないため、報酬は資源に留める
  (恒常強化を付けるかは未決事項 1)。
- 再戦は不可: 撃破は記録保持(§4)に残り、プレイヤーが死んでも復活しない。
  広間は「通った証」として静かになる。

### 表示

- 番人が有効な間だけ、HUD 相乗りでボス HP バーを出す(プレイヤー HP と同じ
  描画経路。新規描画パスは作らない)。

## 3. ドロップ

### 落ちるもの

既存の資源体系(砲の弾数、HP)にだけ接続する 2 種:

- **砲弾セル**: 拾うと重粒子砲の弾数を 1 回復する(満タン時は拾えない=
  上に残る)。ゾーン設計 §5 の予約「精錬区は砲弾の材料」をここで回収する。
- **回復セル**: 拾うと HP を 1 回復する(満タン時は同様に残る)。

### 抽選と地区の寄せ

- 抽選は撃破時に 1 回だけ、スポーン ID と撃破カウンタから
  hash2(seed + salt, idHash, killIndex) で決める純関数
  `dropFor(seed, spawnId, killIndex, biomeId)` とする(実行時の乱数は使わない)。
- 基礎確率: Walker は砲弾 25% / 回復 15%(どちらか最大 1 個)、
  飛行敵は砲弾 30% / 回復 15%(空中戦の消耗への見返りとして砲弾寄り)。
- 地区の寄せは重み倍率の表 `dropProfileFor(biomeId)` で行う:
  精錬区は砲弾 ×2.0(砲弾の材料)、居住区画は回復 ×1.5、
  生体異物区は両方 ×1.2、大空洞水域は砲弾 ×1.3、
  寒鋼基層・廃棄沈殿層・電力区は ×1.0(電力区は将来の接続用に表だけ用意)。
- 記録保持(§4)により倒した敵は再出現しないため、ドロップ目的の
  行き来による無限回収(ファーミング)は構造的に起きない。

### 拾い方と寿命

- プレイヤーの AABB と重なれば自動で拾う(ボタン操作は追加しない。
  ツインスティックの両手が埋まっているため)。
- 落下する: 出現位置(敵の中心)から重力で落ち、床に着地して静止する。
- 寿命 60 秒、残り 5 秒から点滅して消える。同時存在の上限は 16 個
  (古いものから消す)。吸着(マグネット)は第2弾では入れない(未決事項 3)。

## 4. 倒した敵の記録保持

### 方式

- セッション内メモリに `Set<string>`(スポーン ID の集合)を持つ。
  Walker・飛行敵・ボスを同じ集合で扱う(ID の接頭辞 `w:` / `f:` / `b:` で分離)。
- `chooseSpawns`(および飛行敵の出現決定)に任意引数
  `defeated?: ReadonlySet<string>` を追加し、集合に含まれる ID を
  出現候補から除外する。純関数の引数として渡すため、Vitest で固定できる。
  実体の有効化・破棄の現行の仕組み(範囲を離れると実体は捨てられる)は
  変えず、「倒していない敵は戻れば再出現、倒した敵は二度と出ない」だけが変わる。

### 保持の範囲とリセット条件

- **範囲**: セッション全体で保持し、距離による失効はしない。
  1 セッションの撃破数は数百体規模で、ID 文字列の集合としてのメモリは
  無視できる(上限を設けるなら 10,000 件で古い順に落とす安全弁だけ付ける)。
- **プレイヤーの死亡ではリセットしない**。破壊した地形が死亡後も残る
  現行仕様と揃える(死に戻りで敵が戻ると、ドロップ回収と合わせて
  往復ファーミングの抜け道になるため)。
- **セッション跨ぎは保持しない**。セーブ機構が無い現行の前提のままとし、
  永続化は将来セーブを入れる際の別件とする。

### 決定論への影響

- ワールド生成そのものには触れない(出現は実行時スキャンのまま)。
  「同じ seed・同じプレイ履歴なら同じ世界」が保たれ、生成の決定論テストには
  影響しない。変わるのは出現のフィルタ条件だけであり、それも純関数で固定する。

## 5. 重粒子砲と敵の相互作用

### 判定

- `fire()` の発射時に、地形の `bore` と同じ幾何(発射点・角度・
  BORE_LENGTH 300・BORE_RADIUS 3)で敵への命中を判定する純ヘルパ
  `beamHit(beam, body)` を追加する: ビームを中心線の線分とし、
  敵ボディの中心から線分への距離が BORE_RADIUS + ボディの半対角以下なら命中、
  という capsule 近似で固定する(タイル破壊のサンプリングとは独立に、
  敵判定は連続幾何で閉じる。発射フレームだけの計算で、対象は有効中の敵のみ)。
- 判定は地形の破壊と独立に全敵へ行う(壁の向こうの敵にも当たるかは
  地形と同じく「貫通」で統一する。ビームは地形を貫通する一撃なので、
  遮蔽で敵だけ助かるのは読みに反する)。

### 効果

- Walker・飛行敵: **即死**。地形ごと蒸発する一撃なので HP 計算は経由しない。
  ドロップ抽選は通常の撃破と同じ経路で 1 回だけ行う。
- ボス: **10 ダメージ**(HP30 の 1/3)。即死にはしない。砲 3 発を全て
  撃ち込めば倒せるが、弾数 3・回復 6 秒/発の希少さと、硬直中の
  パルス 2 倍との選択が残る(「砲で削るか、掘って逃げるか、硬直を撃つか」)。
- 弾数・溜め・回復の数値は変更しない。砲を通常敵に使うのは
  構造的に過剰火力だが、希少な弾数という対価が既にあるため、
  バランス調整は「撃つ自由、弾は自己責任」に置く。

## 6. 段階分け(各段階が独立した PR)

### 段階 1: 記録保持 + 飛行敵

- §4 の記録保持(chooseSpawns への defeated 引数)と §1 の飛行敵
  (出現スキャン、2 状態の行動、大空洞水域のみ)。
- 検証: 記録保持と飛行敵の出現決定・行動状態機械を Vitest で固定
  (同じ seed で撃破済み ID が二度と選ばれないこと、地区ゲート、
  追尾/巡回の遷移条件)。大空洞水域での飛行敵のスクリーンショット。
  frametime 3 場面(render p50 の悪化 +0.5 ms 以内、第1弾の基準を継承)。

### 段階 2: ドロップ

- §3 のドロップ(抽選の純関数、地区プロファイル、落下・寿命・上限、
  拾取と資源への反映)。Walker・飛行敵の両方から落とす。
- 検証: `dropFor` の分布と地区倍率を Vitest で固定(固定 seed の
  サンプルで確率の偏りを数える)。ドロップ表示と拾取のスクリーンショット。
  frametime(ドロップ上限 16 個の場面を含む)。

### 段階 3: ボス + 砲と敵の相互作用

- §2 のボス(配置の純関数、3 相の状態機械、HUD バー、確定ドロップ)と
  §5 の砲相互作用(beamHit、通常敵は即死、ボスは 10 ダメージ)。
- 検証: `bossSpawnFor` が `grandHallAt` と一致すること、状態機械の
  遷移(予備動作→突進→硬直、硬直中の被ダメージ 2 倍)、`beamHit` の
  幾何を Vitest で固定。テストで特定した大広間の座標での
  ボス戦スクリーンショット。発射フレームの処理時間(frametime の max 側)を
  併記し、発射時の同期処理が体感に響かないことを確認する。
- 飛行敵の他地区開放(flyerMul の数値変更)は、この段階の実機判定と
  合わせて判断する(未決事項 2)。

## 7. コストの見通し

- 更新: 有効中の敵は現行の走査範囲(±40×±24)で頭数が bounded。
  飛行敵の密度上限を加えても同オーダー。ボスは最大 1 体。
  ドロップは上限 16 個で落下判定のみ。
- 描画: 敵・ドロップ・ボスバーは全て既存の fx/HUD 相乗りで平坦色・
  少ない色数に留める。新規描画パスは作らない。ボスは体格が大きい分、
  塗り面積は増えるが 1 体のみ。
- 発射フレーム: 砲の敵判定は有効中の敵への線分距離計算のみで、
  既存の bore(地形)より軽い。
- 目標: 第1弾と同じく render p50 の悪化 +0.5 ms 以内を各段階の合格線にする。

## 8. やらないこと

- **サバイバル要素**(空腹・燃料・拠点化など)。ゾーン設計で後の別件と
  決まっており、本設計では接続もしない。
- **新しい武器種の追加**と既存武器の強化ツリー。戦闘の幅は敵側と
  砲の相互作用で作る。
- **敵弾・遠隔攻撃**。敵の攻撃は接触のみ(第1弾の非ゴールを継承)。
- **記録の永続化(セーブ)**。セッション内の保持まで。
- **ボスの複数種・フェイズ制**。ボスは 1 種・3 相まで。
- **ドロップの吸着・自動回収**、資源の新種追加(砲弾と HP 以外は落とさない)。
- ワールド生成パラメータ・地区文法の変更(出現はスキャンと倍率表の範囲で閉じる)。

## 未決事項(ユーザーの判断が要る点)

1. **ボス撃破の報酬**: 資源ドロップのみとした。砲の弾数上限 +1 のような
   恒常強化を付けると「倒す意味」は強くなるが、数値体系(弾数 3 前提の
   バランス)に手を入れることになる。
2. **飛行敵の他地区開放**: 段階 1 では大空洞水域のみ。電力区・生体異物区へ
   広げる(flyerMul の変更のみで可能)を段階 3 で判断したい。
3. **ドロップの吸着**: 近づくと吸い寄せるマグネットは拾い漏らしを減らすが、
   操作の読み(拾いにいくリスク)を消す。今回は無しで設計したが要否の判断が要る。
4. **ボスの再戦**: 撃破後は二度と出ない設計。再戦(再挑戦)できる仕組みが
   欲しいかどうか。
