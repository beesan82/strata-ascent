# 設計書: タッチ操作(スマホで触れるように)

状態: ユーザー承認済み(2026-11-03、提示した設計案に対して「この内容で実装して」)

## 背景

GitHub Pages で公開したところ、スマホで開けるが何も操作できない、とユーザーが実機で確認した。
操作はキーボード専用(`src/core/input.ts` が `keydown`/`keyup` のみ)で、マウスも照準に使う前提だった。

## ゴール / 非ゴール

- ゴール: スマホ(タッチ端末)で、歩く・梯子を登り降りする・跳ぶ・重粒子砲を撃つ、ができる。
- 非ゴール: 照準のタッチ操作(ドラッグで狙う)、眺望(Shift)、ミュート(M)、ゲームパッド。
  PC の操作感は一切変えない(タッチ端末以外では何も表示しない)。

## 方式

全ての操作は `Input` の「押されているキーの集合(`keys`)」から導出される(state / fireHeld / shiftHeld)。
ここにタッチからの入口を足せば、本体ロジック(物理・砲・音)には触らずに済む。

1. `Input.touchDown(code)` / `Input.touchUp(code)` を追加する。
   - `touchDown` は keydown と同じ処理(集合へ追加、押下エッジ登録、入力コールバック発火=音の開始)。
   - `touchUp` は keyup と同じ(集合から除去)。
2. 画面ボタンは新しい `src/core/touch.ts` が DOM で組み立てる(キャンバスの外、DOM の重ね表示)。
   - 配置: 左下に ← →、右下に ↑ ↓ ジャンプ 砲 の 4 ボタン。
   - 各ボタンは Pointer Events で押下/解放を拾い、対応するキーコード(KeyA/KeyD/KeyW/KeyS/Space/KeyF)で
     `touchDown`/`touchUp` を呼ぶ。`setPointerCapture` で指が外れても解放を取りこぼさない。
     `touch-action: none` と `preventDefault` でスクロール・ズーム・長押しメニューを抑える。
   - 表示はタッチ端末だけ: CSS の `@media (pointer: coarse)` で出し、JS 側も同じ条件でのみ組み立てる。
3. 照準の扱い: マウスが一度も動いていない場合(`mouseSeen === false`)、現在の照準は画面左上を向いてしまう。
   タッチでは狙えないので、この場合の照準を「プレイヤーの向き(facing)の水平」に倒す。
   `main.ts` の render へ渡す aimX/aimY の既定と、`fire()` の角度の両方を同じ既定に揃える
   (ライトコーンとビームの向きがずれないこと)。マウスを動かした後は従来どおり。

## 検証の方針

- `Input` のタッチ入口は純粋な集合操作なので Vitest で固定する(window は最小スタブ)。
- ボタンの DOM 自体はテストせず、タッチエミュレーションのスクリーンショットで表示を確認する。
- PC 表示は従来と差分 0(開始地点スクリーンショット)。
- 描画パス(内部バッファ)には触らないため、フレーム計測は不要。DOM の重ね表示のみ。
