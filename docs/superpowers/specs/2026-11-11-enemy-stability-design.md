# 敵全般の出現安定化（歩行敵・固定砲台の粘着保持とランの正規化）設計

## 症状と経緯

2.17 で飛行ドローンのチカチカ・瞬間移動を粘着保持で直した後も、本人から「やっぱ敵がいきなり現れたり消えたりする」と報告（2026-11-11）。飛行敵以外の敵にも同じ病気が残っている。

## 真因（歩行敵で実証）

歩行敵・固定砲台の選定は飛行敵と同じ「窓依存の選定＋選定外の実体を即時破棄」の構造:

1. **ランの窓依存**: `findFloorRuns` は走査窓（±40×±24）で切れたランをそのまま返す。窓端で切れたランは開始位置と長さが窓の位置で変わる。スポーン ID は `w:<ラン開始>,<床行>`、ラン内オフセットは `hash × (ラン長 − 2)` で決まるため、切断位置が動くと ID も出現位置も変わる。2.14 で建設者に導入した `canonicalRun`（窓端のランを実延長へ正規化）は敵選定には未適用。
2. **密度の代表入れ替わり**: 密度規則（24×12）の貪欲な代表選びが列挙順＝窓位置に依存する。実証: seed 20260711、(196,120) から横へ歩く走査で、床行 136 のスポーン `w:216,136` が dx=60 で現れ dx=64 で消えた（プレイヤーから約 40 タイルの位置で点滅）。
3. **保持の不在**: `refreshEnemies` は選定外の歩行敵・砲台を即座に捨てる（飛行敵は 2.17 で保持を入れたが、歩行敵・砲台は未適用）。

なお出現自体（窓に入ったとき画面外で湧く）は従来どおりの仕様で、問題は「見えている範囲・近傍での出現と消滅」。

## 修正方針

1. **ランの正規化**: 敵選定（歩行敵・固定砲台）に渡すランを `canonicalRun` で正規化し、窓端で切れたランの開始位置・長さを窓位置に依存しない形にする。建設者で実績のある関数をそのまま使う。
2. **粘着保持（歩行敵・固定砲台）**: 飛行敵と同じ規則を一般化する。生存中の個体はスポーンアンカーがプレイヤーから保持半径（チェビシェフ 64 タイル）以内なら選定から外れても保持する。新規出現は保持個体のアンカー近傍（各種の密度規則の内側）では湧かせない。地区ゲート・保護点は新規出現だけを止める。
3. **保持の一般化**: 2.17 の `flyerHold` の仕組みを、種別を問わない保持ヘルパーへ寄せる（アンカー位置と ID を持つ実体の列に対して、選定 ID 集合と保持半径で残すものを決める純粋関数）。飛行敵の挙動は変えない。
4. 出現率・密度・行動・HP などの数値は変えない。ボス（セル単位の有効化、広間に 1 体）は対象外。

## 合格条件

- 窓をずらしても保持半径内の既存個体が消えず、窓端のランから決まるスポーン ID・位置が窓位置で変わらないことが単体テストで固定される。
- 全テスト・型・ビルド通過。走査コスト（canonicalRun の追加）の影響は refreshEnemies が 30 フレームに 1 回である前提で許容範囲（frametime の render p50 悪化 +0.5ms 以内）。
