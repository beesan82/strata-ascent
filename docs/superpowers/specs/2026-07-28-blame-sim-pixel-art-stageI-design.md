# ドット絵大改修 段I: レンダリング基盤のドット絵化 設計書

## 背景と全体ビジョン

現状の blame!sim は地形が「延々と床と梯子だけ」に見え、探索の面白みに欠ける。原因は2つ:
1. 生成された構造(施設・メガ施設・通路網・階層メタ)がすべて AIR/SOLID/LADDER の3値に潰れ、意味の違いが画面に出ない。
2. 描画が滑らかなベクター調(Canvas2Dのグラデ・アンチエイリアス線)で、目指す質感と方向がぶれている。

ユーザーの決定:**アプリ全体のグラフィックを「高精細ドット絵(ピクセルアート)」へ底上げし、同時に施設・構造を意味づけて配置する。**

### アートディレクション(確定)
- **高精細ドット絵**(方向C):16色寒色鋼パレット・多階調・弐瓶的な緻密さをドットで。
- **粒度=中**:画面横 **約34タイル**。1ドットが大きすぎずレトロに寄らず、描き込みとドット感が両立。
- **トーン**:段階Fで確立した「ほぼ黒の鋼モノクローム+暖色は錆/灯のみ」を継承。

### 全体ロードマップ(6段。各段が spec→plan→実装の1サイクル)
- **段I(本書)**: レンダリング基盤のドット絵化 — 内部低解像度バッファ+パレット量子化+ディザ+整数拡大。既存の全描画を一段ドット絵化する土台。
- 段II: タイル&装飾のネイティブ・ドット絵化(generate.ts / decor.ts をピクセルアート流に)。
- 段III: ライティングのドット絵化(段階明度バンド+ディザ、複数光源、距離減衰、色温度)。柱①。
- 段IV: 施設の意味づけ&ランドマーク(系統別施設内装・渡り廊下・遺失物/残骸・停止した乗り物)。柱③=当初要望のコア。
- 段V: 空気遠近・被写界深度(遠景ほど粗ディザ・低コントラスト)。柱④。
- 段VI: ポスト処理&動的演出(限定パレットのブルーム・スキャンライン・色調統一/蒸気・水ゆらぎ・点滅灯・塵・火花)。柱②+⑤。

本書は**段Iのみ**を対象とする。段II以降は各自のspecで詰める。

---

## 段I ゴール

既存の描画コード(background / megastructure / chunkbake / lighting / lightshaft / playerSprite / post)を**作り変えずに**、パイプラインの最終段で全体を一段ドット絵化する。カメラ・物理・ワールド生成・当たり判定は不変。段I完了時点で「既存の見た目がそのまま、確実にドット絵になっている」状態を作る(グラデ由来の色帯はディザで散らす。ネイティブなドット絵タイルは段II)。

### 成功基準
- 全シーン(spawn/中層/大空洞/別系統)が16色パレットに量子化され、ドット絵として表示される。
- ドットがクリスプ(サブピクセルのにじみ・ちらつきが無い)。移動・ズームでドットグリッドが破綻しない。
- 既存テスト(220前後)が回帰なし。純関数(量子化/ディザ/パレット最近傍/ズーム量子化)に決定論テストを追加。
- `npm test` / `npx tsc --noEmit` / `npm run build` すべてクリーン。

## アーキテクチャ

### パイプライン
```
renderer.render()
  ├─ 内部オフスクリーン canvas(低解像度 bufW×bufH)へ既存の全レイヤーを描画
  │     背景 → 超構造 → タイル焼き込み → プレイヤー → ライティング → 光条 → ポスト(グレイン/ビネット)
  ├─ その ImageData を1パス走査:各画素を Bayerディザ付きで16色パレットへ最近傍量子化
  └─ 内部 canvas を画面 canvas へ nearest-neighbor で整数倍拡大転写(レターボックス中央寄せ)
```

現状 `renderer.render()` は画面 canvas の 2D context へ直接描いている。変更は「描画先を内部低解像度 canvas に差し替え、最後に量子化+拡大転写を挟む」こと。**各レイヤーの描画関数のシグネチャ・ロジックは変更しない**(渡す ctx と、幅・高さ・ppt が内部解像度基準になるだけ)。

### コンポーネント(責務と境界)

**`src/render/palette.ts`(新規・純粋)**
- `PIXEL_PALETTE: readonly string[]` — 16色寒色鋼(`steel.ts` の STEEL 値を核に、中間階調を補って16段に構成)。
- `paletteRgb(): Uint8Array` — パレットを [r,g,b]×16 の数値配列に一度だけ展開(量子化ループ用)。
- `nearestIndex(r,g,b, pal): number` — 重み付きユークリッド距離(知覚寄り係数 0.30/0.59/0.11)で最近傍パレット添字。純関数・決定論。
- 依存:なし(steel.ts の色定数のみ)。

**`src/render/dither.ts`(新規・純粋)**
- `BAYER4: readonly number[]` — 4×4 Bayer 行列(0..15)。
- `bayerOffset(x,y): number` — `(BAYER4[(y&3)*4+(x&3)]/16 - 0.5)` を返す(-0.5..+0.5)。純関数。
- 量子化前に各チャンネルへ `offset * DITHER_STRENGTH` を加える。

**`src/render/pixel.ts`(新規)**
- `class PixelPipeline` — 内部オフスクリーン canvas の生成・リサイズ、量子化+ディザの適用、画面への整数拡大転写を担う。
  - `resize(screenW, screenH)`: 目標タイル幅(≈34)と整数スケールから内部解像度 `bufW/bufH` と `scale`(整数)を決める。`bufW = round(screenW / scale)`。
  - `get ctx(): CanvasRenderingContext2D` — renderer が描画する内部 context。
  - `get bufW/bufH`: renderer が ppt 計算に使う内部寸法。
  - `present(screenCtx)`: 内部 ImageData を量子化+ディザし、`imageSmoothingEnabled=false` で画面へ `scale` 倍拡大転写。レターボックス余白は黒(STEEL.black)。
- 依存:palette.ts / dither.ts。

**`src/core/zoom.ts`(変更・純粋)**
- 既存 `targetZoomForOpenness` の出力を**離散段**に量子化する `quantizeZoom(z): number` を追加(例: 最近傍を {1, 3/4, 1/2, 1/3} から選ぶ)。ドット絵として常にクリスプなズーム段のみ許可。EMA平滑後に段へスナップ。

**`src/render/renderer.ts`(変更)**
- コンストラクタで `PixelPipeline` を保持。`resize` で pipeline もリサイズ。
- `render()` 内で `w/h/ppt` を内部解像度基準(`pipeline.bufW/bufH`)に置き換え、描画先 ctx を `pipeline.ctx` にする。末尾で `pipeline.present(screenCtx)` を呼ぶ。
- カメラ由来のオフセットを内部px単位に丸めてドットにじみを防ぐ(`Math.round`)。

**`src/main.ts`(変更・最小)**
- ズーム目標に `quantizeZoom` を適用(EMA の後)。

### データフロー
1. `main.update`:開放度→目標ズーム→`quantizeZoom`→camera へ平滑追従(段へスナップ)。
2. `renderer.render`:内部低解像度 ctx に全レイヤー描画→`present` で量子化+拡大→画面表示。
3. 量子化は表示のみ。tileAt / 物理 / 破壊差分には一切影響しない。

## 内部解像度とスケールの決定

- 目標:画面横に**約34タイル**。
- `TARGET_TILE_PX`(1タイルあたりの内部ドット数)の目安は **6**(=画面横 34タイル×6 ≈ 内部204px幅級)。中密度プレビュー相当。実装時にスクショで 5〜7 の範囲で最終調整する。
- `scale = max(1, floor(screenW / (34 * TARGET_TILE_PX)))` の形で整数スケールを選ぶ。
- `bufW = ceil(screenW / scale)`, `bufH = ceil(screenH / scale)`。内部 canvas はこの寸法。
- 画面へは `scale` 倍で拡大。端数は右/下のレターボックス(黒帯)で吸収。
- ウィンドウリサイズ時に再計算。

**にじみ防止:** カメラのワールド→内部px変換後、平行移動量を整数へ丸める。ズームは離散段なので内部 ppt も安定。

## エラー処理・エッジケース

- 内部 canvas 取得失敗(context null):従来同様 `!` で握るが、生成箇所を1点に集約。
- 極端に小さい/大きいウィンドウ:`scale>=1` を保証。`bufW/bufH` の下限を設ける(例 最小 160px 幅)。
- 量子化ループのコスト:内部解像度が低い(概ね横200〜500px級・画面サイズ依存)ため全画素走査でも軽い。`present` は毎フレーム1パスのみ。
- 既存の画面シェイク(post前の translate):内部 ctx に対して行うので整数化と両立させる(シェイク量も内部px単位に丸め)。

## テスト戦略

**純関数(Vitest・決定論):**
- `palette.test.ts`: `PIXEL_PALETTE` が16色・重複なし・輝度が概ね単調(steel由来)。`nearestIndex` が各パレット色そのものに対しその添字を返す/中間色を妥当な近傍へ割り当てる。
- `dither.test.ts`: `BAYER4` が0..15の置換、`bayerOffset` が [-0.5, 0.5) かつ 4×4 周期。
- `zoom.test.ts`(追記): `quantizeZoom` が許可段のみ返す・単調・境界で最近傍段を選ぶ。

**見た目(スクショゲート):**
- `screenshot.mjs` で spawn / 中層 / 大空洞 / 別系統を撮影。exit0・[pageerror]無し。目視で「16色に量子化・ドットがクリスプ・移動でちらつかない」を確認。

**回帰:** 既存の全テストがパスすること(描画先canvasの変更は純ロジックに触れない)。

## スコープ外(本段では扱わない)

- タイル・装飾を"ネイティブ"ピクセルアートで描き直すこと(段II)。段Iは既存ベクター描画を量子化するのみ。グラデ由来の色帯はディザで散らすが、完全なドット絵タイルは段IIで。
- ライティングの段階明度化・複数光源(段III)。
- 施設の意味づけ・新構造物(段IV)。
- 空気遠近・被写界深度(段V)、ブルーム・動的演出(段VI)。
- 新しい TILE 種・物理・エレベータ等の"動く"要素(別プロジェクト)。

---

## 留意

- 量子化は**表示層のみ**。決定論(worldgen/物理)には無関係。
- パレットは16色固定を基本とし、系統識別は既存の accent/超構造/微量ティントで残す(段IIIで光の色温度でも補強)。
- 段Iのゴールは「作り直し」ではなく「土台化」。最小の変更で全体を確実にドット絵化し、以降の段が段Iの上に安全に積めるようにする。
