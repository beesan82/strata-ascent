# Blame! 風 2D構造体探検シミュレーション 設計書

日付: 2026-07-11
ステータス: 承認済み(ユーザーレビュー待ち)

## コンセプト

弐瓶勉『Blame!』の世界観 — 無秩序に増殖し続ける超構造体、圧倒的なスケール、闇と静寂、孤独な旅 — を味わえる、ブラウザで動く2Dサイドビュー探検ゲーム。

体験の核(優先順):
1. 巨大構造の圧倒感と孤独
2. 探索と発見
3. 緊張感のある遭遇
4. 物語と謎解き(断片テキストによる)

## ゲームデザイン

### プレイヤー
- 操作: ←→移動、ジャンプ、梯子・壁の昇降。ライト照射方向はマウス(または移動方向自動)
- 装備:
  - **携行ライト**: 闇を照らす。時間でエネルギー減少。切れても即死しないが視界が数タイルまで狭まる
  - **重力子放射線射出装置**: チャージ制(最大2〜3発)。地形も敵も貫通する直線ビーム。切り札であり詰み防止の最終手段

### 世界の体験
- 画面はほぼ闇。プレイヤー周囲とライトの円錐だけが照らされ、構造はシルエットで浮かぶ
- 世界は横・縦に広がるが、基本進行方向は「上」。明確なエンディングは置かず「どこまでも昇れる」ことが世界観の核
- 一定高度ごとに「階層」が切り替わり、生成される構造の質感が変化

### 遭遇
- **セーフガード(駆除系)**: 特定領域を徘徊。ライトや音に反応して追跡(状態機械: 巡回→警戒→追跡)
- 基本は隠れる・逃げる・迂回。追い詰められたら重力子砲で構造ごと撃ち抜く
- 死亡時は直前の中継塔(セーブポイント)から再開。世界はシードで保持される

### 物語
- ログ端末・遺物・死体が断章テキストを持つ
- 断章は階層ごとのプールから選ばれ、深い階層ほど核心的な内容が解放される

### リソース(軽め)
- ライトのエネルギー(時間減少、補給ポイントで回復)
- 重力子砲チャージ(充電端子でのみ補給)
- 中継塔 = セーブ+全回復

## 技術アーキテクチャ

スタック: **Vite + TypeScript + Canvas 2D API**(ゲームエンジン不使用、ランタイム依存ゼロ)

選定理由: このゲームの魅力は「ルック(闇とシルエット)」と「ワールド生成」に集中しており、どちらもエンジンの恩恵が薄い。物理は歩行・ジャンプ程度で自前実装が軽い。

### モジュール構成

```
src/
  main.ts            — 起動、ゲームループ(requestAnimationFrame、固定タイムステップ)
  core/
    input.ts         — キーボード/マウス状態の集約
    camera.ts        — プレイヤー追従、巨大空間でのズームアウト演出
  world/
    worldgen.ts      — プロシージャル生成(純粋関数: シード+チャンク座標 → タイル)
    chunks.ts        — チャンクの遅延生成・キャッシュ・破棄
    tiles.ts         — タイル定義(壁、床、梯子、配管、端末、充電端子…)
    strata.ts        — 階層(高度帯)ごとの生成パラメータ
  entities/
    player.ts        — 移動・ジャンプ・昇降の物理、リソース保持
    safeguard.ts     — 徘徊/追跡AI(状態機械)
    physics.ts       — AABB vs タイル衝突判定(プレイヤーと敵で共用)
  render/
    renderer.ts      — 描画統括(シルエット→闇→ライト合成)
    lighting.ts      — ライトマップ(オフスクリーンCanvasで光源合成)
    silhouette.ts    — タイル・構造物のシルエット描画
  game/
    state.ts         — ゲーム状態遷移、セーブ/ロード(localStorage)
    lore.ts          — 断章テキストのプールと出現管理
    beam.ts          — 重力子砲(地形破壊を含む)
```

### データフロー(1フレーム)

入力 → プレイヤー/敵の更新(物理・AI) → カメラ更新 → 必要チャンクの生成/破棄 → 描画(シルエット層 → 闇を敷いたライトマップに光源を焼く → 乗算合成)

### 設計上の要点
- **worldgen は純粋関数**: `generate(seed, chunkX, chunkY) → チャンクデータ`。同一シード → 同一世界。セーブは「シード+プレイヤー状態+破壊差分」のみ
- **地形破壊は差分マップ**としてチャンクと別に永続保持(再生成後も破壊が残る)
- **ライティング**: オフスクリーンCanvasに闇を敷き、光源を `globalCompositeOperation` で切り抜いて乗算合成。シェーダ不要

## ワールド生成

### チャンク方式
- 64×64タイル/チャンク(1タイル≒1m、画面表示は約40×23タイル)
- プレイヤー周囲のみ生成・保持、離れたら破棄(破壊差分は残す)
- 横・縦とも実質無限

### 生成アルゴリズム(チャンク単位、決定論的)
1. **骨格**: 低頻度ノイズで密集領域/巨大空洞を決定。超巨大空間は数チャンクぶち抜きの空洞として出現
2. **床と壁**: 密集領域に水平床を多層に張り、垂直壁・柱で分断。床に開口部
3. **接続保証**: チャンク内の到達可能性をチェックし、孤立空間に梯子・開口部を追加。「上へ昇るルートが必ず存在する」ことを保証
4. **ディテール**: 配管、ケーブル、瓦礫、梁などの装飾シルエットを散布
5. **配置物**: ログ端末、充電端子、中継塔、セーフガード発生域を密度ルールで配置

### 階層(strata) — 高度500タイルごとに変化

| 階層 | 質感 |
|---|---|
| 最下層 | 密集した配管と瓦礫、狭い通路(チュートリアル的) |
| 居住区跡 | 規則的な部屋の残骸、ログ端末が多い |
| 廃棄物層 | 崩れた床、落下リスク、セーフガード多め |
| 大空洞帯 | 数百メートル級の吹き抜け、橋と塔、圧倒感の見せ場 |
| 上層 | 静寂、構造の異質化、核心的断章(以降ループ+強度上昇) |

### ランドマーク
中継塔・巨大構造物は生成規則に一定間隔で埋め込み、遠くからシルエットで見える「目指す目印」にする。

## エラー処理
- セーブデータ読み込み失敗・バージョン不一致 → 破棄して新規開始(警告表示)
- 生成の接続保証が万一破れても、重力子砲による地形破壊が詰み防止として機能

## テスト方針
- **ユニットテスト(Vitest)**: 純粋ロジック対象
  - worldgen: 決定論性(同一シード→同一出力)、上方向ルートの存在、階層パラメータ切り替え
  - physics: AABB衝突の代表ケース(着地、壁ずり、梯子)
  - beam: 破壊差分の記録と再適用
- **描画・操作感**: ブラウザでの実プレイ確認(自動化しない)

## MVPの段階分け(各段階で「遊べる」状態を保つ)

1. **歩ける闇** — 移動・ジャンプ・衝突、固定テストマップ、闇+ライト描画。ここでルックを確認し雰囲気を確定
2. **無限の構造体** — プロシージャル生成+チャンク管理+階層変化
3. **緊張** — セーフガードAI、重力子砲(地形破壊込み)、死亡と中継塔リスポーン
4. **物語と手触り** — ログ端末と断章、リソース管理、セーブ/ロード、巨大空間のカメラ演出、余裕があれば環境音

## スコープ外(YAGNI)
- マルチプレイ、モバイル対応、ゲームパッド対応
- 明確なエンディング・クエストシステム
- 本格サバイバル(食料・耐久度)
- NPC・会話システム(断章テキストのみ)
