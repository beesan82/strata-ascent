### 撮影位置の候補（座標は式。親側で seed 20260711 について確定する）

`--pos=x,y` は体の左上（タイル）。床の行 F に立たせるには `y = F − 1.9`。開始時のズームでは横 ±17 タイルほどが見える。

1. **残滓の出る床**: 開始地点に近いチャンクから `decorateChunk(20260711, cx, cy)` を走査し、`SCENERY_COLORS.wreck`（無ければ `slab` の rect・`beam`・`shard`）の塗りの命令を 1 つ選ぶ。`x0 = cx·64 + min(pts の x)`、`F = cy·64 + max(pts の y)`（rect は `cy·64 + y + h`）。`--pos=(x0 − 4),(F − 1.9)`。
2. **桁渡りの通路**: `SCENERY_COLORS.girderWeb` の rect を 1 つ選ぶ。`X = cx·64 + op.x`（16 整列）、天井行 `R = round(cy·64 + op.y − 1.63)`、床 `F` = `R + GIRDER_CLEARANCE + 1` から下へ見て最初に `tileAt(seed, X + 8, F)` が SOLID の行。`--pos=(X + 8),(F − 1.9)`。電力区・水域の層だと桁が並んで見えやすい。
3. **ステンシル壁面**: `SCENERY_COLORS.stencil` の rect を 1 つ選ぶ。ブロック `bx0 = floor((cx·64 + op.x)/8)·8`、`by0 = floor((cy·64 + op.y)/7)·7`。列 `bx0 − 12 … bx0 + 20`、行 `by0 − 8 … by0 + 16` の中で「SOLID の上 2 行が AIR」の床のうち `(bx0 + 4, by0 + 3)` に最も近い `(X, F)`。`--pos=X,(F − 1.9)`。居住区画の層が最も出やすい。

候補を出す一時コード（コミットしない。vitest で 1 回だけ流して座標を写す）:

```ts
import { it } from 'vitest';
import { decorateChunk, SCENERY_COLORS } from './decor';
it('shots', () => {
  for (let cy = -2; cy <= 2; cy++) for (let cx = -6; cx <= 6; cx++) {
    for (const op of decorateChunk(20260711, cx, cy)) {
      if (op.kind === 'poly' && op.fill && op.color === SCENERY_COLORS.wreck) console.log('wreck', cx, cy, op.pts[0], Math.max(...op.pts.filter((_, i) => i % 2)));
      if (op.kind === 'rect' && op.color === SCENERY_COLORS.girderWeb) console.log('girder', cx, cy, op.x, op.y);
      if (op.kind === 'rect' && op.color === SCENERY_COLORS.stencil) console.log('stencil', cx, cy, op.x, op.y);
    }
  }
});
```

## 実装時の裁定

- **景色はすべて `decorateChunk` の中で作り、描画パスを足さない。** 床の残滓と桁渡りは新しい `sceneryOps`（`segmentOps` の後、既存装飾の上に重なる）、深いベイとステンシルは既存の凹ベイのループの中。どちらも非 surface の命令なので `DecorCache` → チャンク焼き込みに乗り、コストはチャンク生成時だけになる。
- **色は既存色と 1 つも重ならない値にした。** 既存テストは色で装飾を見分けている（`PALETTE.pipe` の水平線は床配管、`STEEL.base` の rect はトレイ、`PALETTE.rib` の塗り poly はガセット、`STEEL.stringer` の線は電力区のケーブル束、など）。同じ色を使うと新しいモチーフが既存の検査に紛れて落ちる。新色は STEEL の隣り合う 2 色の混合だけで、明度はランプの範囲にとどまる（設計 §範囲「色数は既存パレットの範囲」）。量子化（32 色）で既存の色に吸われる可能性は見た目で確かめる。
- **残滓は床の 16 タイルセグメントに 1 つまで、基礎確率 0.12。** 地区倍率を掛けても最大 0.19（居住区画）、寒鋼基層は 0.072。セグメントの判定・ハッシュの引数 `(s, wy)` は既存の床装飾と同じなので、地区をまたいでもチャンク単位で決定論。
- **保護範囲は実行時（`main.ts`）より少し広い、シードだけの関数にした。** 実行時は休憩点の中心から r=20、開始地点から r=10。装飾は `findSpawn(seed)` と休憩点の箱から求め、箱 + 8、開始地点 + 12。`?x=&y=` の開始位置の上書きは見ない（装飾はシードの純関数で、`DecorCache` もシード単位のため）。
- **「梯子・出入口の真上/真下を避ける」は足元の列の空気で判定した。** 出入口は専用のタイルではなく「壁の下 3 行の AIR」なので、残骸・板は足元の外 ±2 列まで床の上 4 行が AIR であること（= 壁際・出入口の脇に置かない）、梯子は同じ範囲の上 4 行と床の直下で弾く。倒れた梁は逆に壁が要るので、床から 4 行上まで固体（= 出入口の穴の無い）壁にだけ寄りかかる。破片の野原はセグメントの 16 列の上 4 行。
- **倒れた梁は壁が無いセグメントでは重み 0 にして、他の種類へ振り替える。** 「壁際から床へ」を守るため、宙に浮いた梁を描かない。（→ 末尾の「親側の検証で梁が 0 件」の裁定で、梁の置き方そのものを「壁と床の角」の走査に移した。重みの表と振り替えの規則は、残骸・板・野原の出方を保つために残している）
- **頭上の桁渡りは「天井に沿って走る吊り H 桁」として描いた。** 側面視では通路を奥行き方向に横切る構造は見えないため、天井の下に吊られた太い桁が 16 タイルごとの継手と 2 タイルごとの補剛材のリズムで頭上を流れる形にした（歩くたびに頭上を構造が横切る読み）。桁の下端は天井下面 + 1.68（配管束が添えば + 2.33）、下に 6 行の空気を要求するので、床に立った頭（床 − 1.75）との間は 2 タイル以上空く。吊りトレイ（8 タイル天井 r∈[0.44,0.56)）の区間は吊り金具と交差するので避けた。カテナリー・垂れたワイヤー・地区の天井小物とは重なりうる（桁が手前）。
- **ベイの深化は既存の凹ベイすべてに掛かる。** 奥の一段暗い面・左の内壁の陰・底の敷居の受け光の 3 命令を足す。中身（配管束・シルエット）は抜け区画の無いベイだけに入れ、抜け区画・鉄筋と重ならないようにした。
- **ステンシルはベイにならなかったブロックだけに、ベイと同じ「閉じた壁」の判定で描く。** ベイとは重ならず、境界一致の性質もベイと同じ（7 行ブロックが水平境界をまたいでも両側が同じ結論になる）。文字は 7 セグメントの数字と横棒・十字・下線だけ。画の端を詰めて隙間を残し、ステンシルらしいブリッジにした。薄さは rect の `alpha 0.22`。
- **地区はセグメントの行（床・天井）・ブロック中央の行で引く。** 地区の境（セル境界）では隣り合うセグメントで濃さが段で切り替わる。既存の地区小物（`decorMul`）と同じ振る舞いで、チャンク境界では破綻しない。
- **生体異物区は残骸に根を絡める。** 「既存の生体装飾に残滓を混ぜる」を、残骸の重み 1.8 と、残骸に `biomechRoot` の根を這わせることで表した。
- **走査範囲とバッファ。** 床の残滓は床行 `ly ∈ [0, 68]`（床から上へ最大 3.4 はみ出す分）、桁は天井行 `ly ∈ [-4, 64]`。バッファ読みは最悪ローカル 70 で `DECOR_MARGIN = 17` の内側。横は最右のセグメントの足元の外 +2 列（ローカル 81）がバッファ外（AIR 扱い）になりうるが、そのセグメントはこのチャンクの画素に重ならない（焼き込み時にクリップされる）。
- **テストは新しいファイル `src/render/decorScenery.test.ts` に分けた。** 低頻度のモチーフでも重くならないよう、走査は見つかった数で打ち切る。境界一致のテストは「見つかった組が 0 なら失敗」で恒真を避ける。
- **親側の検証で倒れた梁が 0 件だった（「倒れた梁 が広域のどこかに出る」と「倒れた梁は壁から床へ倒れかかる」が found 0）。原因はセグメントの条件。** 残滓のセグメントは 16 列すべてが「上が空気の SOLID」でなければならない。梁はさらに、その端のすぐ外の列（`x0 − 1` か `x0 + 16`、つまり 16 整列の列）が床から 4 行上まで固体の壁であることを要した。実世界の壁（施設の側壁、躯体の塊の縁）は 16 整列の列に来ないので、「16 列の床が、ちょうど整列の列で壁に突き当たる」組がほぼ無い。その上で、残滓の率 0.12 × 地区倍率 × 梁の重みの割合（約 1/4）を通る必要があった。走査範囲（cx −4..4、cy −14..3）では 1 件も通らなかった。重みの振り替え（`pickWeighted` の梁の重み 0）と壁の判定の読み位置（`wallAt` の `wy − k`）は設計どおりに動いており、原因ではない。
  - **修正: 梁はセグメントに縛らず、「壁と床の角」ごとに置く。** 角とは次の両方を満たす位置: 列 `wx` が床の行 `wy` から上へ 4 行 SOLID（出入口の穴なし）、かつ隣の `wx ± 1` から `BEAM_RUN = 8` 列が「SOLID の床・上 4 行が空気・直下に梯子なし」。角ごとに `hash2(seed+795, 2·wx + 向き, wy) < min(BEAM_MAX = 0.6, BEAM_RATE = 0.25 × remnant × beam)` で出す。地区ごとの確率は、寒鋼 0.15・居住 0.24・廃棄 0.6（頭打ち）・水域 0.09・電力 0.2・精錬 0.24・生体 0.2。角は床セグメントよりずっと少ないので、残滓の基礎確率 0.12 より高めに取った（設計の「世界のどこかには普通に出る」）。
  - **残骸・板・野原は 1 つも変えない。** セグメントの種類の選び方（`remnantKind`: 率・`pickWeighted` の重み・壁の判定）は、当初のまま関数に括り出しただけ。出る場所・種類・ハッシュは同じ。旧来の「種類が梁（kind 2）」のセグメントには何も描かない。このセグメントは以前も梁を描くか、足元が塞がって何も描かないかのどちらかで、他の種類には振り替わらなかったので、他の種類の出方は変わらない。
  - **梁は床の残滓と重ねない。** 梁の足元の列に掛かるセグメントが残骸・板・野原のセグメント（`remnantKind` が 0・1・3）なら、梁を出さない。保護範囲（`sceneryGuarded`）は、壁の列と足元の列を合わせた矩形で引く。
  - **チャンク境界。** 角の判定は世界座標だけで決まる。壁の列はローカル [−7, 70] を走査する（このチャンクの画素に掛かる梁、つまり壁の面から 5.75 先までに収まる梁をすべて含む）。読みは最悪で、床の列 ±8 と足元のセグメント（ローカル [−17, 80]）、行 `wy − 4 .. wy + 1`（床の行は残滓と同じ `ly ∈ [0, 68]`）。いずれも `DECOR_MARGIN = 17` の内側に収まる。バッファ外を読むのは、このチャンクの画素に掛からない梁だけ。水平境界での一致は、残滓の境界テスト（床が境界の直下 4 行以内）で梁も検査している。
- **親側の検証で「桁渡りの境界一致」が found 0 だった。原因は走査範囲で、生成と境界一致は壊れていない。** 桁の天井（16 列が SOLID・下に 6 行の空気）は、実際にはほぼ躯体の床帯の行（`y mod floorSpacing = 0`）に来る。寒鋼基層の `floorSpacing = 8` は 64 を割り切るので、床帯が境界の直上 4 行（`y mod 64 ∈ [60, 63]`）に来ることは構造上無い。既定の走査範囲（cy −14..3）は寒鋼のセル 0 と隣の 3 セルだけで、そこでは条件を満たす組が出なかった。他の地区（床帯の間隔 9〜15）では、境界の直上に床帯が来る（居住の 5 は床の間が 4 行しか空かないので、桁そのものが出ない）。境界の扱いは正しい: 上のチャンクは天井行 `ly ≤ 64`、下のチャンクは `ly ≥ −4` を走査し、判定の読み（天井行 + 6 まで）がどちらもバッファ内なので、両側が同じ結論になる。生成は直していない。
  - **修正（テスト側）: 桁の境界テストだけ、走査を cy −60..3 に広げて 1 サイクル（7 地区）を含める。** 重さは、境界の直上 4 行に「16 列の天井 + 下に `GIRDER_CLEARANCE` 行の空気」（桁の必要条件）が地形に無い組を、`tileAt` だけで飛ばして抑える（装飾を計算するのは、条件を満たしうる組だけ）。飛ばすのは両側とも桁が出えない組なので、一致の検査は弱めていない。他のテストの走査範囲は変えていない。

## 保留

- **未検証。** このセッションではテスト・tsc・build・スクリーンショット・計測を実行していない。親側で確かめる。
- **新テストの「広域に出る」「境界一致の found > 0」は seed 42 の走査範囲（cx −4..4、cy −14..3。桁の境界テストだけ cy −60..3）に依存する。** 低頻度のモチーフ（倒れた梁・ステンシル）が 0 件で落ちたら、範囲を広げるか（決定論なので一度確かめれば安定）、率を見直す。
- **梁を角の走査へ移した修正は、このセッションでは実行して確かめていない（シェルを使わない指示のため）。** 角の数は、施設の側壁と床帯・底の壁の角、躯体の塊の切り立った縁から見積もった。親側の検証で梁がまだ 0 件なら `BEAM_RUN`（8）を下げるか `BEAM_RATE` を上げる。多すぎて目障りなら `BEAM_RATE` を下げる。
- **狭い部屋（幅 16 未満）では、左右の壁から倒れた梁が交差しうる。** 互いを避ける規則は入れていない。実機で目障りなら、片側を優先する規則を足す。
- **頻度・濃さ・色は実機の「雰囲気」判定で調整する。** 表の値と基礎確率は設計書の寄り方を満たす初期値。量子化で新色が既存色に吸われて差が見えない場合は、`edge`・`girderLit` を一段明るく寄せる。
- **動的な物（補給キャッシュ・端末・infra・アイテム）との重なりは避けていない。** 残滓は焼き込み層なのでスプライトの背後になる。読みにくい組み合わせが出たら、infra の配置矩形をシードの純関数として装飾側でも避ける。
- **前室の先行表示（accent の配管・帯）とは重なりうる。** 残滓が手前に描かれる。
- **開始位置の上書き（`?x=&y=`）では保護範囲が開始地点に付いてこない。** 撮影位置に残滓が重なっても実害はない（装飾のみ）。
- **当たり判定のある造形（通路を割る巨柱など）と動的な残滓（点滅する標識灯）は今回の範囲外。** 設計書の保留どおり次段階の候補。
- **CLAUDE.md の「現在地」と版数は更新していない。** 版数（2.17）は前半の飛行ドローン修正の側で扱う。マージ時に親側で更新する。
