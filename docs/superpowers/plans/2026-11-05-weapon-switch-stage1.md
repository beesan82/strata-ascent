## 実装時の裁定

- **cannonStickPhase の置き場所は `src/core/stick.ts`** にした（計画の選択肢の後者）。スティックの純粋関数群の置き場として既に定義されている場所であり、定数も `CANNON_AIM_RATIO = STICK_DEADZONE` の参照で置けるため。
- **武器モード reducer に `cancelled` イベントを明示した**。設計 §6 の列挙（toggle / fired / neutral）には無いが、「キャンセルでモードが変わらない」（§3-3）を Vitest で固定するための表現として追加した。reducer は状態をそのまま返す。
- **武器モードの状態は `Input` が保持する**。touch.ts はボタンの押下エッジで `input.toggleWeapon()` を呼ぶだけにし、モード変更の通知（`onWeaponChange`）で DOM 表示を同期する。発射後の自動復帰もこの通知でボタン表示まで戻る。HUD は main が `input.weaponMode` を読む。
- **発射候補（release pending）の受け渡し**：スティック砲の「charging のまま離した」は Input が発射候補として立て、main の `fire()` の中でのみ `takeCannonRelease()` で消費して自動復帰する。発射しなかった候補は `graviton.update` の直後に `expireCannonRelease()` で失効させ、無関係な発射（KeyF）に漏らさない。発射可否の判定は従来どおり Graviton の溜め量だけが決める（二重化していない）。
- **makeStick の拡張**：onChange に未加工の倒し比（デッドゾーン処理前）を追加し、onEnd コールバックを新設した。位相判定は中心への戻し量を見る必要があるため、stickVector の丸めた mag では足りない。あわせて **endStick は onEnd を最後の onChange（ゼロ）より先に呼ぶ**よう順序を変えた。逆順だと解放時のゼロで位相が cancel-armed へ進み、「離して発射」が常にキャンセルになる不具合がエミュレーションで実際に発生したため。
- **Task 2 の中間状態**：切替ボタンへの置き換え時点で旧砲ボタンの KeyF 経路を外したため、Task 2 のコミット単体ではタッチで砲が撃てない（Task 3 でスティック文法として復活）。検証は表示切替のみを Task 2 で行い、発射系は Task 3 で全項目を確認した。
- **`.tbtn.cancel-armed` の CSS は削除した**（付与箇所が旧砲ボタンの撤去で消滅したため）。スティック版のキャンセル予告色は設計 §2 の明示手段に含まれていないので足していない。
- **coldSteel の cavity 等、ゾーン段階 1 の数値には触れていない**（本計画は入力系のみ）。

## 計測

- テスト件数：527 件（開始時）→ 540 件（Task 1）→ 542 件（Task 2）→ **550 件（Task 3、最終）**。内訳：weapon.test.ts 新設 +8、stick.test.ts +5、input.test.ts +14 −1（touchPoint テストは撤去に伴い削除）、touch.test.ts −3（cannonPhase のテストは cannonStickPhase のテストへ移行済み）、haptics.test.ts は件数不変（既存ケースに 1 行追加）。
- `npx tsc --noEmit` / `npm run build`：全 Task で通過。
- エミュレーション（Playwright、viewport 844×390・hasTouch・isMobile、座標は getBoundingClientRect 実測、CDP タッチ）で設計 §6 段階 1 の確認項目 1〜8 をすべて実施し **全て通過**：
  1. 切替タップで HUD（`武器 [パルス] / 重粒子砲 3/3` ↔ `武器 パルス / [重粒子砲 3/3]`）とボタンのラベル・色が切り替わる。
  2. 砲モードで倒して溜めゲージ表示 → 0.6 秒超保持 → 離すと発射成立（弾数 3→2、地形の掘削と落下をスクリーンショットで確認）。
  3. 0.25 秒の保持で離すと不発（弾数・モード不変）。
  4. 溜め完了後に起点から 20px（比 0.357）/ 25px（比 0.446）へ戻して離すとキャンセル（発射せず弾数不変）。
  5. パルス連射中に別指で切り替え → 倒し続けても溜めゲージは出ず、離しても弾数は減らない。離して倒し直すと溜めが始まる。
  6. 発射後に HUD とボタンが自動でパルス表示へ復帰。
  7. 非溜め時は左スティックで歩行できる（中央帯域の変化率 56.3%）。溜め中は左スティックを倒しても静止（同帯域の変化率 2.2%。残差は溜め発光とグレイン）。溜め中は `#touch.aiming`（左スティック減光）も確認。
  8. 項目 4 の戻し操作は「フルストローク 56px から中心方向へ 36px のスライド」で成立した。CDP は座標を正確に指定できるため実測上の再現性は高いが、実指での「無理のなさ」そのものは実機判定に残る（下記「保留」）。
- スクリーンショット差分（タッチエミュレーション、スポーン直後・無入力、同引数）：変更前後で **差分 31,325 / 1,316,640 画素（2.38%）、最大チャンネル差 192**。差分の中身は HUD の武器表示追加と切替ボタンのラベル（砲→パルス）・字サイズのみで、意図した範囲に収まっている。
- frametime（`scripts/frametime.mjs --seed=20260711 --stages`、同一機械で変更前 c4769a7 の worktree と交互に計測、各 2 回）：

  | 対象 | render p50 (1 回目) | render p50 (2 回目) | stage:chunks p50 | stage:lighting p50 |
  |---|---|---|---|---|
  | 変更前 | 11.40 ms | 11.90 ms | 0.40 ms | 0.80 ms |
  | 変更後 | 13.20 ms | 11.20 ms | 0.40 ms | 0.80 ms |

  描画パスは増やしておらず、stage 別の p50 は一致。render p50 の絶対値は当日の VM 負荷でゾーン段階 1 の計測時（約 5.2 ms）より全体に重いが、前後の同時比較では系統的な悪化は見られない。本変更は入力系のみで描画に手を入れていないことと整合する。

## 保留

- **PC 経路は現行維持（KeyF 従来動作）。段階 1 の間、PC とタッチで砲の操作が異なる二重仕様になる**（設計 §5 のとおり。PC の統一 = KeyQ 切り替え・左クリック溜め・KeyF 廃止は段階 2）。
- **実機判定は未実施**（親エージェント側）：特に確認項目 8 の実指での戻し操作の無理のなさ（キャンセル圏 25px はノブ径 52px の半分程度のスライド量）、発射後の自動復帰の手触り（設計 §6 段階 3 の再検討候補）、切り替えハプティクスの感触。
- 発射後の自動復帰はタッチ砲のみ。PC の KeyF 発射ではモード概念自体が無いため対象外（段階 2 で扱う）。
- 弾切れ（0/3）でも砲モードへの切り替えは可能で、倒しても溜めは始まらない（設計 §3-4 のとおり。エミュレーションでは弾切れ状態を作るのに実時間の都合で未実施だが、Graviton の `charges > 0` 条件は現行のまま不変）。
- フルスイート実行時に `src/world/worldgen.test.ts` の最重量テストが 20 秒タイムアウトで落ちることが 3 回あった（単体実行では毎回 36 件すべて通過）。本変更は world/ に触れておらず、VM 負荷下の並行実行タイムアウトと判断した。Task 3 の検証ではフルスイート 550 件全通過を確認済みで、最終確認でも落ちたのはこの 1 件のみ（549/550、単体再実行で通過）。
