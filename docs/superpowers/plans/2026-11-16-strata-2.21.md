## 到達可能性の移動モデル(設計書 §A-3 検証 2 の導出)

`src/entities/player.ts` の定数から導く。体は幅 0.75 × 高さ 1.75(立つには頭上 2 行の空きが要る)。
歩行 `WALK_SPEED = 6` タイル/秒、ジャンプ `JUMP_VELOCITY = −13`、重力 `GRAVITY = 30`。

- ジャンプの高さ: 13² / (2×30) ≈ **2.8 タイル** → 床が 2 行上まで届く。
- ジャンプの水平: 同じ高さへ戻るまで 2×13/30 ≈ 0.87 秒 × 6 ≈ 5.2 タイル。
  2 行上へ着地する場合は上昇分が短いので **3 タイル**を保守側に取る。
- 段差アシスト(2.10 で実装済み)により 1 行の段差は歩行で登れる。
- 縁つかみ: 壁面に接した隣の列では、壁の上の床(3 行上)へ登れる。

基準モデル(実際の移動)の辺(立つセル = 足元の床の行と列):
歩行(横 1、上 1 まで)/ ジャンプ(横 3 以内、上 1〜2、弧の空きを要求)/
縁つかみ(横 1、上 3、壁面があること)/ 落下(隣の列の最初の床まで)/
梯子(梯子列に接する床どうしを梯子ノード経由で接続)。
保守モデル(柱あり側): 横 1、上 1 まで、下は制限なし(隣の列の最初の床まで)、梯子は同じ。
加えて、両端と通り道が柱で変わったタイルから 3 タイル以上離れた基準の辺はそのまま使う。

## 実装時の裁定(計画段階)

- **梯子列を胴に含む巨柱候補は棄却する。** 設計書は「施設・幹線のオーバーレイの梯子は
  柱の中に残す(既存の上昇路を切らない)」と定める。ノイズの梯子列(32 列ごとの上昇路)も
  同じ原則で扱い、胴が梯子列を呑む候補は落とす(候補は 8 回試すので頻度への影響は走査で見る)。
  オーバーレイの梯子は設計どおり柱の中でも LADDER として残す。
- **巨柱の合成段**は設計どおり大昇降機の直後(worldgen の合成で grand の段の次)。
  土台タイル(柱なし合成)は worldgen が `pillar.ts` へ差し込む(循環 import の回避。
  `grandShaft.ts` が worldgen を引かない流儀に倣い、pillar.ts も worldgen を引かない)。
- **行列の起点セグメントに既存の残滓(remnantKind 0・1・3)がある場合は行列ごと譲る**
  (先頭の欠けた行列を作らない)。部材は自分のセグメントの残滓・床の途切れ・保護範囲で
  個別にも譲る(設計どおり)。
- **B-3 の敵除外**は既存の保護点(`ProtectedPoint`、チェビシェフ距離)の流儀で、
  終端の乗り場の中心に r=24 の保護点を置く(休憩点の r=20 と同じ近似)。
  保護点は補給・武器庫の選定にも効くが、既存の休憩点ガードと同じ副作用として受ける。
- **B-1 の字幕の「入った先」**: 板の cell を c とすると、下りは c の層、上りは c−1 の層。
  文言・地区名併記の条件は見晴らし台の通過演出(main の autoViewStarted の処理)と揃える。
  クールダウンは板ごと(シャフト ID + 板の cell)8 秒。通過音(入った瞬間)と字幕(抜けた瞬間)で共有する。
- **B-3 の一打**は、乗車中に終端(yTop / yBottom)へ到着したときだけ鳴らす
  (降りた後の余韻という節の趣旨。呼び戻しの到着では鳴らさない)。
- **B-3 のログ行**の距離は、同じ大昇降機に連続して乗っていた間の足場の移動量の合計で数える。
- 新色は §0.5 の上限 8 色以内(基礎の層 2、巨柱 4、サイロ 1 = 7 色)。値は量子化の索引で
  検証してから決める(巨柱: 面・リブ・受け光の索引が互いに異なり、面は躯体の面
  `steelPalette` の `fillMid` の索引と異なること)。

## 実装時の裁定(実装段階)

- 到達検証の2段ゲート化: 保存判定は実移動モデル同士(柱なし全面 vs 最終形全面)、柱自身の通行保証は保守モデルで穴同士・乗り場間に限定した。当初の「保守モデルで全域判定」は、既存地形のジャンプ依存の連絡まで届かないと数えたため。
- baseTileAt の中間段欠落を修正: 柱なし合成にも中間段(stairAt)を含めるよう steppedTileAt 化した。修正前は段差由来の SOLID を「柱で変わったタイル」と誤認し、保存違反の見かけを作っていた。
- 帯の全域埋め立て: 乗り場の帯(梯子列の間)は穴の行以外も SOLID で埋める。帯の中の閉じた床バンドが、届かないポケットを作る実違反が根拠。見た目の柱は本体だけに描く。
- 棄却条件の追加(いずれも到達保存の実測から): (1) 最下のバンドの隙間の下に、帯へ閉じた足場がある候補(hitsSealedPerch。実例は標準シードの p:-8,-6)。(2) 埋め立てに囲まれる施設の梯子がある候補(hitsEncasedLadder。実例はシード42 の p:-2,-5、梯子は x=-281/-280・行 -1803..-1785)。走査は4行刻みのサンプル+当たり列の全行走査にし、採択1件あたり約2.5秒を約1.0秒にした。(3) 両側の梯子列が柱の上下へ抜けていない候補(hitsBrokenLadderAccess)。
- サイロのアンカーは16列×28行の格子に1抽選(当初案では被覆率が70%に達したため格子化)。
- 行列の向きはハッシュで左右を決める(鏡像化)。
- 残滓・行列の足元検査に「床タイル自体が SOLID」を追加(clearAbove / clearAboveWith)。セグメントの外へはみ出す足元の床が未検査で、梯子列の上の床に部材が置かれる実例(シード42、床の行 -480、x=18)が根拠。decorScenery.test.ts の失敗で検出した。
- worldgen.test.ts の座標差し替え: (-40, 130) が柱 p:-1,0 の帯に入ったため (150, 130) へ付け替えた。テストの意図は不変で、付け替え先は tileAt と noiseTileAt が一致することを実測した。
- B-3 の終端の保護点は、補給・武器庫の選定にも効く(休憩点の保護点と同じ副作用として受ける)。
- 終端の一打は専用関数 grandTerminal() とし、立ち上がりを 0.03 秒にした(通過音の 0.35 秒では一打にならないため。55Hz・減衰2.5秒・音量0.5倍の指定はそのまま)。
- 板の内側の灯の間引きの位相は板ごとに取る(板の中で最初の灯を残す)。シャフト全体の位相では、厚さ32行の板で灯が0個になるため。
