# 計画: ズーム段の滑らか化（実機フィードバック対応）

ブランチ: `fix/zoom-smooth`
発端: 2026-11-06、ユーザーの実機フィードバック「視点が広がるのがカクカクすぎて酔う」。

## 診断

- 開放度由来の目標ズームは EMA＋指数平滑で連続的に動くが、描画ズームは `quantizeZoom` で離散段 [0.35, 0.5, 0.75, 1] へ即時スナップする（`src/core/zoom.ts`、`src/main.ts` の描画経路）。
- 開けた場所へ出るたびに 1 → 0.75 → 0.5 と 25〜33% のスケールジャンプが瞬間的に起きる。これが「カクカク」の正体。段境界付近ではチャタリング（往復）も起こりうる（zoom.ts のコメントで「残れば実機確認後に対処」とされていた件が、実機で顕在化した）。

## 方針

段そのもの（ドット絵のにじみ回避）は維持し、段の**切り替わり方**を直す。

- [ ] 段の選択にヒステリシスを持たせる：現在の段から隣の段へ移るのは、連続ズームが段の中点を一定マージン越えたときだけにする（状態を持つ段キーパーを純粋関数＋小さな状態として実装し、Vitest で固定する）。マージンの値は実装時に決めて本書末尾に記録する
- [ ] 描画ズームは段へ即時スナップせず、選ばれた段へ短時間で滑らかに遷移させる（遷移中のみ非段のズーム値を使う。にじみは遷移の一瞬だけに限定される）。遷移の速さは「酔わない範囲で速く」を実装時に調整し、値を記録する
- [ ] 眺望段（VIEW_ZOOM 0.35）への出入りも同じ仕組みを通す（眺望の開始・終了でジャンプしないこと）
- [ ] 検証: 段キーパーの単体テスト（往復でチャタリングしない、大きく動けば追従する）、`npm test` / `npx tsc --noEmit` / `npm run build` 全通過、frametime の前後比較（render p50、各 2 回）。スクリーンショットは遷移の静止画では判別できないため、遷移中・遷移後の 2 枚で段に落ち着くことを確認する
- [ ] 本書末尾に「実装時の裁定」「計測」「保留」を追記（チェックボックスは更新しない）

## 実装時の裁定

- **ヒステリシスマージン `ZOOM_STEP_MARGIN = 0.03`（ズーム単位）**: 段キーパーは、連続ズームが「現在の段と隣の段の中点 ± 0.03」を厳密に越えたときだけ段を移す。中点の前後 ±0.03 がデッドゾーンになる。最も狭い段間隔（0.35↔0.5 = 0.15）の半分（0.075）より小さく、両方向から到達可能。開放度換算では約 ±0.02 で、EMA の残留ノイズより十分大きい。
- **段キーパーの形**: 状態は「現在の段」1 つだけ（main の `zoomStep`）。純関数 `nextZoomStep(current, desired)` が次段を返し、大きく動けば 1 回の呼び出しで複数段でも追従する。境界ちょうどでは移らない（決定論）。起点が段でない値の場合は `quantizeZoom` の最近傍段から始める。
- **遷移 `advanceZoom`**: 指数平滑、係数 `ZOOM_TRANSITION_RATE = 8`（1/秒、カメラ位置の追従と同じ速さ）。0.25 の段差は約 36 フレーム（0.6 秒）で `ZOOM_SNAP_EPSILON = 0.002` 内へ収まり、段へ正確にスナップして静止する。以後は段の値で静止し続けるので、ドット絵のにじみは遷移の一瞬だけに限定される。
- **描画経路**: renderer の `quantizeZoom(cam.zoom)` による即時スナップを廃止し、`cam.zoom` をそのまま描画ズームにした。`Camera.zoomTo`（係数 4 の旧平滑）は `advanceZoom` に役割を譲って削除し、そのテストは `advanceZoom` のテストへ移設した。`quantizeZoom` は段キーパーの起点決定として残置。
- **眺望段の出入り**: `view.zoom`（VIEW_ZOOM または段キーパー由来の zoomTarget）が目標になる既存経路は不変。描画側の遷移が共通化されたため、眺望の開始・終了も自動的に同じ滑らかさになった。

## 計測

- テスト: 589 → **598 件**（zoom.test.ts に段キーパー 6 件・遷移 5 件を追加、camera.test.ts から zoomTo の 2 件を削除）。全スイートでは `worldgen.test.ts` の最重量 2 件が VM 高負荷時の 20 秒タイムアウトで落ちたが、変更前のベースラインでも同一 2 件が同じ落ち方をしており、単体再実行では 38/38 全通過（本変更は world/ に無関係）。tsc クリーン、build 成功（バンドル 227.84KB / gzip 122.29KB、段階 3 の 227.6KB / 122.2KB と同水準）。
- frametime（`scripts/frametime.mjs --seed=20260711 --stages`、render p50、前後各 2 回、同セッション・他処理なし）:

| 場面 | 変更前 | 変更後 |
|---|---|---|
| 開始位置 | 8.20 / 8.20 ms | 8.10 / 8.60 ms |
| 開放場所（pos=244,66） | 9.50 / 9.30 ms | 9.30 / 10.10 ms |

フレーム p50 は全 run で 16.7ms（60fps）維持。系統的な悪化なし（この日の VM は従来の報告値より全体に重く、絶対値ではなく同セッションの前後比較で判断した）。

- スクリーンショット（seed 20260711、pos=244,66、2px 間引きサンプリング差分）: 静止時の変更前 vs 変更後の差分画素は 0.5%（アニメーションのノイズのみ）で、段に落ち着いた画は不変。変更後の遷移中は、静止画との差分が wait 200ms で 39.2%、450ms で 28.4%、800ms で 15.7% と単調に縮み、中間のスケールを経由して段へ収束することを確認した（変更前は wait 250ms 時点ですでに段スケールへスナップ済みで、静止画との差分 35.0%）。

## 保留

- 「酔わないか」の最終判定は実機（親側）。即時スナップという発生源は消えたが、遷移の速さ（係数 8）の体感は実機でのみ分かる。速すぎる／遅すぎる場合は `ZOOM_TRANSITION_RATE` の 1 定数で調整できる。
- 段境界のチャタリングはヒステリシスで構造的に断ったが、実機の長距離移動での最終確認は未実施。
