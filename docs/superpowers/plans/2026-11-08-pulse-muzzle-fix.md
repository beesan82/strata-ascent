# 記録: パルスの発射位置を銃口に合わせる（「腰から出てる」修正）

ユーザー実機報告（2026-11-08）: 「パルスが腰から出てる」。計画書ではなく、本書に原因・修正・検証を記録する。
ブランチ: `fix/pulse-muzzle-origin`

## 原因（数値の根拠）

パルスのスポーン原点が、描画ポーズと無関係にプレイヤーの体の中心で固定されていた。

- 発射側: `src/main.ts` が `pulseGun.update(dt, ..., player.centerX, player.centerY, ...)` と体の中心を渡していた。ポーズ座標（原点＝体の底辺中心）に直すと中心は (0, −0.875) で、ポーズの腰 hip.y = −0.83 とほぼ同じ高さ（差 0.045 タイル）。つまり文字どおり「腰」から出ていた。
- 描画側: 銃は `calculatePlayerPose`（`src/render/playerPose.ts`）の shoulder → weaponHand → muzzle で描かれ、静止・水平照準では muzzle = (1.17, −1.62)。スポーンとの差は **前方 1.17 タイル、上方 0.745 タイル**。
- 照準方向ごとの差（スポーン → 銃口、実関数で計測）: 右 = (+1.17, −0.745)、右上 45° = (+0.90, −1.41)、真上 = (+0.23, −1.69)、真下 = (+0.23, +0.20)。スポーンは照準に全く追従していなかった。
- 歩行中はポーズ側だけ sway / bodyOffset / idleBob で動き、スポーンは不動だった点も食い違いの一部。
- 段階 2 の体の基準位置の変更が原因ではない。スポーンは当初からポーズを一切使っていなかった。

## 修正内容

- `src/render/playerPose.ts`: 純粋関数 `poseMuzzleWorld(centerX, centerY, facing, walkPhase, isWalking, aimAngle, timeSec)` を追加。描画アンカーと同じ変換（中心 + 足元オフセット + ポーズの muzzle）で銃口のワールド座標を返す。足元オフセットは定数 `PLAYER_FEET_OFFSET_TILES = 0.875`（物理ボディ高さ 1.75 の半分）として切り出し、`src/render/playerSprite.ts` のハードコード 0.875 もこの定数参照に置換し、二重管理を解消した。
- `src/main.ts`: 発射原点を体の中心から、発射方向（pulseDir）の角度でポーズ計算した銃口に変更。`isWalking` の定義は renderer の描画判定（`onGround && vx !== 0`）と同一にし、更新順序（player.update → pulse 更新 → 描画）により描画ポーズと一致する。安全点として体の中心も渡す。
- `src/entities/pulse.ts`: 純粋関数 `resolvePulseSpawn(tiles, muzzle, safe)` を追加。銃口が地形に埋まっている場合は、安全点（体の中心）へ向けて 1/16 タイル刻みで後退し、弾の箱（0.4）が地形と重ならない最初の位置から生む。安全点まで埋まっている場合は安全点を返し、従来どおり `moveBody` の埋没ガードで即消滅する（退行なし）。`PulseGun.update` の末尾に任意引数 `safeX / safeY`（既定＝銃口、後退なし）を追加。
- `src/entities/physics.ts`: 埋没判定用に `bodyOverlapsSolid` を export 追加（既存の private `collides` のラッパー）。
- パルスの速度・威力・連射間隔・射程・サイズは一切変更なし。

## 計測・検証

- テスト: 786 → **793 件・全通過**、`npx tsc --noEmit` クリーン、`npm run build` 成功。追加内訳: poseMuzzleWorld の座標固定 3 件（水平・真上・描画アンカーとの一致マトリクス）、resolvePulseSpawn と後退スポーン 4 件（空き地では銃口そのまま／壁の中の銃口は後退／天井に埋まった銃口でも後退して飛び続ける／全埋没では従来どおり即消滅）。
- スクリーンショット: `~/workspace/strata-muzzle-shots/`（`before/` = 修正前 HEAD、`after/` = 修正後。同一 seed・同一操作）。撮影スクリプトと拡大 crop・画素計測スクリプトも同梱。
  - 静止・右: 弾の芯の画素重心が画面 y=361 → 343 へ **18px 上昇**（≒0.745 タイル、ポーズ計算どおり）。拡大では修正前は弾が腰の高さの手すり線に乗り、修正後は胸の銃身の線と一致する。
  - 斜め上: 修正前は弾が胴の付け根から、修正後は肩から伸びる 45° の弾道上に乗る。
  - 歩行中・右: 歩行しながらでも弾は銃の高さの線を飛ぶ。
  - 真上: 弾列の x 重心が 640 → 646（肩オフセット +0.23 タイル ≒ 6px）。縦方向の差は弾道と重なるため静止画では読みにくく、数値と単体テストで担保した。
  - 左向き・斜め下も撮影し、拡大で弾道の出どころを確認した（左はポーズの対称性テストでも担保）。
- frametime（render p50、前後各 2 回・同セッション）: 開始地点 5.80/5.70 → 5.70/5.70ms、pos=244,66 歩行中 6.40/6.30 → 6.30/6.30ms、pos=40,60 は 5.70/5.70 → 5.60/5.70ms。合格線（+0.5ms 以内）。変更は更新側の計算のみで描画パスは不変。resolvePulseSpawn の後退探索は発射フレーム（最大 6 回/秒）かつ銃口が埋まっているときだけ走る。

## 保留

- PC のマウス照準では、描画される銃の向きはマウス方向、パルスの飛行方向は 8 方向キーという既存のずれがある（今回の対象外）。タッチ照準（実機）では描画角と発射方向が同一ベクトルから合成されるため、このずれは起きない。スポーンは発射方向側の銃口に合わせた。
- 重粒子砲の掘削原点も体の中心のまま（`fire()` の bore 原点）。ビームは半径 3 の掘削で原点の見た目の影響が小さく、ユーザーの報告対象もパルスのみのため今回は触っていない。
- 銃口の壁埋没時は「中心へ直線後退」で空きを探す。壁の角などでは弾道の初期位置が銃口−中心の直線からわずかに外れる場合があるが、壁の中で即消える退行より優先した。
