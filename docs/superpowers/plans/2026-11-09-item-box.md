# 実装計画: アイテムボックス（2026-11-09）

設計書: `docs/superpowers/specs/2026-11-09-item-box-design.md`
ブランチ: `feat/item-box`（起点 origin/master）

## Task 1: carry の拡張

- `src/core/carry.ts`: 携行から 1 個取り出す遷移（落とす用）、保管から携行へ 1 個戻す遷移（枠に空きがあるときだけ成功し、戻した分は確保済みから減る）を追加する。純粋な遷移として書き、`carry.test.ts` に追加する。

## Task 2: パネルと配線

- `index.html`: ボックスパネルの DOM とスタイル、開閉ボタン（タッチ用）を追加する。既存の字幕・ボタンのスタイルの流儀に合わせる。
- `src/main.ts`:
  - 開閉の配線（ボタン、KeyB、Esc）。開いている間は更新を止める（描画は維持）。開いた瞬間に砲の溜めを破棄する。
  - パネルの中身の描画: 携行セル（枠ぶん、1 個＝1 セル、素材の色アイコン）と保管（種別ごとの個数）。状態が変わるたびに再描画する。
  - 携行セルのタップ → その場に素材を 1 個落とす（既存の補給品ドロップの経路を使う）。
  - 保管のタップ → 休憩点にいる間だけ携行へ戻す。休憩点の内外の判定は既存の安全圏／箱の判定を使う。
- テスト: DOM に触る部分はテストせず、遷移は Task 1 の純関数で固定する。パネル表示はスクリーンショットで確認する。

## Task 3: バージョンと検証

- `MARKETING_VERSION` を 2.5 に上げる。
- 検証（Muse 側）: `npm test`、`npx tsc --noEmit`、`npm run build`。スクリーンショット（パネルを開いた状態）。frametime 前後各 2 回。

## 実装時の裁定

- 実装は Fable の 5 時間制限（Opus も同じ制限）に当たったため、Muse が直接書いた。
- パネルは index.html の静的 DOM＋main の renderItemBox で都度組み立てる（開いたときと操作のたびに再描画）。ゲーム内 Canvas の描画パスは増やしていない。
- ポーズは frame の更新ループを止める形（freezeSimulation と同じ経路に相乗り）。描画・HUD・字幕の更新は続く。
- 落とす操作は、地面の補給品プール（canAddSupply）に空きがあるときだけ成立させる。空きが無ければ携行からも減らさない（アイテムが消える経路を作らない）。
- 引き出しの可否（休憩点にいるか）は isInRestBoxNow でその場判定する（update の確保判定と同じ式）。保管チップは休憩点の外では locked 表示でタップを受けない。
- 開いた瞬間の溜め破棄は graviton.cancelCharge のみ。スティック側の発射候補は再開後の最初の update で takeFireCancel 経由に乗る既存の流れに任せた。

## 計測

- テスト: 全 999 件（carry の新規 5 件を含む）。フルスイートで worldgen の重量テスト 2 件が負荷起因のタイムアウトで落ちたが、単体再実行で 38 件全通過を確認（既知の揺れ）。
- tsc / build: 通過。
- スクリーンショット: パネルを開いた状態（空のセル 5 個、保管（なし）、注記「保管の引き出しは休憩点で」）を確認。
- frametime（render p50）: master {18.60, 8.40} / ブランチ {10.40, 10.30}。VM 負荷の揺れが大きく中央値は同水準。パネルは DOM で、閉じている間のフレーム処理は真偽値の判定 1 つだけのため、描画コストの増加はない。

## 保留

- アイテムを持った状態のパネル（セルにアイコンが入った見た目）はスクリーンショット未撮影。素材の出現率のため自動操作では引けず、遷移は単体テストで固定した。見た目は実機判定に回す。
- ボックスを開いたままスティックを離した場合の入力残りは、再開後の update で通常どおり処理される前提（実機で違和感があれば、閉じる操作で入力を一括解放する）。
