# 計画: 第 2 弾 段階 2 — ドロップ

設計書: `docs/superpowers/specs/2026-11-07-round2-design.md`（ユーザー承認済み、2026-11-07）
ブランチ: `feat/round2-stage2`
範囲: 設計の段階分けの 2 本目。**ドロップ（Walker・飛行敵）**。ボスと砲相互作用は段階 3 で扱い、本段階では実装しない（ボスの確定ドロップも段階 3）。

## Task 1: ドロップの抽選（純粋関数）

- [ ] `dropFor(seed, spawnId, killIndex, biomeId)` を純粋関数として実装する（乱数なし、ハッシュベース）。基礎確率： Walker は砲弾 25% / 回復 15%、飛行敵は砲弾 30%（回復は設計書の表に従う）。地区倍率は設計書の倍率表どおり（精錬区は砲弾 ×2、居住区画は回復 ×1.5 など）
- [ ] 検証： Vitest で確率の境界・地区倍率・決定論（同じ入力は同じ結果）を固定する

## Task 2: ドロップ実体と取得

- [ ] ドロップは 2 種（砲弾セル／回復セル）のみ。撃破位置から落下して床に静止する。寿命 60 秒、同時上限 16 個、吸着（マグネット）なし
- [ ] 取得： 接触で拾う。満タン（砲弾が上限、HP が全快）のときは拾えずに残る
- [ ] 描画は既存の描画へ相乗りし、描画パスを増やさない。2 種が色と形で判別できること
- [ ] 検証： 落下・静止・寿命・上限・満タン時の不取得をテストで固定する。撃破地点のスクリーンショットでドロップが視認できること

## 実装時の裁定

- **抽選は `src/world/drop.ts` の `dropFor(seed, spawnId, killIndex, biomeId)`**。敵種はスポーン ID の接頭辞（`w:` / `f:`）で判定し、ボス（`b:`）は対象外として常に null（確定ドロップは段階 3 の別経路）。ID 文字列は FNV-1a で整数化して `hash2(seed + 4201, idHash, killIndex)` の x スロットへ載せる。確率は 1 回の roll に対する累積閾値（砲弾 → 回復の順）で、どちらか最大 1 個を保証する。killIndex は main のセッション通算撃破カウンタ（0 始まり、撃破のたびに +1）。
- **地区倍率は設計 §3 の表どおり**（精錬区 砲弾 ×2.0、居住区画 回復 ×1.5、生体異物区 両方 ×1.2、大空洞水域 砲弾 ×1.3、他は ×1.0）を `dropProfileFor` として固定し、Vitest の分布テスト（固定 seed・4000 サンプル）で各地区の実測割合が理論値の ±3.5 ポイント以内にあることを固定した。
- **ドロップ実体は `src/entities/drop.ts` の `DropItem`**（一辺 0.5 タイル、重力落下は `moveBody`、寿命 60 秒・残り 5 秒から点滅、上限 16 個は `pushDrop` が古い順に落とす）。取得判定と「満タン時は拾えず残る」は純関数 `canPickup` に分離してテストで固定。実体側の配線（撃破検知→抽選→出現、毎フレームの落下・寿命・取得）は main.ts、描画は renderer の既存 fx 相乗り（新規パスなし）。
- **地区の判定は撃破位置のセル**で行う。`onEnemyKilled` が敵の中心座標から `biomeCellAt` → `biomeIdForCell` で引く（プレイヤーの現在セルではない）。
- **ドロップの色は 32 色パレットの実在色にした**。当初案の回復色 `#7fc46a` は量子化で金 `#caa64a` へ寄り緑と読めなかったため、砲弾 = `#8d62cb`（紫）+ 芯 `#30254c`、回復 = `#3c755f`（緑）+ 芯 `#c7d0ce` に変更。色と形（角型 / 十字）の両方で判別する方針は維持。
- **プレイヤー死亡時にドロップはリセットしない**（設計に明記が無い点の裁定）。敵実体とパルスは従来どおりリセットするが、ドロップは撃破地点に残り、寿命 60 秒で自然に消える。撃破記録が死亡で消えない方針（§4）とも整合する。
- 取得時の効果音・触覚は追加していない（設計に無いため）。拾得の反映は HUD の弾数・HP 表示のみ。

## 保留

- 実機判定（ドロップの視認性、拾いにいく動線の読み、満タンで残る挙動の体感）は親エージェント側。
- ボスと砲と敵の相互作用は段階 3 の範囲（本段階では未実装）。ボスの確定ドロップ（回復 1 + 砲弾 2）も段階 3 で、`dropFor` 経由ではなく確定配置として実装する想定。
- ドロップの吸着（マグネット）は設計どおり未実装（未決事項 3）。
