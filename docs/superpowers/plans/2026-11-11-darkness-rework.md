## 実装時の裁定

- **暗幕の式を `depthLight.curtainAlpha` へ移した。** `lighting.ts` は `document` に触るクラスで単体テストしにくく、`lighting.test.ts` は存在しない。設計の「lighting の係数を既存テストの期待値で固定する」は、純粋関数にした `curtainAlpha` を `depthLight.test.ts` で固定する形にした。描画手順（1 回のフィル）は変えていない。
- **地区の ambientLevel は 1/64 刻みにした。** 境界の混合（`blendBiomeVisuals`）は `from + (to − from) × t`、`biome.test.ts` の中点の断言は `(from + to) / 2` を `toBe` で比べる。2 桁の小数（例 0.15 と 0.31）では両者が丸めで 1 ulp ずれうるため、2 進で割り切れる値にして断言をそのまま残した。比は 0.554〜0.586 で、設計の目安（×0.5〜0.6）に収まる。地区の明るさの順は旧値と同じ（テストで固定）。
- **空の色も一緒に落ちる。** `renderer.drawSky` の基準色は `bb.ambientLevel`（補正なし）から作るので、地区の値を下げると空のフィルも暗くなる（設計 §1 の意図どおり）。遠景（`background.ts`）と超構造は `ambientColor` だけを読むので色は変わらず、暗幕が濃くなる分だけ暗く見える。
- **発光部は描画順を変えない（暗幕の後に描く対応は不要）。** `renderer.ts` の順は 空 → 遠景 → 超構造 → チャンク → プレイヤー → **暗幕（Lighting）** → 光条 → 重力子砲の演出 → 破片 → 撃破の演出 → パルス → 敵弾 → 設備 → **敵** → **ドロップ** → キャッシュ → post（グレイン・ビネット）。敵の目（ボス・歩行機）、飛行ドローンの航行灯と目、砲台の警告灯、ドロップはすべて暗幕の後に平坦な色で描かれており、暗幕の下で消えない。描画パスの追加・移動はしていない。
- **プレイヤー自身は暗幕の下のまま。** プレイヤーは暗幕の前に描くが、補助光の円（中心で暗幕の 85% を消す）の中心にいるので、暗幕 0.86 でも残りは約 0.13 に留まる。変えていない。
- **ビネット（post）は `ambient`（地区 × 深さ、囲まれは掛けない）を読み続ける。** 2.16 では敵・ドロップの視認性を変えないため室内の暗さを掛けなかったが、地区の値を下げたので `1 − ambient` は上がり、ビネットは全体にやや強くなる（画面の角の最大 0.28 × 0.6〜0.9 ≒ 0.17〜0.25、旧 0.08〜0.2 前後）。画面中央（短辺の 0.35 倍の円の中）には掛からず、敵とドロップは暗幕の上にあるので、周りとのコントラストはむしろ上がる。ビネット用に旧尺度の ambient を別に作ることはしなかった（式が二重になる）。実機で角の敵が見にくければ保留の対処をとる。
- **光条（`lightshaft.ts`）の上限 `AMBIENT_MAX = 0.8` は変えない。** 光条は「暗く開けた空間に差す大気の光」で、旧値では大空洞帯の浅い層の光溜まり・休憩点（0.7 + 0.15 / + 0.12）だけがこの上限を超えて光条が出なかった。新しい値では上限に届く場所がなくなり、そこでも開けていれば光条が出る。強さ（`darkF`）も暗いほど上がる（典型で 1 割強）。光条の加算は 1 本 α 0.1 × 強さで、暗い世界の「光は例外」に沿うと判断した。光源（光柱・塔の灯・休憩点の灯）の色と数は変えていない。
- **前室・休憩点の補正（+0.15、+0.12）は加算のまま変えない。** 地区の値が下がった分、補正は相対的に大きく効き、光溜まりと休憩点の周りは周囲より明るい「光の例外」として際立つ。スポーン直後・休憩点まわりが暗くなりすぎない配慮は、この補正と暗幕の上限、補助光の 3 つで受ける（新しい補正は足さない。スクリーンショットで確かめる）。
- **深さ・囲まれ・地区の積は暗い地区ですぐ上限に当たる。** 生体異物は層 0 の開けた場所でも暗幕 0.859 で、深さや囲まれの差がほぼ出ない。設計の「上限 0.86 で真っ黒にしない」を優先し、上限は変えていない（保留）。

## 保留

- **未検証。** このセッションではテスト・tsc・build・スクリーンショット・計測を実行していない。親側で確かめる。
- **`ambientLevel` の他の読み手の確認。** このセッションではリポジトリ全体の検索ができず、読んだ範囲（`renderer.ts`、`lighting.ts`、`post.ts`、`lightshaft.ts`、`beacon.ts`、`biome.ts`）以外で `ambientLevel` の絶対値に閾値を持つ処理（環境音など）があるかは未確認。親側で `grep -rn "ambientLevel" src` を確かめ、閾値を持つ読み手があれば旧尺度との対応を記録する。
- **スポーン地点の地区。** スポーンが最下層・生体異物のような暗い地区だと、層 0 の開けた場所でも暗幕がほぼ上限（0.84〜0.86）になる。スクリーンショット 1 で暗すぎると判定したら、上限を 0.82 前後へ下げるか、スポーン付近だけの補正（休憩点の `REST_AMBIENT` と同じ形）を検討する。
- **暗い地区での深さ・囲まれの効き。** 上の裁定どおり、暗い地区では暗幕が先に上限に当たる。「深く・囲まれるほど暗い」の勾配が出るのは大空洞帯・上層・居住区跡が中心になる。実機の判定で足りなければ、上限を地区ごとにする・暗幕の色（`darken(ambientColor, 0.4)`）を深さで暗くする、などを検討する。
- **背景の滲み（空のフィルの帯、大穴の方角の手がかり）。** 滲みは暗幕の下にあるので、暗幕が 0.22〜0.55 → 0.61〜0.86 になると見える量が大きく減る（最も暗い地区で 14% 程度）。量子化で帯が消えて方角が読めなくなるかをスクリーンショットで確かめる。消えるなら `GLOW_ALPHA` を上げる（上限 1）か、滲みを overlay 側へ移す（ただし全幅の lighter になり重い）を検討する。
- **ビネットの強まり。** 上の裁定どおり。角の敵が見にくければ、ビネットの係数を `1 − ambient` から旧尺度相当（例 `1 − min(1, ambient / 0.56)`）へ寄せる。
- **光条の出る場所の増加。** 上の裁定どおり。大空洞帯の前室で光柱と光条が重なって明るすぎるなら、`AMBIENT_MAX` を新しい尺度（0.45 前後）へ下げる。
- **最終判定は実機。** 本人の「暗がりを探索してる感じ」が正。数値はすべて開始値で、実機の判定で詰める。
