# 実装計画: 資源と武器の再設計（2026-11-09）

設計書: `docs/superpowers/specs/2026-11-09-ammo-armory-design.md`
ブランチ: `feat/ammo-armory`（起点 origin/master）

## Task 1: 弾薬の純粋モデル

- `src/core/carry.ts`: 携行種別に `shell`（砲弾）と `pulsecell`（パルス弾セル）を追加する。個数レコードの初期化と総数の数え方は種別表から導く現行の形を保つ。
- `src/core/ammo.ts` を新設する: 定数 `PULSE_SHOTS_PER_CELL = 20`。状態は装填中の残発数 `loaded` と携行（CarryState）の組で扱い、純粋な遷移として次を置く:
  - パルスの 1 発消費: loaded があれば減らす。無ければ携行の pulsecell を 1 個装填してから撃つ（装填と同時に 1 発消費）。どちらも無ければ撃てない。
  - パルスの残弾総数（loaded ＋ 携行セル × 20）。
  - 砲の 1 発消費可否: 携行の shell が 1 以上か。
- テスト: `ammo.test.ts` に消費・装填・弾切れ・残弾総数を固定する。`carry.test.ts` は新種別に合わせて更新する。

## Task 2: Graviton と発射経路の組み替え

- `src/entities/graviton.ts`: charges と自動回復（recharge）を廃止する。溜めの状態機械だけを残し、発射の可否は外から渡す。既存テストは新しい契約に合わせて書き換える。
- `src/main.ts`:
  - 砲の発射成立時に携行の shell を 1 個消費する。残弾が無ければ溜めを開始しない（溜め音・演出も出さない）。
  - パルスの発射は PulseGun の発射総数の差分で数え、発射ぶんだけ ammo の遷移を適用する。残弾が尽きたらそれ以上撃たせない（PulseGun へ渡す発射可否で止める）。
  - 取得経路: 地面の砲弾セル（drop kind `charge`）は携行の `shell` として拾う。パルス弾セルは新しい drop kind として追加し、携行の `pulsecell` として拾う。`canPickup` の判定は携行枠ベースに組み替える（満杯なら拾えず残る）。
  - 満腹度による砲の回復速度の修飾（rechargeTimeFor 等）は回復廃止に伴い撤去する。
  - 死亡時の扱いは従来どおり（携行は保持、装填中の残発数は 0 に戻す）。
  - 初期所持: パルス弾セル 2 個を携行に入れて開始する。

## Task 3: ドロップと補給の再配分

- `dropFor`（敵ドロップ）: 砲弾セルを抽選から外す。素材・回復・糧食の重みは現行を維持する（合計圧縮の再計算に注意）。
- 休憩点の初回補給: 2 個目は弾薬にする（パルス弾セルか砲弾を、既存のハッシュ流儀で決める）。
- ボス報酬: 砲弾 1 は残す（地面の砲弾セルとして出す）。

## Task 4: 武器庫エリア

- 配置: 補給キャッシュの選定（world/supply）に相乗りする別種の選定を足す。決定論（シード＋識別子のハッシュ）、地区倍率（電力区・精錬区は濃く、水域・生体異物区は薄く）、休憩点とスポーンの保護範囲はキャッシュと同じ。
- 開封: 近傍に最大 1 つ、接触で開封し、砲弾 1 ＋ パルス弾セル 2 を補給品として出す。開封済みはセッション内で復活しない。補給品プールの空きが無い間は開封しない（キャッシュと同じ）。
- 描画: キャッシュの描画に種別（通常／武器庫）を渡し、武器庫は弾薬クレートの見た目（色と形を変える。描画パスは増やさない）。

## Task 5: 箱画面の状態セクションと HUD の整理

- `index.html` / `src/main.ts` のボックス: 状態セクションを追加する（HP、満腹度バーと糧食数、パルスの残弾総数、砲弾数、階層と高度、最深記録、確保済み総数）。開いたときと操作のたびに再描画する現行の経路に乗せる。携行セルのアイコンに shell（紫の弾）と pulsecell（小さなセルの束）の見た目を足す。
- HUD: 文字行の組み立て（updateHud の状態表示）を撤去し、ボスの HP バーだけを出す。最深記録の保存など表示以外の副作用は updateHud から切り離して残す。

## Task 6: ボタンのアイコン化

- `src/core/touch.ts` と `index.html`: ボタンのラベルを文字から記号にする（跳 = ↑、望 = ◎、箱 = ▦、武器 = パルスは » 、砲は ● を目安に、フォントで描ける字形を選ぶ）。武器ボタンのモード明示色（紫）は維持し、ラベル同期（syncWeaponUi）は記号の切り替えに読み替える。

## Task 7: バージョンと検証

- `MARKETING_VERSION` を 2.6 に上げる。
- 検証（Muse 側）: `npm test`、`npx tsc --noEmit`、`npm run build`。スクリーンショット（箱画面、タッチのアイコンボタン、武器庫）。frametime 前後各 2 回。

## 実装時の裁定

- **弾薬の置き場**: 弾薬は `core/carry.ts` の携行種別 `shell` / `pulsecell` として素材と同じ枠（5）を共有する。種別表 `CARRY_KIND_INFO`（表示名と「弾薬か」）を足し、個数レコードの初期化・総数は従来どおり `CARRY_KINDS` から導く。消費と装填は `core/ammo.ts` の純粋な遷移（`firePulse` / `fireCannon` / `canFire*` / `pulseShotsTotal`）に寄せ、`ammo.test.ts` で固定した。パルスの装填中の残発数 `loaded` は携行の外（main の `pulseLoaded`）に持ち、死亡で 0 に戻す。
- **自動確保は弾薬を除く**: 休憩点の箱に入ったときの `secureCarry` は弾薬以外（素材）だけを確保済みへ移す。弾薬まで自動で保管に入ると、休憩点に入るたびに武器が空になり、箱を開けて戻さないと戦えない「見えない罠」になるため。弾薬を保管に置きたいときは、休憩点でアイテムボックスの携行セルをタップすると保管へ入る（新しい遷移 `storeCarry`。休憩点の外では従来どおり「その場に落とす」）。引き出しは従来どおり保管チップのタップ。
- **確保は「入った瞬間」だけ**: 従来は箱の中にいる間 6 フレームごとに `secureCarry` が走り、箱で引き出した素材が次の判定で再確保されていた（item-box 段階の未検証部分）。`prevInRestBox` を足し、箱の外→中の遷移でだけ確保するようにした。復活点が箱の中でも、死亡前が箱の外なら復活直後に 1 回だけ確保される（従来と同じ結果）。
- **Graviton**: `charges` / `MAX_CHARGES` / `RECHARGE_TIME` / `rechargeTimeFor` を廃止し、溜めの状態機械だけを残した。`update(dt, held, canFire, fire)` の `canFire` は main が `canFireCannon(carry)` で渡す。`canFire` が偽なら溜めが始まらず `chargeRatio` は 0 のまま（溜め音・グロー・左スティック拘束も出ない）。砲弾の消費は `fire()` の先頭。満腹度による回復速度の修飾（サバイバル段階 2 §4）は回復ごと撤去した。砲の回復音 `rechargeTick` はパルス弾セルの装填の合図に充て直した。
- **パルスの発射可否**: `PulseGun` は弾薬を知らない。main が `firing` に `canFirePulse(pulseLoaded, carry)` を掛け、発射総数の差分ぶんだけ `firePulse` を適用する。1 update で増える発射数は高々 1 なので遷移の適用順に曖昧さはない。
- **敵ドロップ**: `world/drop.ts` から砲弾の区間を外し、抽選対象を `EnemyDropKind = heal | ration | material` にした。回復・糧食・素材の基礎重みと地区倍率は現行値のまま。砲弾ぶんは他へ配分しない（敵を倒す資源価値を下げ、場所を主経路にする設計意図）。結果として合計が上限 0.62 に届く組み合わせは無くなり圧縮は起きないが、仕組みは残した。砲弾の区間が先頭にあったため、同じロールでも抽選結果は従来から変わる（既存テストは新しい分布で書き直した）。
- **休憩点の備蓄**: 2 個目は弾薬（`restStockSecondFor` → `charge` か `pulsecell`）。地区別の砲弾率 `REST_STOCK_SHELL_RATE`（電力・精錬・水域 0.6、寒鋼・廃棄 0.4、居住・生体 0.3）をハッシュで引く。旧表の「回復／糧食」は出なくなる（糧食は 1 個目で常に出るため）。ボス報酬の砲弾 1（`bossRewardFor`）は変更なし。
- **武器庫の選定**: `chooseArmories` は `chooseSupplyCaches` と同じ床ラン・保護点・大広間除外・argmin 方式で、塩（4304）と密度だけが違う。密度は `ARMORY_THRESHOLD = 0.3 × ARMORY_MUL[地区]`（電力・精錬 1.6、寒鋼・廃棄 1.0、居住 0.8、水域・生体 0.5）。キャッシュと同じ場所に重ならないよう、main は選定済みキャッシュの位置を r=2 の保護点として武器庫の選定に加える。ID は `a:` 接頭辞で、開封済みの差し引きはキャッシュと同じ「選定後の減算」。
- **武器庫の開封**: 接触判定はキャッシュと同じ式（幅だけ 0.55 に広げた）。補給品プールに 3 個ぶんの空きがあるときだけ開封し、`ARMORY_CONTENTS = [pulsecell, charge, pulsecell]` を 0.7 タイル間隔で並べる。開封音はキャッシュと共用。
- **描画**: 武器庫はキャッシュの fx 配列に `armory: true` を立てて渡し、同じループ内で分岐する（描画パスは増やさない）。見た目は鋼灰 `#51728d` の角張ったクレート＋暗紫 `#30254c` の底帯＋紫 `#8d62cb` の帯（砲弾セルの紫で弾薬の箱と読ませる）。パルス弾セルのドロップは淡色 `#c7d0ce` の横長＋紫の縦筋 2 本。いずれもパレット実在色。
- **HUD**: `updateHud` から文字行の組み立てを全て外し、到達階層の更新・最深記録の保存・節目／新記録の字幕（表示以外の副作用）とボスの HP バーだけを残した。文字列が変わらないフレームでは DOM に触らない。系統ラベル（`SYSTEM_LABEL` / `regionAt`）と seed の表示は設計書の状態項目に無いので撤去した。
- **箱画面の状態セクション**: HP、満腹度（ASCII ゲージ＋数値、low は金色・危険域は赤）、糧食、現在の武器、パルス残弾総数（装填＋セル）、砲弾数、階層と高度、最深記録、確保済み総数。携行セルは種別ごとに並べ、素材／砲弾／パルス弾セルの CSS アイコンで描き分ける。保管チップのラベルは種別表の表示名。
- **ボタンの記号**: 跳 = `↑`（U+2191）、望 = `◎`（U+25CE）、箱 = `▦`（U+25A6）、武器 = パルス `»`（U+00BB）／砲 `●`（U+25CF）。いずれも Emoji Presentation を持たない字形で、絵文字化する `⬆` `⚫` は避けた。記号は `BUTTON_GLYPH` / `weaponGlyph` として `core/touch.ts` に置き、ボタンに `aria-label` で日本語名を残した。`.tbtn` は inline-flex で中央寄せ、記号 1 文字に合わせて font-size を上げた。
- **取得音**: `pulsecell` の取得は砲弾と同じサンプルを高めのレート（1.25）で鳴らし、合成音の既定（`PICKUP_NOTES.pulsecell`）も足した。

## 計測

- テスト: 全 1025 件通過（新規の ammo・武器庫・携行種別の拡張ぶんを含む）。検証側で supply.test.ts の分布テストに pulsecell の型（キャッシュからは出ない＝0）を足して tsc を通した。
- tsc / build: 通過。
- スクリーンショット: 箱画面（状態セクション＋パルス弾セル 2 個のセル表示）、モバイル幅でアイコン化したボタン（» ↑ ▦ ◎ の描画）を確認。武器庫の実物は配置が探索依存のため自動操作では引けず未撮影（選定の決定論は単体テストで固定）。
- frametime（render p50）: master {5.70, 6.30} / ブランチ {5.70, 6.80}。中央値差 +0.25ms 程度で合格線内。

## 保留

- README の操作表（タッチ操作の行）は item-box 以前から現行の二本スティック構成と合っておらず、今回も触っていない。記号ボタンへの更新と合わせて別途直す。
- 記号の見え方（`▦` `◎` の字幅・太さ）は端末の等幅フォントに依存する。iOS 実機でのスクリーンショットで確認し、潰れるようなら `▤` や `◯` へ差し替える。
- 休憩点の箱に立ったまま弾薬を保管へ入れた直後にその場で再度拾う経路は無い（保管チップのタップで戻す）。箱で「保管へ」と「落とす」が場所で切り替わる挙動は、実機で迷うようなら携行セルの長押しなどに分ける。
- 武器庫の密度（窓あたり 15〜48%）は机上の値。実プレイで弾薬が足りない／余るなら `ARMORY_THRESHOLD` と `ARMORY_MUL` だけで調整できる。
- パルスの装填中残発数は死亡で 0 に戻る（計画どおり）。携行セルが 0 のまま死ぬと最大 19 発を失う。厳しすぎれば装填中を携行へ戻す遷移を足す。
- 敵ドロップから砲弾を外したぶん、ドロップ全体の発生率が下がった（Walker で 58% → 36%）。糧食・回復の供給感が変わって見えるなら、ここで重みを見直す。
