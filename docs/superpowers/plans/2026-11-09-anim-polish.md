## 実装時の裁定

- **ポーズ計算の引数**: `calculatePlayerPose` / `poseMuzzleWorld` / `drawPlayer` は既存の省略可能引数 `hanging` をそのまま残し、その後ろに小さな構造体 `PoseMotion`（onLadder, climbPhase, onGround, vy, landT, landVy, climbUpT）を 1 つ足した。6 つの新入力を位置引数で足すと 12 引数になるため。省略時の既定 `GROUNDED_MOTION`（接地・梯子外・タイマなし）で従来のポーズ計算と完全に同一になる（既存テストはすべて引数追加なしで通る前提）。`poseMotionOf(player)` で renderer と main の発射原点が同じ値を使う。
- **main.ts も触った**: 計画は playerSprite / renderer のみだったが、発射原点 `poseMuzzleWorld` を main が呼んでいる。空中・梯子で描画の銃口だけ動いて弾の原点が地上ポーズのまま、という不整合を避けるため main にも `poseMotionOf(player)` を渡した（1 行）。
- **climbPhase の進み**: 縦移動距離 0.5 タイルで π（`CLIMB_RUNG_TILES = 0.5`）。歩行の「1 タイル = π」とは違えて、梯子の段の音（`audio/params.LADDER_RUNG_STEP = 0.5`）と足の踏み替えが同期するようにした。
- **climbPhase は梯子を離れたら 0 に戻す**（保持しない）。walkPhase は保持だが、梯子は main の `ladderTravel` が離脱で 0 に戻す前例に揃えた。静止中の梯子ポーズを「位相 0 の昇降ポーズ」と同じ形にしてあるので、昇り始めでポーズが飛ばない。昇降を途中で止めた瞬間は歩行と同じく静止ポーズへ切り替わる（既存の歩行停止と同じ割り切り）。
- **梯子ポーズの条件は「梯子上かつ非接地」**。梯子上では vy = 0 のとき moveBody が下方向の衝突を起こさず `onGround` が立たないため、床面で梯子の列に立っている／横切っているだけでしがみつきポーズになってしまう。Player に描画専用の `feetSupported`（足元 1/16 タイル下に固体があるか）を足し、`onLadderNow = vy ≠ 0 || !feetSupported` とした。物理の `onGround` には書き戻さない。
- **タイミング定数の置き場**: `LAND_POSE_TIME`（0.1 s）と `CLIMB_UP_POSE_TIME`（0.16 s）はタイマを持つ `entities/player.ts` で定義して export し、`render/playerPose.ts` が import して残り時間を正規化する（二重定義を避ける）。entities → render の逆向き依存は作らない。
- **着地の沈みの閾値**: 落下速度 5 未満（着地音の `LAND_MIN_VY` と同じ）では沈まない。これで梯子を降りて床に着く（vy = 4）、梯子の列を横切って `onGround` が一瞬落ちて戻る（vy ≈ 0.5）といった微小な「着地」で沈まない。5 で上限の 30 %、25（MAX_FALL）で上限 0.22 タイル。残り時間に比例して線形に戻る。
- **空中ポーズの補間**: `tanh(vy / 7.5)` を −1..1 の相にして、上昇量 = max(0, −t)、落下量 = max(0, t) で係数を混ぜる。閾値は使わない。空中・昇降中は体が実際に動くので呼吸の bob を乗せない。
- **よじ登り復帰は「上書き」ではなく「重ね」**: 土台のポーズ（地上・空中・梯子）と屈みポーズを `climbUpCrouch`（経過 40 % まで 1、残りで smoothstep で 0）で線形に混ぜる。復帰中に跳んでも空中ポーズへ屈みが溶けていくので飛ばない。計画の優先順位「掴まり ＞ よじ登り復帰 ＞ 梯子 ＞ 空中 ＞ 着地 ＞ 歩行」は、掴まりだけが完全上書きで、よじ登り復帰は最上位の重ね、着地は地上だけの重ね、と読み替えた。
- **梯子・屈みの銃口**: 掴まりの前例どおり肩→手の延長に置き、発射原点との整合は問わない（空中は照準追従を維持）。
- **よじ登りの屈みの手の位置**: 「縁に手をつく」を、向いている側（壁の上面）に両手をついた形にした。実際の縁は登った後は踵側にあるが、後ろ手は横向きの人影では読めない。

## 計測

検証担当（Muse）が 2026-11-09 に実施:

- テスト: 973 件全通過（76 ファイル）。`npx tsc --noEmit` 通過、`npm run build` 成功。
- 検証側の修正 1 件: 着地タイマのテストが 1 件落ちた。原因は実装の不具合ではなく、着地直後の数フレームに接地が点滅し落下速度 1 前後の小さな再接地が起きる物理側の既存挙動で、ポーズが再点火し続けていた。対策として、着地ポーズを数える下限 `LAND_MIN_VY = 3` を player.ts に追加した（沈み込みが見え始める速度 5 より下、再接地の 1 前後より上）。これで本物の着地（落下速度は 5 以上）だけがポーズを出し、テストも無変更で通る。
- frametime（render p50、seed 20260711、交互計測）: master {6.20, 5.70} / 本ブランチ {5.80, 5.60}。悪化なし。
- スクリーンショット: ジャンプ上昇中（脚を畳む）と落下中（脚を伸ばす）の姿勢の違いは確認できた。梯子昇降の途中は、自動操作では昇り切ってしまうか梯子に届かず、決定的な 1 枚が撮れなかった。梯子ポーズの形状（位相で腕と脚が交互）は単体テストで固定済みで、最終の見た目は実機判定に回す。

## 保留

- ジャンプ前の予備動作（しゃがみ溜め）: 設計どおり見送り。入力バッファ／コヨーテの感触に触るため。
- 梯子の昇降を途中で止めた瞬間、位相の途中から静止ポーズへ切り替わる（歩行停止と同じ割り切り）。気になるなら短いブレンドを足す。
- 床面で梯子の列を横切るとき、`onGround` が立たないため歩行 gait が止まり静止ポーズのまま滑る（従来からの挙動。今回の `feetSupported` で梯子ポーズにはならなくした）。直すなら `isWalking` の判定を renderer / main / audio の 3 箇所で揃えて変える必要がある。
- 梯子上で撃つと弾の原点が段を掴む手から出る（掴まりと同じ割り切り）。
- スクリーンショット（梯子昇降途中・上昇・落下）と frametime の前後計測は検証担当。render p50 の悪化は +0.5 ms 以内が基準。ポーズ計算は 1 フレームに 2 回（描画・発射原点）の純粋関数で、描画パスは増えていない。
