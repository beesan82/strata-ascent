# 実装メモ: 箱タップで照準が固着するバグの修正（2.9）（2026-11-09）

ブランチ: `fix/box-aim-poison`（起点 origin/master）

## 本人の特定

2.6〜2.8 で直らなかった「向きが変わらない・背中から発射」の件。本人が「箱を開くと発生する」と発生条件を特定した。

## 真因

`Input` が `window` の `mousemove` を無条件に受け、`mouseSeen` を立てていた。タッチ端末では、preventDefault されていない要素（アイテムボックスのパネル・セル・×ボタン等）をタップするとブラウザが互換マウスイベント（mousemove 等）を合成発火する。そのため箱を操作した瞬間に「マウスがその座標にある」ことになり、以降ずっと:

- 描画照準（銃・コーン）はスティックではなく、箱をタップした画面上部の座標へ固着する。
- パルスはスティック方向へ飛ぶので、銃と発射方向が食い違い「背中から発射」になる。
- 重粒子砲の発射方向（renderer.aimAngle）も固着点の方向になる。
- `mouseSeen` は一度立つと戻らないため、セッション中ずっと直らない。

スティックと操作ボタンは pointerdown で preventDefault しているため、通常プレイでは発火せず、箱の操作でだけ踏む。

## 再現と修正

- 再現（修正前）: エミュレーションで 箱を開く→×で閉じる→左照準、の手順を踏むと、銃が×ボタンのあった右上方向へ固着し、パルスだけ左へ飛ぶことを撮影で確認した。
- 修正（`src/core/input.ts`）: `mousemove` リスナを廃し、`pointermove` で `pointerType === 'mouse'` のものだけを受ける。タッチ・ペン由来の移動と合成イベントは照準に入らない。PC のマウス照準は pointermove でも従来どおり動く。
- 回帰テスト（`src/core/input.test.ts`）: mouse/touch/pen の pointermove で mouseSeen の立ち方を固定し、`mousemove` リスナ自体が無いことも assert する。
- 修正後の同じ手順で、銃が左を向きパルスと一致することを撮影で確認した。

## 検証

- テスト 1030 件（input の回帰テスト 1 件追加）。フルスイートで worldgen の重量テスト 1 件が負荷起因で落ちたが単体再実行 38 件全通過（既知の揺れ）。tsc・build 通過。
- 再現撮影（修正前）: 箱→×で閉→左照準で、銃が×のあった右上へ固着しパルスだけ左へ飛ぶ。修正後の同じ手順では銃も左を向きパルスと一致。
- 描画変更なし（入力リスナのみ）のため frametime 計測は省略。
- MARKETING_VERSION 2.9。
