# 実装計画: 段階1 — 弾の向き＋チャージ演出のリアル化（2026-11-09）

設計書: `docs/superpowers/specs/2026-11-09-fx-stage1-design.md`
ブランチ: `feat/fx-stage1`（起点 origin/master = a1ca0ba）

## Task 1: 弾の向き（純粋関数＋描画）

- `src/render/shotShape.ts`（新規）: `shotShape(dx, dy, ppt)` が `{ angle, outerLen, outerWid, coreLen, coreWid }` を返す純粋関数。長さ・太さは現行の定数（外帯 0.62/0.26、芯 0.44/0.13 タイル相当）を踏襲。速度ゼロは angle=0。
- `src/render/shotShape.test.ts`: 水平・垂直・45°・ゼロベクトル・長さの単調性を固定。
- `src/render/renderer.ts`: pulses と shots の描画を、現行の横/縦2分岐から `shotShape` の角度で `translate/rotate` して描く形に置き換える。色・2層構造は現行踏襲（パルス=鋼/白、敵弾=錆/金）。fx パスへの相乗りは維持。

## Task 2: チャージ演出の作り替え（in-buffer）

- `src/render/beam.ts` の `drawCharge` を作り替える。要素:
  - 収束パーティクル: 個数・速度は ratio 比例。配置は決定論ハッシュ（既存の debrisFragments と同じ流儀、時間は引数で受ける）。
  - コア: 放射グラデーションの球（白→金→透明）。四角は廃止。
  - 電弧: ratio >= 0.6 で折れ線放電を数本。時間量子化ハッシュで形を変える。
  - 完了リング: ratio >= 1 の間、経過時間で拡大するリング。
- 純粋部分（パーティクルの位置列・電弧の頂点列・リング半径）は `src/render/beamShape.ts` に寄せて Vitest で固定する（既存の chargeSegment 等は置き換え、テストも追随させる）。
- fx への配線: `chargeFullT`（満タン経過秒）を `FxState` 相当の型と main 側のチャージ状態から追加する。既存の `chargeRatio` の出所を追い、満タン継続時間を数える。

## Task 3: グローオーバーレイ（present 後）

- renderer の present 完了後に、表示解像度で銃口位置へ放射グラデーションのグローを `lighter` で1枚重ねる。半径・不透明度は chargeRatio 連動。定数 `CHARGE_GLOW_OVERLAY`（true）で無効化可能にする。
- 銃口の表示座標は、既存のカメラ・ズーム・present の拡大率から求める（新規の座標系は作らない）。

## Task 4: バージョンと検証

- `ios/App/App.xcodeproj/project.pbxproj` の `MARKETING_VERSION` を 2.1 に上げる（2箇所ある場合は両方）。
- 検証（Muse 側で実施）: `npm test`、`npx tsc --noEmit`、`npm run build`。
- スクリーンショット前後比較: 斜め射撃（照準を斜めにして発射した状態）、チャージ 0.5、チャージ 1.0。
- frametime: `node scripts/frametime.mjs --seed=20260711 --stages` を前後各2回。render p50 の悪化が +0.5ms を超えたらグローオーバーレイを外し（定数を false）、その裁定を本計画の末尾に記録する。

## 実装時の裁定

- **弾の軸合わせは回転なしで描く**: `shotShape` は角度に加えて `axis`（'h' / 'v' / 'diag'）を返し、0・±π/2・±π に一致する向き（8 方向入力の横縦、砲台の水平・垂直射撃）は従来どおり整数 px に丸めた矩形で描く。回転描画は斜めだけに限る。これで横縦の弾は従来と画素一致（差分 0）のまま、斜めだけが変わる。回転描画の矩形は半端な px 位置になり縁がアンチエイリアスされるが、量子化で階段状に落ちるので問題にしない。
- **弾の寸法は従来定数を踏襲**: 外帯 0.62/0.26、芯 0.44/0.13 タイル相当（ズーム 1 で外帯 8×3 px、芯 6×2 px）。テストで固定した。
- **溜め演出の時刻**: `drawGravitonEffects` に `timeSec` 引数を足し、renderer の `render` が受け取っている `timeSec`（main の simTime）をそのまま渡す。freeze 時は simTime が止まるのでパーティクルも止まる（スクリーンショットでの再現性に都合がよい）。
- **ばらつきは `hash2` の決定論ハッシュ**: パーティクルは固定種（`CHARGE_HASH_KEY`）と番号 i、電弧は `floor(timeSec × 18)` の tick と番号 j を種にする。`Math.random` は使わない。
- **in-buffer では放射グラデーションを球コアの 1 枚だけ使う**。段階 3 で廃止していたが、本段階の設計（§2-2）が明示的に球コアに求めるため復活させた。加算合成（lighter）は in-buffer では使わず、present 後のグローオーバーレイだけに限定する。renderer.test の「放射グラデーション 0 枚」の固定は「1 枚」に改めた。
- **コアの透明端は rgba**: グラデーションの外縁を透明にするため、パレット色を `hexWithAlpha` で rgba 化した色止めを使う。中間色は量子化で帯になるが、設計が許容している。
- **溜め演出の寸法は px 固定（ppt 非連動）**: 従来の `drawCharge` と同じく内部バッファ px の定数で描く。眺望ズーム（0.35）では相対的に大きく見えるが従来と同じ振る舞いで、段階の範囲外とした。
- **完了リングは `chargeRing(ratio, fullT)`**: `ratio < 1` なら必ず null を返す（main が `chargeFullT` を 0 に戻す前のフレームでも、満タン未満でリングが出ることはない）。寿命は 0.25 秒。
- **`chargeFullT` の出所**: `Graviton` の状態機械には触らず、main の `update` で `graviton.update` の直後に `chargeRatio >= 1` の間だけ dt を積み、それ以外は 0 に戻す。GravitonFx では省略可（既定 0）にして既存テストの部分オブジェクトを壊さない。
- **グローオーバーレイの座標**: 銃口の内部バッファ座標（`visualAnchors.muzzle`）に押しの平行移動量（`pushX/pushY`。従来は ctx.translate に直接渡していた値を変数に取り出した）を足し、present の余白（presentX/presentY）と整数倍率 scale を掛けて画面座標にする。新しい座標系は作らない。
- **グローは `CHARGE_GLOW_OVERLAY`（renderer.ts、true）で無効化できる**。計測で render p50 の悪化が +0.5ms を超えたら false にする（計測は検証担当）。

## 計測

検証担当（Muse）が 2026-11-09 に実施:

- テスト: 923 件全通過（76 ファイル）。初回実装時 917 件 → 電弧/リング差し戻し後に 923 件。Vitest の "Unhandled Error" が 1 件出るが中身は worker の RPC タイムアウト（onTaskUpdate）で、VM 高負荷時の基盤側の揺れ。テスト自体の失敗ではない。
- `npx tsc --noEmit` 通過、`npm run build` 成功。
- スクリーンショット（Playwright、seed=20260711）:
  - 斜め射撃（PC のキー斜め＝右上＋KeyJ）: 弾が進行方向に傾いた細長い 2 層形状で描かれることを確認。なお PC のパルス照準はマウスでなくキー 8 方向（pulseAimDir）が正であり、検証手順の最初の取り違えは手順側の問題でコードの問題ではなかった。
  - チャージ: コアのグラデーション球＋収束パーティクル＋オーバーレイの光暈は良好。初版の完了リング（最大半径 25px の細線）と電弧（極座標の滑らかな歩行）はそれぞれ「泡の輪」「リボンのうねり」に見えたため差し戻し、リングは最大半径 13px・TTL 0.18 秒・2 重ストロークの柔らかい帯へ、電弧は主方向＋垂直ジッターの稲妻型（全長はコア半径＋10px 以内）へ作り替えて再撮影し、放電らしい見た目になったことを確認した。
- frametime（`scripts/frametime.mjs --seed=20260711 --stages`、render p50）: master {5.80, 6.00, 6.20} 中央値 6.00ms / 本ブランチ {6.50, 6.10, 6.00} 中央値 6.10ms。交互計測のペアでも master 6.20 に対しブランチ 6.00。差は +0.1ms 程度で計測ノイズの範囲。p95 は VM の並行負荷で両者とも大きく振れた。
- **グローオーバーレイの裁定: 採用（CHARGE_GLOW_OVERLAY = true のまま）**。既定シナリオ（溜めなし）では追加描画自体が発生せず、render p50 の悪化も基準 +0.5ms 以内。溜め中のみの追加は放射グラデーション 1 枚に限られる。

## 保留

- **計測・スクリーンショット未実施**: 実装担当の環境ではシェルを走らせていないため、`npm test` / `npx tsc --noEmit` / `npm run build`、前後スクリーンショット、frametime は未検証。検証担当が実施し、結果を「計測」に書く。
- **グローの採否**: `scripts/frametime.mjs --seed=20260711 --stages` の既定（溜めなし）ではグローは描かれないので、溜め中の負荷は `--press=` でチャージを保持した状態の計測が必要。悪化が +0.5ms を超えるなら `CHARGE_GLOW_OVERLAY = false`。
- **斜め弾のスクリーンショット**: 受け入れ基準の「45° 付近の弾」は、斜め入力を保持して撃った状態を撮る必要がある（`scripts/screenshot.mjs` に押下中キーの指定があるか未確認）。無ければ `?freeze` 中の弾の静止は撮れないので、検証担当に手順の追加を委ねる。
- **溜め演出の ppt 連動**: 眺望ズーム時のサイズ感は段階 2 以降で必要なら見直す。
- **電弧の線描画（stroke）の負荷**: 1 px の折れ線を最大 5 本、完了リングは arc の stroke 1 回。CPU キャンバスでは軽いはずだが、量子化後の見え方（1 px 線が量子化でちぎれる可能性）はスクリーンショットで確認する。必要なら線幅 2 か矩形の連なりに置き換える。
