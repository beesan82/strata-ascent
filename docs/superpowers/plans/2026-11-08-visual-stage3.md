# 計画: 見た目大幅改善 段階 3 — ビームと演出

設計書: `docs/superpowers/specs/2026-11-08-visual-overhaul-design.md`（ユーザー承認済み、2026-11-08）
ブランチ: `feat/visual-stage3`
範囲: 設計の段階 3 のみ。**ビームと演出の作り直し**。地形（段階 1）とプレイヤー・歩行（段階 2）は完了済みで触らない。

診断の要点（設計書より）: ビームの放射グラデーション＋`lighter` 加算は量子化された硬いピクセル世界と文法が違い、バンディングして浮く。色（白青）も世界のパレットと無接続。太さ一定・残光 0.18 秒・痕跡なしで、「地形を 300 タイル貫く一手」の質量表現がほぼない。

## Task 1: ビームの作り直し

- [ ] 放射グラデーションと加算合成を廃止し、パレット色の階段状の帯で構成する。色は設計の未決事項 4 の推奨案（芯は白のまま、外帯だけ錆・金の熱色）を初期値に採用する
- [ ] 太さが時間で痩せる減衰、掘削縁への熱色の残光（再焼き込みへの相乗り）、決定論の破片を入れる
- [ ] シェイクは毎フレームのランダムな震えから単発の「押し」へ変える
- [ ] 砲の数値・判定（BORE 定数、`beamHit`、ダメージ）は一切変えない。演出だけの変更である
- [ ] 検証： 発射シーケンスの連続フレームで、帯の構成・減衰・残光・破片を確認する

## Task 2: 弾と敵の演出の文法統一

- [ ] パルスの弾と敵の見た目を、ビームと同じ面構成の文法（パレット色の階段・グラデーションなし）に揃える
- [ ] 検証： 発射・被弾の場面のスクリーンショットで統一感を確認する

## Task 3: 仕上げ

- [ ] `npm test` / `npx tsc --noEmit` / `npm run build` 全通過（worldgen.test.ts の最重量テストは VM 高負荷時のタイムアウト揺れあり。単体再実行と変更前ベースラインとの比較で切り分けること）
- [ ] frametime は render p50 の悪化 +0.5ms 以内（前後各 2 回・同セッション比較）
- [ ] 計画末尾に「実装時の裁定」「計測」「保留」を追記（チェックボックスは更新しない）
- [ ] Pages 再デプロイ + Codemagic ビルド（TestFlight 配信）は親エージェント側で実施

## 実装時の裁定

- **ビームの帯構成は純粋関数 `beamBands`（`src/render/beamShape.ts`）で固定**（Task 1）。外帯＝錆 #9a6d32（alpha 最大 0.38、幅最大 2.8 タイル、寿命の 8 割で消滅）→熱帯＝金 #caa64a（寿命の前半のみ）→中帯＝明るい鋼 #51728d →芯＝白 #c7d0ce（最後まで残る）。設計 §8-④ の推奨（芯は白、外帯だけ熱色）を初期値として採用。色は全てパレット実在色で、テストで `PIXEL_PALETTE` への所属を固定した。太さと明度（alpha）の両方が痩せる減衰。
- **残光の寿命 BEAM_TTL は 0.18 → 0.30 秒へ延長**（Task 1、main.ts の演出定数）。「太さと明度が痩せていく減衰」を 0.18 秒では読み切れないため。BORE 定数・beamHit・ダメージ・チャージ・再装填には触っていない（検証：標準場面の差分 0 画素、掘削の形は不変）。
- **銃口フラッシュは矩形の閃光に置換**：金の外形＋白の芯の短い矩形が寿命の前半だけ出て縮む（`muzzleFlash`）。放射グラデーションは廃止。
- **溜めの表現**：放射グラデーションの球を廃止し、銃口へ収束する 6 本の短い帯＋中心の芯に置換。色段は鋼→錆→金（`chargeColor`）、完了手前で芯が白になる。設計の「武器そのものの発光段」は、プレイヤー描画（段階 2 の範囲）に触らないため銃口の芯の色段へ寄せた。
- **シェイクは単発の「押し」に置換**（Task 1）：発射方向と逆向きへ最大 6px（画面座標）を 0.1 秒で線形減衰。renderer の Math.random は撤去され、描画側の Math.random 例外は無くなった（post のグレイン生成と audio のノイズは従来どおり対象外）。押しの寿命管理は main の `beamPush`（PUSH_TTL=0.1）で、強さ比 t を fx.push として渡す。
- **掘削縁の熱色は ChunkBaker の期限管理で焼き込みに相乗り**（Task 1）：`invalidateBored` が再焼き込み対象へ一律に期限（直近フレーム時刻 + `HEAT_SECONDS = 6` 秒）を刻み（`markHot`）、bake は期限内だけ `hotEdges`（`src/render/hotedge.ts`、純粋関数）の面へ錆の帯（深さ 0.22 タイル、alpha 0.5）＋金の際線（1px、alpha 0.9）を描く。冷えるときは `expireHot` が期限切れチャンクを 1 回だけ無効化して通常の縁へ戻す（毎フレームの再焼き込みはしない）。クレーター判定は「破壊済み かつ 元地形が空気でない」で craterCells と同じ意味論。隣接チャンクのクレーターにも面する（グリッドは周囲 1 セル込み）。
- **破片は発生点方式**（Task 1）：main の `fire()` が破壊適用前にレイキャスト（0.25 タイル刻み、`peekTileAt` で未生成は生成しない）して掘削点を取り、命中した敵・ボスの中心にも置く。形と配置は `debrisFragments`（発射 key・角度・経過時間だけから決まる決定論、1 点 10 個、寿命 0.32 秒、大半は発射の逆側へ吹き出す）。発生点は最大 24 件で打ち切る。
- **パルスと敵の色はパレット実在色へ寄せた**（Task 2）：従来色は量子化で実質同じ色に寄っていたことを最近傍計算で確認したうえで明示した（歩行敵 #8a4b52→錆 #9a6d32、飛行敵 #7fa3c0→鋼 #51728d、ボス各相・フラッシュ #f2d7d7→#c7d0ce 等）。例外は飛行敵の上帯のみ #2e3d4a（実効 #192633）→ #16202b と 1 段暗くした。パルスは外帯 #51728d（0.62×0.26 タイル）＋芯 #c7d0ce（0.44×0.13）の 2 層。歩行敵は錆の胴＋#3d2618 の足元＋金の目、飛行敵は鋼の胴＋暗い上帯＋白の目（フラッシュ時は目を反転）。ドロップとキャッシュは設計どおり触らない。
- **ボスの継ぎ目の alpha は 0.9**（Task 2）：当初 0.55 で実装したら、淡色の胴の上で量子化ディザが破線状に割れた（実画面で確認）。HARD 板の継ぎ目（0.9）に合わせて実色へ寄せた。
- **音（設計 §5.3）の確認結果**：音響エンジンに発射音・破砕音そのものが存在しない（環境音のみ）ことを確認した。新規作成は設計 §7 の対象外なので本段階では扱わない。
- **`renderer.test.ts` の drawGravitonEffects テストは新契約へ書き換え**：放射グラデーション不使用・加算合成不使用・溜めとビームが銃口を原点に矩形で描かれることを固定する。

## 保留

- 歩行敵・飛行敵の新しい顔（目の灯を含む）は実画面で捉えられなかった（今回の検証シーンでは画面内に出なかった）。ボスとパルス・ビームで文法と色の出方は確認済みで、歩行・飛行の色は量子化後の実効色が従来と一致することを計算で担保したが、目の灯の見え方は実機判定待ち。
- 熱色の継続 6 秒と錆帯の濃さ（alpha 0.5・深さ 0.22 タイル）、押しの強さ（6px・0.1 秒）、帯の太さの初期値はすべて実機判定待ち。スクリーンショットでは熱色はかなり明確に読めるが、実機の小画面での強さは未確認。
- 破片は掘削点の 1 点（中心レイの初回接触）から出す形にした。半径 3 タイルの掘削面全体から出す形は採っていない（発生点の意味がぼやけるため）。物足りなければ発生点の複数化が候補。
- 発射シーンのスクリーンショットは壁時計タイミングで構図が揺れる（落下・カメラ）。帯の減衰の段階ごとの厳密な画素比較はできておらず、連続フレームの目視と純粋関数のテストで担保した。
