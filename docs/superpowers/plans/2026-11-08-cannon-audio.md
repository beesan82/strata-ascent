# 計画: 重粒子砲と破砕の音

背景: 見た目改善 段階 3（PR #45）の調査で、音響エンジンに重粒子砲の発射音・破砕音自体が存在しないことが判明した。2026-11-08 にユーザーが次の改善として「砲と破砕の音を付ける」を選択。
ブランチ: `feat/cannon-audio`
範囲: 重粒子砲まわりの効果音の新設。砲の数値・判定・描画と、既存の音（足音・環境音ほか）の仕様は変えない。

方針: 既存の音響エンジン（Web Audio による合成、外部音声ファイルなし）の流儀に合わせ、すべての音を合成で作る。パラメータ計算は純粋関数として Vitest で固定する。

## Task 1: 溜め音と発射音

- [ ] 溜め（0.6 秒）に同期して pitch が上がっていく唸りを付ける。キャンセル時は自然に止まること
- [ ] 発射時に重低音の轟き＋破裂感のある音を付ける。ビームの見た目（帯の太さ・「押し」シェイク）と重さの方向を揃える
- [ ] 検証： パラメータの純粋関数をテストで固定し、発火タイミングが発射処理と結線されていることを確認する

## Task 2: 破砕音

- [ ] 掘削で地形が壊れたときに破砕音を付ける。壊れたタイル数に応じて音量・長さを変えるが、1 発の掘削で 1 つの音に集約する（タイルごとに鳴らさない）。上限も設ける
- [ ] ボス・敵への命中時は破砕音と区別できる扱いにする必要があれば分ける（必須ではない）
- [ ] 検証： 破壊数→パラメータの純粋関数をテストで固定する

## Task 3: 仕上げ

- [ ] 既存の音（足音・パルス・環境音）との音量バランスを params 上で揃える。うるさすぎる場合は実機判定で調整できるよう、音量は定数に切り出す
- [ ] `npm test` / `npx tsc --noEmit` / `npm run build` 全通過（worldgen.test.ts の最重量テストは VM 高負荷時のタイムアウト揺れあり。単体再実行と変更前ベースラインとの比較で切り分けること）
- [ ] frametime は render p50 の悪化 +0.5ms 以内（前後各 2 回・同セッション比較）
- [ ] 音の良し悪しはヘッドレスでは判定できないため、実機判定が前提であることを保留に明記する
- [ ] 計画末尾に「実装時の裁定」「計測」「保留」を追記（チェックボックスは更新しない）
- [ ] Pages 再デプロイ + Codemagic ビルド（TestFlight 配信）は親エージェント側で実施

## 実装時の裁定

- 溜め音の結線は `AudioFrame.chargeRatio` 経由にした。`Graviton.chargeRatio` は「溜め中」だけ 0 より大きく、発射・キャンセル・弾切れのすべてで 0 に戻るため、エンジン側は「比率 > 0 の間だけノードを持ち、0 に戻れば短いリリース（時定数 0.05 秒）で止める」だけで発射/キャンセルの区別なしに自然に止まる。`Graviton` 本体には手を入れていない。
- 溜め音の合成は鋸波 2 本（+9 セントの微デチューンでうなりを作る）→ ローパス（基音の 6 倍、比率に連動）→ ゲイン。pitch は `chargeFreq`（55→220 Hz の指数カーブ）、ゲインは `chargeGain`（CHARGE_GAIN の 0.7→1 倍）。
- 発射音は 2 層：サブ正弦波の pitch 落下（120→34 Hz、0.5 秒、ゲイン 0.9）が重低音の芯、ローパスを 3800→240 Hz へ落とすノイズ（0.32 秒、ゲイン 0.65）が破裂感。どちらも dry + convolver に送る既存の流儀どおり。
- 破砕音の「壊れたタイル数」は `Destruction.size` の差分では取れない（未生成チャンクへの盲目記録も数えるため）。`Destruction` に `knownBroken`（実タイルとして確認して壊した数だけの累計ゲッター）を新設し、`fire()` で bore 前後の差分を渡す。`bore` の署名・挙動は無変更。
- 破砕音は 1 発で 1 音に集約し、パラメータは `crushParams`（対数圧縮、600 タイルで頭打ち）。敵・ボス命中時の区別は付けていない（計画の「必須ではない」どおり。地形が壊れたかどうかで音の有無が分かれるのが現状の区別）。
- 発射音・破砕音のノイズは、開始時に 1 本だけ作る長いノイズバッファ（1.5 秒、ループ再生 + ランダムな開始位置）を使い回す。足音用の 0.06 秒バッファと既存の音は無変更。
- 音量調整はすべて `src/audio/params.ts` の「重粒子砲の音」節の定数（CHARGE_* / FIRE_* / CRUSH_*）に集約した。エンジン側に残る定数はリリース時定数など機構側のみ。

## 計測

- テスト: 793 件 → **797 件・全通過**（params に溜め pitch/ゲインと crushParams の 3 件、destruction に knownBroken の 1 件を追加）。`npx tsc --noEmit` クリーン、`npm run build` 成功。
- 動作確認（Playwright headless、AudioContext を計装して実駆動）: 溜め開始で osc がちょうど 2 本増え、保持中は増えない（毎フレーム生成なし）。溜め pitch の実測は中盤 105.4 Hz → 満タン 219.1 Hz（理論 110 / 220 Hz）。真下への発射では溜め 2 + 発射 2 + 破砕 1 のノードが増え、地形が壊れなかった発射では破砕の 1 本が増えないことを実地で確認。発射×3・キャンセルの後も未停止ノード数は常駐分（ドローン+ハム等 7）と一致し、リークなし。ページ例外なし。検証スクリプトは `~/workspace/strata-cannon-audio/verify-audio.mjs` に保管。
- frametime（render p50、前後各 2 回 + p244 はベースライン worktree との交互ペア比較）: 開始地点 前 6.10/6.00 → 後 5.90/5.80ms、pos=244,66 歩行 前 6.50/6.40 → 後 6.90/6.60（ペア比較では base 6.90/6.50 に対し after 6.30/6.90 と方向が一致せず VM ノイズの範囲）、pos=40,60 前 5.70/8.30 → 後 7.40/5.70（前後とも大きくばらつく場面）。描画パスへの追加はなく、合格線（+0.5ms 以内）を満たすと判断した。

## 保留

- **音の聴感（重さ・うるささ・既存音とのバランス）はヘッドレスでは判定できないため、すべての音量・帯域・長さは初期値であり実機判定が前提。** 調整は `src/audio/params.ts` の CHARGE_* / FIRE_* / CRUSH_* 定数だけで完結する。
- 破砕音の大きさは「生成済みチャンク内で実タイルとして確認できた破壊数」に比例する。未生成チャンク方向への長距離掘削では、見た目の掘削量より音が小さめに出る場合がある（数えられない分は仕様として割り切った）。
- 敵・ボスへの命中だけ（地形が壊れない）場合は破砕音は鳴らない。命中音を分ける必要があれば別途。
- タブを隠したときの suspend で溜め音が止まったままになるケースは既存の suspend/resume の挙動に委ねた（復帰後は次フレームの比率追従で再開する）。
