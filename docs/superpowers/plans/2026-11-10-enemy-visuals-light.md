## 実装時の裁定

- **レイは刻みサンプリングでなくタイル格子の境界辿り（DDA）にした。** 設計の開始値「刻み 0.25 タイル」は使っていない。格子を境界ごとに辿ると、固体タイルの表面の位置が刻みに依らず正確に決まり、1 本あたりの参照回数も「通過するタイル数」（コーン半径 22 タイルで高々約 30 回）で刻み 0.25（約 90 回）より少ない。本数は開始値どおり円 48 本・コーン 40 本。
- **端点は壁の表面から照らし代 `WALL_SKIN = 0.3` タイルだけ壁へ入れる。** 表面ちょうどで止めると壁の縁の画素が 1 つも照らされず、「壁面が光を受ける」見え方にならないため。照らし代は半径を超えない（`min(maxDist, t + skin)`）。1 タイル厚の壁でも照らし代は 0.3 なので向こう側へは抜けない。
- **中心のタイルは見ない。** プレイヤーの中心が固体に入っている瞬間（崖つかみのよじ登り等）にレイが距離 0 で止まり、光が丸ごと消えるのを避ける。
- **未生成チャンクは空気として扱う。** 描画のためにチャンクを生成しない（`peekChunk` は生成しない）。可視範囲のチャンクは焼き込みのために生成済みなので、実際には半径内はすべて引ける。
- **タイル参照は 1 フレームごとに作り直す。** `chunkSolidLookup` は直前のチャンク配列を覚えるが、破壊はチャンク配列をその場で書き換えるので（`applyDestruction`）、同じフレーム内でも掘削の結果は反映される。キャッシュはフレームをまたがない。
- **円は角度 0 から等角度で 48 本、コーンは扇の両端を含めて 40 本。** 円の多角形は開けた場所で半径 9 の円に内接する 48 角形になるが、グラデーションは半径で 0 になるので縁は見えない。コーンも同様に扇の弧が弦になるだけ。
- **フォールバック。** `occlusion` を渡さない呼び出しは従来の `arc` のまま（グラデーションの停止点の文字列も同じ）。
- **歩行位相は中心の x 座標から導く。** 歩行敵は水平にしか自走しないので、実体に移動距離の状態を足さずに「移動距離から決まる」位相になる。反転の瞬間は `x × dir` の符号が変わるので位相が飛ぶが、同じフレームで向きも反転するので目立たない。落下中も x が変わらなければ脚は止まる。
- **歩行敵の形は当たり判定の箱（0.9 四方）に収める。** 胴は上半分強（-0.42〜+0.14）、脚は腰 +0.12 から床 +0.45 まで。背のセンサーだけ箱の上へ 0.15 はみ出す。目は進行方向側のバイザーの中で、金に淡色の芯（`lighter` は使わず、芯の色で発光を見せる）。
- **飛行ドローンの航行灯は左が錆、右が緑。** パレットに赤が無いため、錆 `#9a6d32` を左舷灯、緑 `#3c755f` を右舷灯にした。向きでは入れ替えない。ローターの円盤は淡色の α 0.4 の薄い帯、羽根は円盤の上の暗色の帯で、見かけの長さを |cos|（もう 1 枚は |sin|）で伸び縮みさせて回転に見せる（31 rad/s。60 fps では 1 フレーム約 0.5 rad 進む）。
- **センサーアイは追尾中だけプレイヤーを向く。** 巡回中は進行方向の斜め下、止まっていれば真下。色は従来どおり淡色（追尾で色は変えない）。
- **スラスターは速度 0.2 タイル/秒以上で、速度と逆向きに焚く。** 強さは速度 / 追尾速度で、時刻と個体の位相から ±12% 揺らぐ。胴の後ろに描くので、真上・真下への噴射は胴の縁から伸びる。
- **砲台の警告灯は `Turret.aiming` を読む。** `cooldown` は狙えている間だけ減るので、見失うと途中の値で止まる。`cooldown` だけで警告を出すと、見失った砲台が点滅し続ける。そこで読み取り専用の `aiming` を Turret に足した（update で `canAim` を記録するだけで、行動・数値は変えない）。狙えていないときは暗い錆色、照準中は錆色に灯り、発射 0.6 秒前から金/錆の点滅が 4→14 Hz へ加速し、残り 0.12 秒（警告 0.8）からは白く灯り続けて暈が出る。
- **砲身の後退は発射直後 0.15 秒だけ。** `cooldown` が発射間隔（1.6 秒）から 0.15 秒減るまでの間、砲身を最大 0.14 タイル縮める。狙えていないときは後退させない（見失った直後に縮んだまま止まるのを避ける）。
- **従来の砲台の「金の目」は警告灯に置き換えた。** 上蓋の中央の 1 点が状態を読ませる灯になる。

### 検証結果（親側、2026-11-10）

- テスト 1121 件全通過（1076 → 1121、新規 45 件）。tsc・build 通過。

- スクリーンショット: start / p244 / p40 / p300 / 右走行。遮蔽は床スラブの上下で光が切れる構図で確認。敵の接写はヘッドレスの盲目移動ではフレームに入れられず未撮影（ポーズ関数は単体テストで固定済み。見た目の最終判定は実機）。

想定: 描画パスの追加はない（Lighting の円とコーンのパスの形が多角形になるだけ、敵は fx 相乗りの矩形が 1 体あたり 20〜30 枚に増える）。レイキャストは 1 フレームあたり円 48 本 × 高々約 13 タイル + コーン 40 本 × 高々約 40 タイル（懐中電灯モード）の参照で、CPU の JS 側で 0.1 ms 未満の見込み。敵の矩形の増加は画面内の敵の数に比例する（1 枚あたりの画素数は小さい）。

## 保留

- **未検証。** このセッションではテスト・tsc・build・スクリーンショット・計測を実行していない。親側で確かめる。
- **見た目の差分。** 壁際では暗幕の消える範囲が壁の手前で切れるので、start / p244 のスクリーンショットは差分 0 にならない（意図した変化）。敵が画面に入る構図では敵の形も変わる。
- **レイの間の取りこぼし。** 角を掠めるレイと隣のレイの間は直線で結ぶので、壁の角の付近で光の縁が三角形に欠けたり、角の中へ少し入ったりする。粗く見える場合は本数を増やす（まず円 64 本・コーン 56 本）か、角の頂点へ向けた追加のレイを足す。
- **斜めの隙間。** 格子辿りで x と y の境界が同時に来たときは y を先に進めるので、対角に接した 2 枚の固体の間を光がすり抜ける向きがある（1 方向だけ）。目立つ場合は同時のときに両隣を確かめる。
- **他の光源の遮蔽**（ビーコン・塔の灯・光柱・休憩点の暖色）は設計どおり対象外。
- **敵の目・灯の色と暗幕。** 敵は暗幕の後に描くので、壁の向こうで暗い場所にいても目や灯は暗くならない（従来と同じ）。
- **歩行敵の脚は ppt が小さい眺望ズームでは 1 px の線になる。** 形が潰れる場合は眺望時だけ脚を省く。
