## 実装時の裁定

### Task 1: 素材アイテムと抽選

- 種別名は `DropKind` に `'material'` を足した(表示名「素材セル」。HUD・字幕では「素材」と呼ぶ)。新しい型や実体クラスは作らず、既存の `DropItem` に種別として載せる。
- 敵ドロップ(`dropFor`): 素材の基礎重みは敵種によらず 8%(Walker 22/12/16/8、飛行敵 27/12/11/8、砲台 25/10/10/8)。地区倍率(`DropProfile.material`)は全地区 1.0 で、段階 C の地区固有素材の接続点としてだけ用意した。合計圧縮(`DROP_TOTAL_CAP` = 0.62)は 4 種で行う。結果として:
  - 圧縮の無い地区(寒鋼・廃棄・水域・電力)では消耗品 3 種の実効確率は従来と同一で、素材 8% が「落ちない」側から削られる。
  - 圧縮のある地区では消耗品が数ポイント下がる。精錬区 Walker の砲弾 39.7%→35.5%、居住区画 Walker の糧食 24.2%→21.6%、生体異物区 Walker は従来 61.6% で非圧縮だったのが 69.6% で圧縮に入り砲弾 26.4%→23.5%。精錬区砲台の砲弾 45.6%→40.8%。これを「大きくは崩さない」範囲と判断した(最大の下げ幅は精錬区砲台の約 5 ポイント)。
  - 抽選の区間は 砲弾→回復→糧食→素材 の順に素材を末尾へ足した。非圧縮の地区では従来の個々の抽選結果(同じ seed・ID・killIndex)も変わらない。
- 補給キャッシュ(`supplyFor`): 素材 20% を地区によらず一定で足し、残り 80% を従来の地区別比率で消耗品 3 種が分け合う(`SUPPLY_MATERIAL_RATE`)。消耗品表そのものは `SUPPLY_CONSUMABLES` として従来の数値のまま残し、`supplyTableFor` が素材込みの表を返す。
- 休憩点の備蓄(`restStockSecondFor`)には素材を混ぜない。休憩点で出た素材はその場で確保されるだけで「持って帰る」行為にならないため。ボスの確定ドロップも変えない。
- 地面の実体は補給品区分(`permanent`、寿命なし)。地面の上限は糧食と同じ仕組みで種別ごとに持ち、素材は 8 個(`MAX_GROUND_MATERIALS`)。溢れたら最も古い素材が点滅して消える。糧食 16 + 素材 8 = 24 で、残りの 8 は上限判定つきのキャッシュ・備蓄・遺留品が使う。これにより `onEnemyKilled` では糧食と同じく `canAddSupply` を見ずに置ける。
- 描画は既存の fx のドロップ分岐へ 1 種を足しただけ(描画パスは増えない)。鋼青 `#3a73a4` の縦長(幅 0.62s × 高さ s)に淡色 `#c7d0ce` の上端帯。糧食(金の横長)とは向きと色、砲弾(紫の角型)とは色と縦横比、回復(緑の十字)とは形で分ける。いずれもパレット実在色。
- 取得音は砲弾の素材(`pickupCharge`)をレート 0.8 で流用し、音声ファイルは足さない。合成の既定(`PICKUP_NOTES.material`)も用意した。

### Task 2: 携行枠と確保

- `src/core/carry.ts` を新設。状態は `{ carried: Record<CarryKind, number>, cap, secured: Record<CarryKind, number> }` で、段階 A の `CarryKind` は `'material'` のみ。枠の判定は総個数(`carriedTotal`)で、`addCarry` は満杯なら同じ state を返す。`secureCarry` は携行をすべて確保済みへ移し、移した個数を返す(0 なら合図を出さない判定に使う)。
- 取得は `canPickup` に `carried` / `maxCarry` を足して既存の「満タンなら拾えず地面に残る」に相乗りさせた。消耗品の判定には影響しない。
- 確保の配線は休憩点の箱の判定(6 フレームごとの `inRestBox`)の中で、復活点の更新とは独立に行う。復活点が動かなくても(同じ休憩点へ戻っても)携行があれば確保される。
- 確保の合図は専用の短い音 `audio.secure()`(確認音 `confirm` をレート 1.3 で 2 回。未ロード時は上行 3 音)と、字幕「素材 n 個を確保」(既存の `Caption` へ相乗り)。設計書は「合図」を音として書いているが、「持って帰る手応え」を確かめる段階なので字幕も併せた。新しい画面・ボタンは足していない。
- HUD は満腹度の後ろに ` — 携行 n/5 / 確保済み m` を併記。確保済みが 0 でも出す(最深記録は 0 で隠すが、携行枠は常時見える方が「拾える残り枠」として役に立つため)。
- 死亡時は携行を触らない(段階 A の裁定どおり保持)。復活処理にその旨のコメントだけ置いた。

## 保留

- 素材の出現率(敵 8%、キャッシュ 20%)と携行枠 5 の釣り合いは未検証。実プレイで「枠が埋まる前に休憩点へ着いてしまう」なら敵側を 10% へ、逆なら枠の初期値を見直す。数値はいずれも `BASE_RATE` / `SUPPLY_MATERIAL_RATE` / `INITIAL_CARRY_CAP` の 1 箇所ずつ。
- 圧縮地区での消耗品の下げ幅(最大約 5 ポイント)が遊びに響くなら、素材を圧縮の外側に置く案(消耗品の実効確率を一切変えない)に切り替える余地がある。今回は設計書の「既存の重み・合計圧縮の枠組みの中」を優先した。
- 素材セルの判別(鋼青 縦長 + 淡い上端帯)は量子化後のスクリーンショットで未確認。小さいズーム段で上端帯が 1 px になるため、回復セルの淡い芯と紛れる場合は帯を外して単色にする。
- 確保の音は `confirm` の流用で、専用サンプルは足していない。復活点の更新音(同じ `confirm` 単発)と初回到達時に重なるので、聞き分けにくければ専用素材か別の既存素材(`tick` など)へ替える。
- 携行素材は死亡時に保持される(段階 A の割り切り)。段階 B で遺留品化するときは `dropRemainsOnDeath` と同じ箇所で `carry` を落とし、`secured` は触らない形にする。
- 確保済み `secured` は永続化していない(セッション内のみ)。保存可能な形(種別と個数)にはしてある。
