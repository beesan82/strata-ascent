## 実装時の裁定

- 純粋関数群は touch.ts ではなく新規 `src/core/stick.ts` に置いた。Input と
  touch.ts の双方から使うためで、循環参照を避け、zoom.ts / view.ts と同じ
  「core の小モジュール + 専用テスト」の構成に合わせた。
- 向き(facing)のスティック追従に |x| >= 0.3 の不感帯を入れた(設計は「x 成分に
  追従」のみ)。ほぼ真上の狙いで向きが左右に反転し続けるのを防ぐため。
- 保持照準をパルスのフォールバック方向にも採用した(設計 §4「パルスの
  フォールバック方向になる」を main の合成に実装)。合成の優先順位は
  右スティック > 保持照準 > 移動入力 8 方向。PC では保持照準が常に無効なので
  従来どおり 8 方向になる。
- 砲ドラッグ中のカメラ先行の方向は「画面中心 → 照準点」で算出した。
  プレイヤー位置を基準にするとカメラの移動自体で方向が変わり振動しうるため。
  指を止めれば方向は一定になる。
- ライトコーン合成のスティック点は、両軸とも canvas.height/2 × 0.9 の半径で
  取った。軸ごとに別スケールにすると atan2 の角度が歪むため。
- 照準合成を一本化した帰結として、砲をドラッグせず溜めて離した場合の発射
  方向は、従来の「向きの水平」ではなく保持照準(あれば)になる。誤射防止の
  モード分離(溜め・キャンセル・左入力無効化)自体は無変更。
- 右スティックのボタン優先は CDP エミュレーションでも実測した: 砲ボタン矩形
  (568,246,76×76) の内側に触れるとスティックではなく砲が立つ。検証時は
  ボタンから離れた点 (500,120) を原点に使うこと。

## 保留

- 実機確認ポイント 5 点(設計書 Task 5: 歩きながら斜め上に撃てる / 止まって
  真上を狙える / 狙った先が画面に入る / 砲の誤射が増えていない / 梯子の誤登りが
  増えていない)は未実施。TestFlight ビルドでの判定待ち。
- 真上へのパルスの飛行そのものは、スポーン直上の天井が低く弾が即座に命中
  するためエミュレーションでは目視できなかった(構えの変化と斜め 45° の
  飛行で代替確認)。
- 梯子の誤登り率・砲の誤射率は実機の指操作でしか測れない。閾値は
  stick.ts の定数(STICK_KEY_Y など)に集約してあるので、実機評価を受けて
  数値だけを調整できる。
- Pages 再デプロイと Codemagic ビルド(TestFlight 配信)は本計画の範囲外
  (親フローの手順で実施)。
