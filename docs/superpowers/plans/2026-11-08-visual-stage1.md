# 計画: 見た目大幅改善 段階 1 — 地形の重厚化

設計書: `docs/superpowers/specs/2026-11-08-visual-overhaul-design.md`（ユーザー承認済み、2026-11-08）
ブランチ: `feat/visual-stage1`
範囲: 設計の段階 1 のみ。**地形の重厚化（すべて焼き込み側の変更、毎フレーム負荷ゼロが原則）**。プレイヤー・歩行（段階 2）とビーム・演出（段階 3）は扱わない。

診断の要点（設計書より）: タイル内装が量子化で消え、上端の明線だけが残って「発光した図面」に見える／ディテールの周期が 1 タイルで均一で人間の部屋のスケール感になる／前景と背景の明度分離が弱い／ディザの網点が面を印刷物に見せている。

## Task 1: プレート単位のパネル割りと面の明度構造

- [ ] パネル割りを 1 タイル単位からプレート単位（2〜4 タイル）へ引き上げ、大きな面に明度の段差を作る。地区性（地区ごとの文法・色）は壊さない
- [ ] 検証： 同じ seed・同じ位置の変更前後スクリーンショットで、大きな面の段差が目視で読めること。絶景の余地の原則（生成パラメータの振れ幅を狭めない、レア枠を残す）を壊していないこと

## Task 2: リムライトの間引きと質感の焼き込み

- [ ] リムライトは上端のみ弱めて残し（初期値 alpha 0.55・幅 0.08）、側面・下端は消す。足場の可読性が落ちていないかをスクリーンショットで確認する
- [ ] 垂れ汚れ・錆の滲みを決定論で焼き込む（生成・描画に Math.random を使わない）
- [ ] 検証： 変更前後スクリーンショットと差分（差分画素数と、意図した変化との対応）

## Task 3: 前景と背景の分離、ディザの A/B

- [ ] 遠景を 1 段沈めて（明度を下げて）前景と分離する
- [ ] ディザ強度 12 と 8 を 3 場面で A/B 撮影し、面の網点感とバンディングを見比べて採用値を決める（裁定として計画書に残す）
- [ ] 検証： 前後の奥行きの読みやすさをスクリーンショットで確認する

## Task 4: 仕上げ

- [ ] `npm test` / `npx tsc --noEmit` / `npm run build` 全通過（worldgen.test.ts の最重量テストは VM 高負荷時のタイムアウト揺れあり。単体再実行と変更前ベースラインとの比較で切り分けること）
- [ ] frametime は render p50 の悪化 +0.5ms 以内（前後各 2 回・同セッション比較）。加えてチャンク焼き込み時間（bake）の前後も測る（設計書の方針）
- [ ] 計画末尾に「実装時の裁定」「計測」「保留」を追記（チェックボックスは更新しない）。設計書もこの PR に含める
- [ ] Pages 再デプロイ + Codemagic ビルド（TestFlight 配信）は親エージェント側で実施

## 実装時の裁定

- **プレートの重ね描きはアトラスではなく chunkbake の焼き込みパスで実施**（Task 1）。アトラスはバイオーム単位でキャッシュされワールド座標を持たないため、プレートの明度段・継ぎ目・角リベットはワールド座標から chunkbake で重ねた。割り付けはワールド座標のハッシュのみで決まるので、部分再焼き込みでも全面と画素一致する。明度段はパレット実在色の重ねで作る：暗段 = STEEL.black を alpha 0.30、明段 = #c7d0ce（パレット 27 番）を alpha 0.08、中段は無地。
- **プレート割り付け**（`src/render/tileset/plate.ts`、純粋関数 `plateAt`）：12 タイルのスーパー区間を 2〜4 の和が 12 になる固定パターン 12 種で割り、スーパー区間ごとにハッシュで選ぶ。行の高さ列は全世界で共有され（横継ぎ目が一直線に通る）、列の幅列は行ごとに変わる。明度段は暗 34% / 中 44% / 明 22%。
- **アトラス側の整理**（Task 1）：縦グラデ alpha 0.35 → 0.15、タイル単位のパネル線・角リベット・縁の明線を廃止。ベベルの暗帯は残した。
- **染みはプレート局所モデル**（Task 2、`src/render/stains.ts`）：プレート上面からそのプレートの内側だけに垂れ、プレートを跨がない。これでチャンク境界・部分再焼き込みと衝突せず決定論で済む。付くのはプレートの約 45%、錆（#9a6d32、パレット 30 番）はその約 30%。装飾レイヤー（DecorCache）への相乗りは採らなかった（crater の clearRect と干渉するため）。
- **リムライト**（Task 2）：上端のみ alpha 0.9 → 0.55・幅 0.12 → 0.08 タイルで残し、側面・下端は描画を廃止。`rimSegments` の純粋関数と既存テストは変更していない（描画側で top 以外を読み飛ばす）。
- **遠景を沈める**（Task 3）：背景レイヤー基準色 `BG_BASES` を鋼ランプ 1 段分暗くし（[黒と far の中間, far, far と base の中間] → [黒, 黒と far の中間, far]）、AI 遠景の `BACKDROP_ALPHA` を 0.45 → 0.36 に下げた。
- **ディザ強度は 12 → 8 を採用**（Task 3 の A/B 裁定）：3 場面（開始地点 / pos=244,66 / pos=40,60）で比較し、平坦面の網点が目視でも計測でも減った（開始地点の壁面で 4×4 ブロック内色数の平均 3.51 → 3.05）一方、暗部のグラデーションに新たなバンディングは出なかった。強度 8 でも Bayer オフセット×8 は整数刻み（2/8 刻み）のため量子化の整数距離パス（intExact）は維持される。
- **ディザ変更に伴うテスト追随**（Task 3）：`pixel.test.ts` の同距離テーブルは強度依存のため `scripts/quantties.ts` を強度 8 で回し直して再生成した（最近傍の同距離 3363 件中、整数の先勝ちと割れるのは 735 件。強度 12 では 205 件 / 46 件）。「production strength disperses」テストの代表色は強度 8 でも 2 色へ割れる色（15,22,30）へ差し替えた。`pixel.ts` 内の件数コメントも追随。

## 計測

- テスト件数：730 件（開始時）→ 741 件（+11：plate +6、stains +5）。全通過、`npx tsc --noEmit` クリーン、`npm run build` 成功。
- frametime render p50（各 2 回、同セッション・他処理なし）：
  - 開始地点：変更前 5.90 / 5.90ms → 変更後 5.90 / 5.70ms
  - pos=244,66（KeyA 移動中）：変更前 6.50 / 6.90ms → 変更後 6.40 / 6.40ms
  - pos=40,60：変更前 5.70 / 5.70ms → 変更後 5.80 / 5.60ms
  - いずれも合格線（悪化 +0.5ms 以内）の中。stage p50（sky 0.2 / background 0.6〜0.7 / chunks 0.2〜0.3ms）も不変。毎フレーム描画パスは増やしていないため想定どおり。
- bake（ChunkBaker.get の同期焼き込み、代表 10 チャンク合計）：VM 負荷で同一ビルド内でも ±10% 以上ぶれるため、ベースライン（5422743 の worktree）と交互に測るペア比較とした。ペア 2 組で base 293.9 / 425.7ms に対し final 315.7 / 410.5ms、染みパス単独の有無でも中央値差は約 4% 程度。有意な増加は確認できず、1 チャンク平均は前後とも約 42〜45ms の帯。アトラス生成は 0.55〜0.82ms/本で不変。
- 変更前後スクリーンショット（同じ seed=20260711・同じ位置、保存先 `~/workspace/strata-visual-stage1-shots/before|after/`）：
  - start：差分 437,939 画素（47.5%）、最大チャンネル差 107
  - p244：差分 354,589 画素（38.5%）、最大チャンネル差 86
  - p40：差分 431,424 画素（46.8%）、最大チャンネル差 107
  - 差分の内訳は意図した変化と対応する：タイル枠の消滅とプレート面＋明度段への置換、リムの減光・側面/下端の消滅、背景の減光、ディザ網点の減衰。プレイヤー周辺や HUD は不変。

## 保留

- リムライト初期値（alpha 0.55・幅 0.08）の最終判断と、プレート明度段の濃さ・染みの目立ち具合は実機判定待ち（設計 §8-③）。スクリーンショットでは足場の上端は読めているが、実機の小画面での可読性は未確認。
- 染みは控えめで、スクリーンショットでは判別しづらい場面が多い。実機で「汚れが足りない」と判断されればゲート率 45% か alpha を上げる調整が要る。
- 胸の装甲色（設計 §8-①）とビームの熱色化（§8-④）は段階 2・3 の範囲で未着手。
- bake 計測は VM 負荷の揺れが大きく、厳密な前後差は測れていない（ペア比較で「有意な増加なし」まで）。実機でのチャンク焼き込みの引っかかり有無は TestFlight 配信後の実機判定で確認する。
