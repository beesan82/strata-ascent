## 実装時の裁定

- **保存は 1 キー・1 JSON、最深記録は従来のキーのまま。** 設計の「最深記録は従来の保存と統合する（重複させない）」は、保存先の storage と取得経路（`safeLocalStorage`）を共有し、値は従来の `best-layer` キーだけを正とする形にした。ランの保存には最深記録を入れない。「さいしょから」はランの保存だけを消し、最深記録は残す（ランを跨ぐ記録のため）。
- **壊れた保存は部分的に使わず丸ごと捨てる。** 1 項目でも形・範囲が不正なら通常の開始にし、保存も消す（設計の「黙って破棄」）。半端な復元で矛盾した状態（例: 携行が枠を超える）から始めるより安全と判断した。版数を上げたときも旧い保存は同じ扱いで消える（移行は書いていない）。
- **再開位置の「使える」は「地形と重ならず、足元 0.25 以内に床がある」。** 破壊した地形は保存しないので、掘った穴の中の安定接地点は再開時に埋まっていることがある（→ 復活点へ落ちる）。昇降機・トラムの上の接地点はタイルの床が無いので外れる（足場は再開時に初期位置にあるため）。復活点も同じ判定で、使えなければスポーンを復活点にする。
- **再開時の安定接地点は再開位置で初期化する。** 再開直後に死亡しても、遺留品は再開位置へ落ちる（従来の「スポーン直後」と同じ扱い）。
- **HP・武器モード・到達階層（`maxLayer`）は保存しない。** 設計の保存対象に無い。再開時の HP は満タン、到達階層は再開位置の階層から数え直す（最深記録は従来どおり保存済みの値が正）。新記録の字幕はセッション開始時点の記録を基準にする従来の規則のまま。
- **飢餓の経過秒（`starveT`）は満腹度に含めて保存する。** 満腹度 0 のまま閉じて開き直すと猶予がやり直しになる抜け道を作らないため。
- **撃破済みは記録の古い順で保存し、復元は `recordDefeated` を通す。** 上限 10000 の安全弁がそのまま効く。
- **変更検知は「直列化した文字列を前回の保存と比べる」。** 状態ごとの汚れフラグを各所に散らさないため。歩いている間は安定接地点が動くので、移動中はほぼ 3 秒ごとに書く（数 KB〜撃破数に比例。撃破 10000 件でも数百 KB の同期書き込みで、3 秒に 1 回なら許容とした）。タイマーはゲーム更新と独立の `setInterval` で、アイテムボックスを開いて止めている間の出し入れも拾う。
- **`?x=&y=` と `?freeze=1` のセッションは永続化しない。** スクリーンショット・計測の再現性を保ち、デバッグ位置で本来の保存を上書きしないため。Playwright の headless は毎回新しい文脈なので、`--pos` を使わない計測（`--stages` の既定位置）にも保存は影響しない。
- **「さいしょから」は保存を止めてから消して読み込み直す。** 読み込み直しで来る `pagehide` / `visibilitychange` の保存が、消した直後の保存を書き戻さないようにした。確認の状態は箱の開け閉めで解ける。押した後にボタンのフォーカスを外す（Space のジャンプや Enter で 2 回目が押されてしまうのを防ぐ）。
- **遺留品は「中心位置と種別」だけを持ち、再開時に補給品として置き直す。** 寿命・経過秒は持たない（遺留品は補給品で寿命が無い。地面の糧食の溢れで点滅中だった物も再開時は点滅しない）。死亡直後の保存は落下中の位置になるが、静止後は 3 秒おきの保存で書き直される。

## 保留

- **未検証。** このセッションではテスト・tsc・build・スクリーンショット・計測を実行していない。親側で確かめる。
- **破壊した地形は保存しない（設計の対象外）。** 再開すると掘った穴は埋まって戻る。安定接地点は判定で外れて復活点へ落ちるが、**遺留品の位置は判定していない**: 掘った穴の中に落ちた遺留品は、再開後は地形に埋まって回収できなくなることがある（重粒子砲で掘り直せば届く）。実機で問題になるなら、復元時に埋まった遺留品を最寄りの空き位置か復活点へ寄せる。
- **複数のタブで同じ seed を開くと、後に保存した方が勝つ。** 単一枠の設計どおりで、排他は入れていない。
- **iOS アプリ（WKWebView）の localStorage は端末の空き容量が逼迫すると OS に消されることがある。** その場合は通常の開始に戻る（最深記録も同じ扱い）。気になるなら Capacitor の Preferences へ移す。
- **容量超過で保存に失敗しても知らせない。** `writeSave` は false を返すだけで、次の機会に再試行する。撃破記録が上限 10000 まで伸びても数百 KB で、通常は 5 MB の枠に収まる見込み。
- **昇降機・トラムの位置、敵の HP、地面の通常ドロップは戻らない（設計どおり）。** 敵は出現集合の再計算で戻り、倒していない敵は満タンで出直す。
- **CLAUDE.md の「現在地」は更新していない。** マージ時に親側で更新する。
