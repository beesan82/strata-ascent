## 実装時の裁定

### Task 1: 飛行敵の他地区開放

- `FLYER_MUL` を power 0.5 / biomech 0.75 に引き上げた（waterVoid 1.0 が最大のまま）。初期候補のまま統計の条件（下記）を満たしたため、倍率の再調整はしなかった。
- 出現統計は一時スクリプト `scripts/flyer-survey.ts`（main の `refreshEnemies` 再現: seeds [1, 42, 20260711, 7, 99]、cell -28..-1 の各セル 3 点 = 地区ごと 60 スキャン、スキャン矩形 ±40 × ±24、保護点はスポーン相当の遠方点 r=10 と `nearestRestPoint` r=20）で計測し、スクリプト自体は計測後に削除した（コミットしない）。

### Task 2: ボス予備動作の改善

- 進捗→見た目の変換は純粋関数 `windupPose(phaseT, timeSec)` として `src/render/bossPose.ts` に新設した。進捗 p = phaseT / 0.7（`BOSS_WINDUP_TIME`、数値は不変）から沈み込み量・震え量・点滅状態・目の色を決定論で返し、renderer のボス分岐はこの pose だけを見て描く。`enemy.ts` は無変更。
- 沈み込み: 最大 0.35 タイル、p^2 で増える。renderer 側では足元（下辺）を床に anchored のまま高さだけを縮める。
- 震え: 振幅 p^2 × 最大 0.09 タイル、`sin(timeSec × 80)` の時刻ベース。Math.random は使わない。
- 点滅: 初期 10Hz（現行互換）から p^2 で +16Hz まで加速する。位相は周波数変化の解析積分を phaseT 基準で進めるため、予備動作の開始時は必ず淡色（`#c7d0ce`）から始まる。p > 0.75 では点滅を止め、熱色（錆 `#9a6d32`）に固定する。
- 目の灯: ボスの全相に新設した（歩行敵と同じ文法で向き側の上部に 1 点）。通常は金 `#caa64a`、予備動作の終盤（p > 0.75）は白 `#c7d0ce`。被弾フラッシュ中は歩行敵と同様に色を反転して残す。色はすべてパレット実在色の範囲内。
- fx の拡張: main がボス要素に `bossPhaseT`（`boss.phaseT`）と `bossDir`（`boss.dir`）を追加して渡し、renderer の fx 型にも同名フィールドを足した。新しい描画パスは作っていない。
- 警告音: 入れた。`AudioEngine.bossWarn()`（矩形波 880→587Hz の下降チャープ 0.18 秒、ゲイン 0.1、dry のみへ送る）。パラメータは `src/audio/params.ts` の `WARN_*` 定数。main が approach→windup の遷移を検出して 1 回だけ呼ぶ（開始前は何もしない既存流儀どおり）。

### Task 3: 武器切替の PC 統一

- `KeyQ` を `GAME_KEYS` に追加し、`pressKey` の押下エッジで既存の `toggleWeapon()` へ合流させた（keydown のオートリピートは既存ハンドラで除かれる）。タッチの切替ボタンと PC の Q で切り替えの入口が 1 本になった。
- 砲マウス: Input の入口として `pressMouseLeft()` / `releaseMouseLeft()` を新設し、window の pointerdown / pointerup はここへ委譲する形にした。押下時点で「砲モード・ニュートラル要求なし・眺望中でない」ときだけ溜め（`mouseCannonHeldFlag`）をラッチし、`fireHeld` はスティック held とこれの OR。解放で既存の `cannonReleasePending` を立て、main の `fire()` が `takeCannonRelease()` で消費して自動でパルスへ復帰させる（発射候補の失効 `expireCannonRelease` の枠組みは不変）。
- `KeyF` 廃止: `GAME_KEYS` と `fireHeld` から外した。`input.test.ts` の旧 KeyF テスト（「押下で fireHeld が立つ」）は「押しても立たない」固定へ置き換えた。
- `pulseHeld` のマウス分は「パルスモード かつ ニュートラル要求なし」のときだけ有効にした（砲モードで左クリックを保持してもパルスは連射されない）。
- 安全策の PC 読み替え（設計 §5）: 切り替え時の engaged 判定は「スティックの倒し比 > デッドゾーン || マウス押下中」。ニュートラル要求の解除条件にマウス解放を足した（スティックが倒れたままの場合はマウス解放だけでは解除しない）。マウス溜め中の切り替えは、スティック溜めと同じ分岐で先に `requestFireCancel()` してから切り替える。
- 眺望（Shift）の PC 相当（裁定）: スティック版 §3-7 と同型に、眺望中の押下では溜めを開始せず、溜め中に眺望へ入って解放したらキャンセル要求にした。あわせて blur（フォーカス喪失）時はマウス溜めをキャンセルして破棄する（解放発射がフォーカス外で成立しないため）。
- `main.ts` は `fire()` のコメント追随のみ（発射候補がタッチ／PC 共通になった旨）。数値（溜め 0.6 秒など）とタッチ経路の挙動は変えていない。ホイール切り替えは入れていない（保留参照）。

### Task 4: 大広間の床の HARD 化

- 広間の床の行（`noiseTileWith` の広間分岐、`y === hall.floorY`・広間の x 範囲内）を SOLID から HARD に変えた。物理は `isSolid` が HARD も固体として扱うため、広間番人・プレイヤーの足場は従来どおりで、破壊側は既存の多層防御（bore の HARD スキップ、`tileAtLive`・`Destruction.applyTo` の HARD 保持）にそのまま乗る。
- `isHardAt` には、界面・ランドマークがタイルを決める位置では既存判定をそのまま返し、それらが無い位置でのみ広間床を HARD とする判定を足した（`tileAt` の優先順位の鏡写し）。これで未生成チャンクへの bore でも広間床は破壊として記録されない。
- 追加の裁定: 梯子列の列は `noiseTileWith` で広間より先に LADDER として返るため、床の行でも `isHardAt` は偽とした（`tileAt === HARD` との同値を保つため）。
- 見た目の変化: HARD はチャンク焼き込みで板（ほぼ黒の平坦な面＋縁）として描かれるため、広間の床行の見た目が従来の SOLID の床から板の帯に変わる。これは仕様どおりの変化として受け入れる（スクリーンショットで確認済み）。

### Task 5: 大広間の絶景拡張

- 煙突の純粋関数 `hallChimneyAt(seed, cell)` / `hallChimneyForHall(seed, hall)` を `src/world/grandhall.ts` に新設した。幾何: 幅 48、広間の中心 x に寄せ、範囲は `[hall.y0 − h, hall.y0)`、広間が無いセルでは null。広間の寸法・出現率は変えていない。
- 彫りは `noiseTileWith` の広間と同じ優先度帯（梯子列・前室の forceFloor の後、空洞・塊より前）に置き、タイルの属するセルの煙突に加えて下のセル（cell + 1）の広間の煙突も引く（煙突が 1 つ上のセルへ伸びるため）。`tileAt` の合成順は変えていないため、界面・ランドマークが先に決まり、休憩点も煙突に勝つ。界面の板（HARD）は煙突を横切る位置では板のまま残る（テストで固定）。
- 高さの調整（1 回のみ）: 初期値 128 / 160 / 192 では絶景計測の長大区間が伸びなかった（下記計測）ため、候補を 192 / 256 / 320 に引き上げて最終形とした。引き上げ後も長大区間は増えなかったが、絶景点は微増し、レア枠・大きな開け区間は痩せていないため、この値を採用する。
- 幅の追加検証（1 回のみ）: 保留に残した「煙突の幅の拡大」を 1 回だけ試した。診断（一時スクリプト、計測後に削除）で広間ごとに標本列の最長連続点を数えたところ、幅 48 では調査範囲内の広間 8 件のうち 3 件で標本列（x 間隔 64）が煙突を 1 本も通らず、10 点に届く広間は無かった（最長 9 点。詳細は計測参照）。`HALL_CHIMNEY_WIDTH` を 48 → 96 に広げ、幾何テスト（`grandhall.test.ts` の幅の固定）も追随させたところ、長大区間が 28 → 29 に増え、他の指標も痩せなかったため幅 96 を採用する。最終形は幅 96・高さ 192 / 256 / 320。

### Task 6: 新敵「固定砲台」

- 配置は `chooseTurretSpawns`（`src/world/spawn.ts`）を新設した。Walker と同じ床ラン＋hash 決定論で、ID は `t:${run.x},${run.floorY}`、位置は床の上（左上 = (sx, floorY − 0.9)）、hash の塩は 4301（出現判定）/ 4302（ラン内オフセット）の 4301 系（Walker 4001 系・Flyer 4101 系・drop 4201 と衝突しない）。基礎率は `spawnRateForLayer(layer)` に地区倍率だけを掛ける形とし、Walker の地区 spawnMul は掛けない（倍率表がゲートを兼ねるため）。
- 地区ゲートは倍率表 `TURRET_MUL`（power 1.0 / foundry 0.8、他は 0）と `turretMulFor` で持つ。
- 除外の裁定: 保護点は Walker と同じチェビシェフ距離。大広間は砲台ボディ矩形（0.9×0.9）が少しでも重なれば除外。歩行敵の選定済み位置との近接はチェビシェフ距離 ≤ 3 タイルで除外（引数 `occupied` は main が Walker の選定結果 `desired` を渡す）。砲台同士の密度上限は Walker と同じ定数（24×12）を共用する。撃破済みは選定後の減算（他敵と同じ）。
- 実体は `src/entities/turret.ts` に新設した。定数: HP 4、大きさ 0.9×0.9、射程 10 タイル、連射間隔 1.6 秒、初回発射遅延 0.8 秒、弾速 12 タイル/秒、弾の大きさ 0.3、弾の寿命 1.1 秒（射程/弾速 ≒ 0.83 + 余裕）。クールダウンは狙えている間だけ減り（見失っている間は止まる）、照準角 `angle` は狙えている間だけプレイヤー中心へ更新し、見失っても保持する。被弾は他敵と同じ `hit(damage)`（flashT・dead）。
- 視線は純粋関数 `hasLineOfSight`（線分を 0.25 刻みでサンプルし、`isSolid` に触れたら遮断。梯子は固体ではないので遮らない）。
- 弾 `TurretShot` は重力なしの直進弾。移動は `moveBody` ではなく 0.1 タイル刻みの歩進＋ `bodyOverlapsSolid` で固体への接触を判定する（斜め弾で軸別衝突の取りこぼしを避けるため）。寿命（1.1 秒）でも消える。敵・ボスには当たらない（main はプレイヤーとの重なりだけを見る）。

### Task 7: 最深到達の記録

- 記録の出し入れと節目判定は `src/core/records.ts` に新設した。保存キーは `bestLayerKey(seed)` = `strata-ascent:best-layer:${seed}` で seed ごとに分ける。storage は `getItem` / `setItem` の抽象で受け、例外・null は握りつぶして読みは 0 にフォールバックする。不正値（数値でない・負数・非有限）も 0 扱いで、小数は切り捨てに正規化する（読み書き共通）。
- 節目は `RECORD_MILESTONE_INTERVAL = 5`。`crossedMilestone(prevMax, newMax)` は区間 (prevMax, newMax] 内の最大の 5 の倍数を返し、無ければ null（5→9 は null、4→12 は 10）。
- 字幕文言も純粋関数にした: 節目 `milestoneCaptionText` = 「第 n 階層到達」、新記録 `newRecordCaptionText` = 「新記録 第 n 階層」。
- 結線（main）: 起動時に localStorage を安全に取得する（取得自体が例外になる環境も握りつぶし、取れなければ記録なしで続行）して `bestLayer` を読む。追加の裁定として、スポーン位置も「到達した階層」に含め（開始時の `maxLayer` の定義と揃える）、開始時の maxLayer が記録を上回っていれば字幕なしで記録だけを同期する。これで `?x=&y=` の深いスポーンでも記録が保存される（通常スポーンは第 1 階層なので、実質の差は記録なし→1 の同期のみ）。
- `updateHud` の既存の接地時更新箇所で `maxLayer` が増えたときだけ次を行う: `bestLayer` を上回れば更新して保存する。節目字幕はセッション内の `maxLayer` の跨ぎで判定する。新記録字幕はセッション開始時点の記録（読み込み値）を初めて超えたときにセッションで 1 回だけ出す。両方が重なったら節目を優先し、新記録はその回で消費する。
- HUD は「第 n 階層」の直後に「/ 最深記録 第 m 階層」を併記する。記録が 0 のときは出さない。
- ゲームの数値・生成・物理・描画パスには触れていない（保存と DOM 表示のみ）。`Math.random` は使っていない。
