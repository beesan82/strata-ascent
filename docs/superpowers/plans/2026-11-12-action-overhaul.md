# 2.19「アクション大幅改善(遭遇率・部位破壊・敵の大型化)」 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 敵の遭遇率を約半分に下げて景色探索に集中できるようにし、被弾位置で部位を壊して機動力・攻撃力を奪う戦闘(歩行敵の脚、飛行ドローンのローター、固定砲台のセンサー)を入れる。部位を狙い分けられるよう敵を大型化する(プレイヤーは 0.9 のまま)。

**Architecture:** 部位の判定は純粋関数 `src/entities/parts.ts`(矩形内の縦位置で上端/下端 45% の帯を判定)に置き、各敵クラスが `hitAt(damage, hitY)` で「部位の耐久を削るか、本体 HP を削るか」を決めて `PartHit` を返す。部位の耐久は本体 HP と別枠。パルスの命中だけが `hitAt` を通り、重粒子砲は従来どおり `hit(hp)` で即死させる(部位を上書きする切り札)。出現率は基礎率 `spawnRateForLayer` の係数だけを半分にし、飛行敵・砲台はこの基礎率に地区倍率を掛ける既存の仕組みのまま同率で下がる。大型化は実体の寸法定数と、スポーン位置(床 - 体の高さ)だけで済ませ、スプライトは旧寸法の形のまま `ppt` に体格比の倍率を掛けて描く。

**Tech Stack:** Vite + TypeScript、Vitest。コメントは日本語。

**Spec:** `docs/superpowers/specs/2026-11-12-action-overhaul-design.md`

- 描画は既存の fx 相乗り(`renderer` の敵ループ)の中だけで描き分ける。新しい描画パスは足さない。

## 実装時の裁定

- **被弾位置**: パルスの中心の高さ(`p.body.y + p.body.h / 2`)。パルスは一辺 0.4 なので、矩形の端をかすった弾は中心が矩形の外に出ることがある。帯の判定は矩形の外の値を端へ寄せるので、かすった弾は近い側の部位に入る。
- **重粒子砲は部位判定を通さない**: 従来どおり `hit(hp)` で即死させる。`hitAt` は呼ばない(部位を上書きする切り札のまま)。
- **飛行敵・砲台の出現率は基礎率の半減だけで下げる**: どちらも `spawnRateForLayer × 地区倍率` なので、基礎率を半分にすれば同率で半分になる。地区倍率まで半分にすると 1/4 になり二重に下げることになるため、`FLYER_MUL`・`TURRET_MUL`・密度規則は変えない。
- **砲台の体格は 1.2 四方**(設計の「一回り大きく」)。頭上 2 タイルの空きに収まり、幅 1.2 でラン内の床に収まる。
- **脚破壊後の歩行速度と地上を這う速度はどちらも 0.8 タイル/秒**(歩行敵の通常 2 の半分以下)。
- **ローター破壊後**: 破壊の瞬間に巡回へ戻して速度を 0 にし、以後は重力で真下へ落ちる(落下中は横へ動かない)。接地後は巡回の向きへ這い、壁と床の端で反転する(歩行敵と同じ規則)。追尾はしない。接触ダメージは残す。
- **センサー破壊後**: `aiming` を常に false にし、クールダウンも進めない。照準角は最後の値を保持する(砲身はその向きで止まる)。
- **出現位置**: ラン内オフセットの式(`floor(hash × max(1, len - 2))`、最大 `len - 3`)は変えない。幅 1.8 の歩行敵も右端が `len - 1.2` に収まるので、スポーン ID と横位置は従来と同一のまま、縦位置だけが新しい高さに合わせて変わる。保護点の判定は縦位置を含むので、境界ぎりぎりの候補は出現の有無が変わりうる(決定論は保たれる)。
- **出現条件(頭上の空き)は変えない**: 床ランは頭上 2 タイルの空きを要求しており、歩行敵 1.6・砲台 1.2 はそのまま収まる。飛行敵のポケット(5×4)も 1.5×1.0 を収める。砲台と歩行敵の近接除外 3 タイル(左上どうし)も、幅 1.8 / 1.2 の体が重ならない距離なので変えない。
- **通路で詰まらないか**: 歩行敵は高さ 1.6 になったので、高さ 1 の隙間はくぐれない。`moveBody` で横に阻まれると壁と同じく反転するので、その場で凍結・固着はしない。幅 1 の穴は床端の判定で手前で反転する。
- **描画倍率**: スプライトの形の寸法は旧体格(0.9 四方)で書いたまま、`ppt × 新体格 / 0.9` で一様に拡大して描く(歩行敵と砲台は高さ、飛行ドローンは幅で合わせる)。歩行敵は足の下端が床にちょうど来る(0.45 × 1.6 / 0.9 = 0.8 = 高さの半分)。描く歩幅も倍率ぶん伸びるので、歩行位相は `x / 倍率` で求めて足が床に対して滑らないようにした。
- **部位状態の受け渡し**: renderer は `w/h` の有無でボスを判別しているので、通常敵には `w/h` を渡さず `broken` を足した。
- **通知**: 取得ログに `pushNotice(text)` を足して同じ左端の行へ出す(TTL・最大件数は取得と共通)。DOM・表示の同期は既存のまま。
- **部位破壊音**: 撃破音より短く軽い「割れ」(打撃サンプルを速めに + FM の金属ティック + 鋸波の短い下降)。脚・ローター・センサーで共通。撃破の瞬間は従来どおり撃破音だけ(部位破壊と撃破は同じ被弾で同時に起きない)。
- **テストの世界**: 出現率を半分にすると、床ラン 2 本の世界で「何体か選ばれる」前提の検査が偶然 0 体になりうる。歩行敵の撃破済みの検査と砲台の検査一式を、床ラン 50 本(60 間隔、密度上限より離す)の世界へ移した。飛行敵の検査は 80×40 の全面空気のポケット(数千候補)なのでそのまま。`enemyHold.test.ts` は第 10 層(上限到達後)で数値の前提を持たないので注記だけ直した。
- **`beamHit.test.ts` は 0.9 の半対角のまま**: 半対角を受けるだけの純関数の幾何テストで、新寸法(半対角約 1.20)に差し替えると「ボスなら当たる」検査の余白(+0.5)がボスの半対角 1.64 を超えて成り立たなくなる。検査用の基準寸法として残し、注記を直した。
