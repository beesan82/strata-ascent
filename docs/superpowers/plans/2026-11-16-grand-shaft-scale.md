# 2.20 改修「大昇降機を原作準拠のスケールへ」 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 大昇降機(`docs/superpowers/plans/2026-11-14-grand-shaft.md` で実装済み)を、2400〜4800 タイル(6〜13 層程度)を貫く「乗り通すのが非常識に長く、途中駅で降りるのが前提」のスケールへ改める。足場は 3 タイル/秒(乗り通しは約 13〜27 分)。長大化に合わせて頻度は今より稀にし、世界の大物として置く。途中駅・眺望区間・詰みなし・決定論・チャンク境界一致は従来どおり保つ。

**Architecture:** 配置のモデルを「列バンド × cell グループ(3 層)に閉じた 1 本」から「列バンド × 開始 cell の抽選で、決めた長さだけ下へ貫き続ける 1 本」に改める。下の層の側は、行の cell から上へ一定数(`GRAND_LOOKBACK_CELLS`)の開始 cell を引いて「上から来ているシャフト」を決定論で認識する(`grandShaftCovering`)。同じ列バンドの並行は、上の開始 cell の候補が届いていれば棄却する(保守的な棄却で、判定は一定の範囲を見るだけで閉じる)。足場は `LiftShaft` に速さ(`speed` / `callSpeed`)を足し、大昇降機だけ 3 タイル/秒にする。景色は既存の焼き込み(`grandShaftOps`)の中で変化を足し、描画パスは増やさない。

**Tech Stack:** Vite + TypeScript、Vitest。コメントは日本語。

**前提:** 設計書 `docs/superpowers/specs/2026-11-12-mega-structures-design.md`、計画書 `docs/superpowers/plans/2026-11-14-grand-shaft.md`(2.20 初版の大昇降機)。設計書の数値(300〜600 タイル、5 タイル/秒)は本計画の裁定で置き換える(設計書の本文は書き換えていない)。

## Global Constraints

- 生成・描画に `Math.random()` を使わない。配置・長さ・停止階・眺望区間とその変種・深度標識は seed と世界座標の hash とシャフトの幾何だけで決める(`AGENTS.md`)。
- 地形合成との重なりは既存の流儀(候補を作って棄却する)のまま: 孔(±`GRAND_PASSAGE_CLEAR`)・大構造・休憩点の箱・大広間と煙突・通常の昇降機・メガ施設とは配置の段階で重ならない。`composeTile` / `isHardAt` の優先順位は変えない。
- 通常の昇降機(`elevatorShaftAt`)の配置・速さ・初めの位置・呼び戻しは変えない。
- 描画は焼き込み(チャンクの装飾)と既存の灯の矩形への相乗りだけ。新しい描画パスは足さない。
- 頻度・長さ・速さの数値はすべて定数(`GRAND_RATE`、`GRAND_TRIES`、`GRAND_MIN_LENGTH`、`GRAND_MAX_LENGTH`、`GRAND_LOOKBACK_CELLS`、`GRAND_SPEED`、`GRAND_CALL_SPEED`、`GRAND_MARKER_*`、`GRAND_PLATE_BAND_EVERY`、`GRAND_VISTA_VARIANTS`)。
- 完了条件: `npm test`、`npx tsc --noEmit`、`npm run build` が通る。乗車中の frametime の render p50 悪化は 2.20 初版比 +0.5 ms 以内。スクリーンショットで前後を確認する。

## Review Focus

## 実装時の裁定

- **抽選の単位と長さ**: 「列バンド × 開始 cell」で抽選し(`GRAND_RATE`)、開始 cell の中で上の停止階を決め、長さ `GRAND_MIN_LENGTH`〜`GRAND_MAX_LENGTH`(2400〜4800)を hash で決めて下へ貫く。目標の行が落ちる cell を終わりの cell とし、その床帯の行(板の下面から 64 以上下・床の板の上面から 16 以上上)へ丸める。目標が cell の頭(板の直下)に落ちて丸めで最長を超えるとき、または収まる行が無いときは 1 つ上の cell の底で止める。それでも範囲外なら置かない(再抽選しない)。層の高さは 300〜450 なので、2400 でも 6 層以上を貫く。
- **上から来ているシャフトの認識**: 行の cell から上へ `GRAND_LOOKBACK_CELLS = ceil(4800 / 300) + 1 = 17` 個の開始 cell を引き、終わりの cell が行の cell に届くものを持ち主とする(`grandShaftCovering`)。層の最小の高さ(`BIOME_CELL_BASE − BIOME_CELL_JITTER` = 300)で最長を割った数なので取りこぼさない。`grandTileAt`・`grandShaftsNear`(装飾・灯・main の近傍)はすべてこの入口を通る。
- **並行の禁止(保守的な棄却)**: 同じ列バンドで、開始 cell より上 `GRAND_LOOKBACK_CELLS` 個の「候補」(抽選・縦の配置・横の配置まで通ったもの)のどれかの終わりの cell が自分の開始 cell 以上なら棄却する。上の候補が自身さらに上の候補に棄却されていても棄却する。こうすると判定は上へ一定の範囲を見るだけで閉じ、棄却の連鎖を遡らず、引く順序によらない。代わりに「見えない候補」が下を消すぶん頻度が少し下がる(稀少にしたい今回の方針と合う)。別の列バンドとは外形が重ならない(外形はバンドの内側)。
- **横の候補**: 2.20 初版と同じく孔スロットの境目付近(スロットの 32 タイルグループ 9〜14 番)。初版は 8 個を hash で試したが、長いシャフトは貫く板(孔の ±124)と各層の大構造(孔 +160、スロット 3 個に 1 基)の両方を全層で避けなければならず収まりにくいので、候補 42 個(7 スロット × 6 グループ)を hash の開始位置から歩幅 13 で全部巡る(`GRAND_TRIES = 42`)。重なりの棄却の規則そのものは初版のまま(既存の流儀を維持)。
- **頻度(机上の見積もり。実測は親側で)**: 横の配置が収まる確率は貫く層の数で急に下がる(孔の揺らぎ ±64 と大構造の有無が層ごとに独立なため)。見積もりは 7 層で 2 割前後、11 層で 2% 前後、13 層以上で 1% 未満。`GRAND_RATE = 0.5` と並行の棄却を掛けて、列バンド × 層あたり数 % 以下(2.20 初版は約 1 割)。テストは「1 割未満」を上限として固定した。**実際の長さの分布は短い側(2400〜3200)に寄る**(長いほど収まりにくい)。設計どおり全数が 2400〜4800 には入る。
- **メガ施設の判定**: 初版は外形を 8 タイル格子で標本したが、外形が 4800 行になると候補ごとに数千回引くことになるので、外形が掛かるセクター(一辺 16384)のハブの矩形(一辺 192)との矩形の重なりで判定する。`megaFacilityAt` はハブの矩形の全タイルで非 null を返す(セクターの外へはみ出す分は隣のセクターの判定になるので、矩形全体で見るのは安全側)。テストは外形の全タイルを `megaFacilityAt` で確かめる(2 本)。
- **速さ**: `LiftShaft` に `speed?` と `callSpeed?` を足し、`advanceElevator(e, dt, riding = true)` が `liftSpeed(shaft, riding)` で進む。大昇降機は `GRAND_SPEED = 3`(乗り通し 2400 で約 13.3 分、4800 で約 26.7 分)。通常の昇降機はどちらも持たないので乗っていてもいなくても 5 のまま(既存のテストは無変更で通る想定)。
- **呼び戻しの速さ(初版の保留を前倒し)**: 3 タイル/秒のまま呼び戻すと最長 27 分待つことになり、途中駅で降りる前提が成り立たない。乗り手のいない足場(呼び戻し・降りた後の残りの移動)は `GRAND_CALL_SPEED = 40`(4800 タイルで 120 秒 = 初版の最長の待ちと同じ)で動かす。乗った瞬間から 3 に戻る。
- **初めて出会ったときの位置**: 通常の昇降機は従来どおり下端。大昇降機は `main.ts` がプレイヤーの行を渡し、最寄りの停止階に置く(`initialElevator(shaft, nearY)`)。足場の位置はセッション内のみ・近傍から外れると捨てる(初版と同じ)ので、離れて戻ると最寄りの停止階に置き直される。
- **途中駅・設備**: 初版のまま(板ごとに上下 2 段、設備は `GRAND_AMENITY_RATE = 0.5`)。13 層級では途中駅 12 か所前後(停止階 26 前後)。設備・補給・端末の ID(`s:g:band,cell` など)は形式を変えない(cell は板の cell で、同じバンドで一意)。シャフトの ID は `g:band,startCell` に変わる(2.20 は未配信なので保存の互換は考えない。足場の状態はもともと保存対象外)。
- **眺望区間**: 間隔(80 行、3 タイル/秒で約 27 秒ごと)・幅・張り出しは初版のまま。区間ごとに hash で変種を選ぶ(`grandVistaVariant`: 手すりだけ / 渡り桁 / 垂れケーブル)。眺望の光(灯の矩形 1 枚)は変えない。
- **深度標識**: `GRAND_MARKER_EVERY = 120` 行ごと(約 40 秒ごと、位相 60 で灯の行と筋交いの交点を避ける)に、内側の背面の中央(2 本のケーブルの間)へ板 1 枚と「この先(下)の途中駅の数」の目盛り(上限 6、0 なら終点の注意帯)。壁の内側の面に置く案は、壁が床帯の行ごとに出入口で抜けて間隔が崩れるので背面にした。
- **板の通過帯**: 貫く板の上面の行から 32 行ごと(厚さ 96 の大界面では 3 本)と下面の直前の行に、内側の背面へ帯と斜めの縞。どの層を通過しているかの合図(層の通過字幕の代わりではない。保留参照)。
- **色**: 新しい色(`plateBand` / `marker` / `markerTick` / `gantry` / `droop`)は `STEEL` と注意色の混合で、既存の `PALETTE` / `SCENERY_COLORS` / 地区色と同じ値にしない(初版と同じ方針)。
- **テストの重さ**: シャフトが 10 倍長いので、タイル単位で外形全体をなめる検査は最初と最後の板のまわり(±40 行)に絞り、全長を見る検査(内側の空気・落下)は本数を減らした。落下は 4800 タイルで最大 192 秒ほどかかるので上限を 240 秒にした。

## 保留

- **頻度と長さの分布の調整**: 見積もりどおり長い側(4000 以上)が稀なら、(a) 板のまわりだけ外形を細くして孔の離れの判定を緩める、(b) 収まらなかったとき長さを短い側へ引き直す、のどちらかで均す。どちらも重なりの棄却の流儀は変えずにできる。
- **乗り通しの操作**: 停止階ごとに ↑↓ を押し直すか押し続ける必要がある(4800 タイルで最大 26 回、または 27 分押し続け)。「次の端まで行く」急行の操作を足すかは実機の体感で決める。
- **呼び戻しの足場への飛び乗り**: 乗り手のいない足場は 40 タイル/秒で動く。動いている最中に飛び乗った場合の着地(1 ステップ 0.67 タイル)を実機で確かめる。問題があれば呼び戻し中は乗れないようにするか、乗り場の手前で減速する。
- **層の通過演出**: 板を越えたときの階層番号・地区名の字幕と通過音は出ない(初版から持ち越し)。長い乗車では「今どの層か」が分かりにくいので、次の改修の第一候補。板の通過帯と深度標識はその場しのぎ。
- **休憩所の機能**: 途中駅の休憩所は「灯の下に接地すると復活点が移る」だけ(初版から持ち越し)。長い乗車の途中の補給・満腹度の扱いは実機の体感で決める。
- **背景の大構造**: 眺望区間から見える遠景は既存の超構造のシルエットのまま(初版から持ち越し)。
- **景色の小物・施設の梯子**: 初版の保留をそのまま持ち越し(シャフトが長くなった分、当たる回数は増える)。
- **設計書の数値**: `2026-11-12-mega-structures-design.md` の 300〜600 タイル・5 タイル/秒の記述は本計画の裁定で置き換わった。設計書の本文を更新するかは本人の判断を待つ。
